## 2026-07-15 — globalfsm-activation (module: state_machine)

### Context
`SetGlobalState` rerouted from direct field write to matrix-validated `GlobalFSM.TransitionTo()`.
Pre-emptive call-site audit (before test run) found 3 matrix-illegal sites the proposal missed
(proposal claimed 2 call sites; TraversalEngine had 7).

### Decisions

1. **TraversalEngine RunAsync catch — redundant `SetGlobalState(Error)` removed**
   - Level 1 (code analysis). `Done(Reasons.Error)` already sets Error; the double-set would
     throw `Error→Error` inside the catch, breaking Log-and-Continue. No test modified.

2. **Traversing→Terminated (StopAsync / Done(Cancelled|Timeout)) — two-step via Paused**
   - Level 3 (user consultation). Locked matrix (identical in Python `VALID_TRANSITIONS`) has no
     Traversing→Terminated edge. User approved: `Traversing→Paused("stopping")→Terminated`.
     Alternatives rejected: ForceGlobalState (would drop trace), matrix extension (locked 🔴).

3. **StateRestorerTests.PreserveAndRestore_All5FieldsMatch — setup path fix**
   - Level 4 (careful test modification, setup only — assertions untouched). Setup used
     `Idle→Traversing` (matrix-illegal). Rewritten to legal `Idle→Initializing→Traversing`.
     Restore path itself now uses `ForceGlobalState` (production change, per spec).

4. **6 new spec-scenario tests added** (user approved)
   - 3 in StateMachineTests (ForceState history/no-callback; SetGlobalState invalid throws;
     valid records history + callback), 3 in TraversalEngineTests (two-step stop history;
     FsmType="GlobalFSM" trace; ForceState produces no trace).
