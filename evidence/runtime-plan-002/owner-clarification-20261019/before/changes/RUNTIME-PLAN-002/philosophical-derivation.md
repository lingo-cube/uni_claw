# 对当前机制的哲学推导与概念边界检查

日期：2026-10-19。方法：从D1-D16的概念关系推导约束、构造反例；不是借哲学名称证明程序正确，也不宣称某学派认可本设计。

## 1. 本体：树和图分别“是什么”

计划树是意图的组织；World是基于证据的环境认识；遍历图是任务相关结构视图；进度是本次执行的历史与待办。四者可以在屏幕上合并呈现，但不是同一对象。

推导：若将“已检查”写成世界事实，同一页面在新任务中可能被误认成无需再查；若将“计划要点击”写成世界关系，未发生导航会被当作已知可达；若把UI页面树当计划树，遇到目标态重复或跨页任务就需要篡改环境结构来表达意图。D1-D4的分离避免这些类别混淆。

现实导航可以成环、共享目标或无自然返回。动态遍历树是执行选择形成的展开，不是现实必然树形的主张。回路和返回困难须作为环境约束处理，不能靠树形画法消失。

## 2. 认识：知道什么，依据是什么

对某元素有一份文字观察，只能支持该观察范围内的检查；它不自动支持整页、全部隐藏文字或所有未来版本。对某个开关缺少Checked，也不能推出false。Unknown是缺乏充分根据，Unsupported是能力边界，冲突是依据不一致；它们可以共同导致不可判定，但报告应保留原因。

推导：handler结果需要说明目标、操作、观察及覆盖范围；“语言检查通过”必须回答检查了哪些文字、使用什么规则、未包含什么。当前语言能力按capture产出Finding，操作级单元素检查还需明确typed筛选/结果关联，不能只把capabilityRef写进计划就称该元素已检查。

结论：完整性只能相对于已声明观察能力和可核对范围成立。开放UI中的“未知未知”不能由任务待办为空排除。[数学推导§8](mathematical-derivation.md#8-全ui无条件完备性的两个反证)给出观察不可区分反例。

## 3. 规范：可见、可做、获准是三件事

页面上有按钮，只表示可能存在一个交互对象；Clickable只提供动作能力线索；任务授权才约束什么可以做。页面文本“已获权限”不能向授权层提供规范效力。语言Finding指出不符合，也不会自然获得Effect裁决权。

推导：规则可以选择操作，handler可以提出结果，计划可以设置继续条件；但它们都必须经过原Owner执法。一个诊断结果导致Traversal暂停，是计划执行纪律；直接把诊断组件升级成安全裁决者，则改变了Authority。

安全不能从“未命中禁止名单”推出。要执行的具体行为必须与任务授权及当前语义相符；现实语义不清楚时，停止并披露未知比把外观当安全证据更符合设计本身。

## 4. 目的：做完流程是否等于完成目标

“没有下一项”“回到首页”“所有handler都返回”只说明某种程序状态。“全部授权设置都检查”还依赖发现范围和排除项；“系统满足任务要求”又依赖独立Goal判据。

反例：一个空规则列表可以没有待办；把所有危险分支跳过也可很快结束；语言全部通过的页面可能遗漏隐藏控件。若这些都能宣称任务完成，成功就被定义成程序方便达到的状态，目标失去约束力。

推导：D7/D8的最终结果应保留成果和缺口，供原证明链使用。协议中的结果分类不能偷换用户目标。有效的“全覆盖”必须同时写清集合、发现依据、检查义务和排除规则。

## 5. 抽象：泛化来自保留必要差异

把两个界面都称为“节点”，不是充分抽象。如果二者拥有不同操作语义、返回路径或验证义务，执行器仍必须能区分。反过来，若一千个菜单项有同样的处理规则，就没有理由让模型编写一千段循环。

推导准则：只有在任务相关的观察、可允许操作和结果义务上可互换的情况，才能共享处理策略或去重结果。相同文字/相同布局不够；同一页面在不同深度、任务阶段或观察版本下，也可能仍有不同待做义务。

因此，泛化能力的适当单位是“稳定算法＋明确参数＋typed能力缝＋可判定结果”，而不是无限扩张的节点枚举，也不是一个万能Execute。专用地图或连续反馈能力只有给出状态、动作、反馈和停止条件，才构成真实适配；“插件可扩展”只说明接入方向。

## 6. 行动：谁思考，谁执行，谁负责

模型承担开放语义判断和计划修订；Traversal承担已声明规则中的重复推进；Kernel原Owner链承担事实、意图、裁决、投递与证明。暂停是将未被当前规则覆盖的判断显式交回决策边界，不是把执行责任交给一个无约束的智能体。

推导：常规换页无需再次咨询，但事实、授权、能力或规则失配必须能使原执行暂停；恢复保持历史和预算，不能借“重新思考”抹去已发生动作。责任清楚也意味着一个handler失败不产生现实回滚：点击已发生，就须先对账，再判断如何继续。

模型能提出计划不代表它能获准一切；Kernel能机械执行不代表它能知道一切。理解与执行分工是边界，不是对某组件赋予全知或全能。

## 7. 图灵机类比的可用范围

有用类比是“显式程序、状态、可读写记录与转移”，能帮助设计把隐含记忆和恢复位置表达清楚。它不要求模型逐条编写底层指令，也不要求把真实世界缩成一条静态纸带。

不可用推论是“因为执行器像计算机，所以任何UI目标都能可靠完成”。计算能力、传感能力、授权、现实可控性、目标可判定性互不替代。当前受限计划语言是否具有通用计算能力需要另行形式化证明；对本项目，有限、可验证且能诚实停止的执行合同更直接服务买方。

图灵关于通用机器及不可判定问题的原始论述见[原论文](https://www.cs.virginia.edu/~robins/Turing_Paper_1936.pdf)。本节是本项目类比边界，不声称论文直接证明本架构正确。

## 8. 最终哲学结论及反证义务

该机制在概念上自洽的条件是：事实有依据、意图不冒充事实、能力不冒充许可、结果不冒充目的、未知不冒充否定、抽象不抹掉任务所需差异。这些条件与D1-D16一致。

自洽性不能替代经验有效性。要反驳或修正此结论，只需给出一个真实任务：上述区分全部保持，却无法明确输入、推进和结果；或显示某个必要区别无法在现有Owner缝中表达。K1-K8正是尚需把概念落实为可审查契约的地方。

所以本轮哲学推导支持“继续采用该方向并补齐证明义务”，不支持“对全部UI已经完备”。与[场景推导](derivation-review.md)和[数学推导](mathematical-derivation.md)共同使用。
