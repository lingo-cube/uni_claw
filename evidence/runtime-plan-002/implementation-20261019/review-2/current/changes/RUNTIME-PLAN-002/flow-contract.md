# 计划树与遍历图：流程契约设计基线

日期：2026-10-19。状态：设计基线已接受并持久化，覆盖D1-D19和明确Owner归属；目标设计，不是已实现协议。架构原则核对见[评审结论](architecture-review.md)，等待Owner开启后续任务。

最新责任澄清见D17-D19及[第12轮](grill-round-12.md)：检查逻辑归handler能力；Traversal Control和Recovery / Reorientation归既有Control Loop；Kernel internal run driver只协调执行时机/顺序/生命周期，进度与结果记录经原Owner缝。以下不要求driver实现领域检查/规划/恢复算法，也不允许handler直接改写Run/World/Control。

后续Owner已授权将本稿用于新一轮场景/数学/哲学推导，分析无需再次等待确认。结果见[三层推导](derivation-review.md)；发现K1-K8具体证明义务，正式字段与实现仍未冻结，不能把本稿直接视为适配完备协议。

## 1. 输入

调用方提交PlanTree并关联任务/当前Run。计划说明目标、范围、节点处理规则、安全限制、深度/预算内约束及结束条件，不要求预列未知页面，也不单独提交遍历图。

Kernel执行驱动经显式Owner读取缝取得执行信息：World的当前事实及有依据结构、当前Run的进度、有效授权/安全策略/能力和预算。执行依赖必须明确；不通过隐藏全局访问或复制canonical store省参数。

## 2. 三者的分工

| 对象 | 表达什么 | 来源与约束 |
|---|---|---|
| PlanTree | 要做什么、按什么规则处理、何时结束 | Agent提出/修订，Kernel采纳；规则只能使用已提供语义，不能扩权 |
| 遍历图 | 当前任务范围内累计已观察的页面、元素及关系 | 从World摘取引用、组织成可重建视图；身份/依据沿用World，失效或更正须反映，不反写世界事实 |
| 任务进度 | 本Run已做、待做、受阻及执行位置 | 来自Run/执行记录，独立于图；进度不能代替World事实或任务完成证明 |

保留历史结构不使旧定位变成当前动作目标。查询/缓存/物理存储方式后定；已知图只是观察范围内的知识，不能当作完整真实环境。

## 3. 执行与暂停

```text
提交计划并关联任务
→ 发起一次Traversal持续执行
→ Kernel按需取得World派生遍历图、Run进度及当前约束
→ Control Loop中的Traversal Control按规则顺序选择首个确定匹配项；Control签发交互意图
→ 执行该操作的前置handlers（有序、目标和观察明确关联）
→ 交互操作经Control、接地/绑定、Assurance、Effect与新观察/独立验证；只读处理不产生Effect
→ 执行该操作完成并验证后的handlers（有序，读取明确关联的新观察）
→ 经原Owner缝更新事实/进度，再继续处理
```

不同具体操作可绑定不同的Plan Handler列表，例如某元素的语言检查绑定于该元素的操作（D11）。支持操作前、完成并验证后两个时机，各自按计划显式排序；输入明确关联目标与观察，原目标消失不能自动换目标，后置handler不替代Kernel强制验证（D13）。独立只读处理也可绑定handler，不必点击，不扩展Effect ActItem为万能入口（D14）。Registry注册次序不代表计划次序，也不新增Handler注册表或任意调用入口。

handler只引用本任务已提供并有效绑定的能力/声明操作。必需能力启动前缺失则不启动，运行中失效则暂停；显式可选项才可跳过并记录，不自动替换能力（D12）。

检查结果按计划选择“仅记录并继续”或“必须满足才继续”；后者不符合/Unknown时暂停。语言检查未声明阻断条件时默认记录并继续，Finding不升级为安全授权或Assurance裁决（D15）。

检查是否完成、通过或需要重检由该handler对应能力的协议定义；Kernel正确调度并保存调用状态与能力结果，不重新计算领域结论。语音不对等“不符合”可以只是记录，不是调用执行失败。只有已声明的必需继续条件不满足才暂停，调用异常不伪装成功（D18/D19）。需要恢复时，执行位置、结果、已发生动作及消耗交给Recovery职责，具体恢复策略不放进Traversal。

规则按显式顺序选首个确定匹配项，不隐式合并多组交互；前项Unknown且会影响选择时保留未知并走约定处置，不当false跳过。多个检查明确组合到所选操作的handlers，安全策略始终独立逐动作执法（D16）。

已有GuardStep及语言专用post-commit hook可提供接入参考；StepAct/StepVerify是内部阶段。操作级typed绑定和验证后公开扩展契约仍需后续设计与实现，不添加万能hook集合，事实依据见[第11轮](grill-round-11.md)。

记录、观察等零Effect处理仍受工作量和预算约束。新页面若仍被规则覆盖就继续，不因换页自动咨询模型；未知不能默认允许动作，黑名单未命中也不能直接认定导航安全。

需要新决策时，暂停原执行并暴露原因；Kernel依既有咨询边界取得明确继续/修订，在合法边界重检事实和授权后继续。保留位置、已做工作、失败记录及预算；在途Effect先对账，不盲重发。暂停受既有取消、超时、资源和停止规则约束，不意味着无限等待。

Traversal Control和Recovery都是Control Loop既有子职责；Kernel内部driver负责编排它们与其他Owner的交互，不成为planner、领域判断或恢复智能。World拥有belief、Run拥有进度真值、Control签发意图、Assurance裁决、Effect Boundary投递。执行记录经原Owner写入缝，handler不直接改写这些状态；不另建Primary Run/Owner，对外持续执行接口不合并权威。

## 4. 查询与输出

| 时机 | 提供什么 |
|---|---|
| 执行中，包括暂停时 | 只读概览：当前状态、执行位置、完成/剩余工作、暂停原因及待决定事项；详细图、日志和证据通过引用读取 |
| 本次执行结束后 | 执行报告：结束方式/原因、完成/未完成工作、跳过/未知及证据引用；正常结束与提前停止分别交代 |

状态查询不驱动执行、隐式续行或模型咨询；暂停时不提前返回最终执行报告。调用方不必反复取NextStep推动循环。

Traversal结束、计划段结束、任务Goal满足是不同判断；最终报告供原任务证明/终局链使用，不能单独宣布全覆盖或Goal完成。

遍历完成要求限定范围内应处理项已处理、发现结束有依据，排除/未知/深度截断可核对；无法证明发现充分就报告部分完成。后续可由结果校验Capability按其声明协议辅助校验，本次不注册该能力，也不改变原目标证明权威（D17）。

## 5. 菜单例子：从输入到结果

1. 提交“只读检查设置”的计划：安全导航进入子树，控件记录，禁止项标记，未知按覆盖约定保留缺口或暂停，限定深度，处理后返回首页。
2. World先提供已观察到的首页结构；进入“网络”并验证后，World建立有依据关系，遍历图引用它。新发现“Internet”无需预先写入计划。
3. Traversal在Kernel原执行链中继续展开、记录、返回；独立任务进度记录处理结果，图不加“已处理”真值。历史定位不能直接用于下一次点击。
4. 查询可见当前位置、已完成和剩余工作；若未知分支需要模型决定，原执行暂停。Kernel取得明确决定后重检并继续，过去动作和消耗不重置。
5. 本次执行结束后，返回实际完成内容、被禁止/未知的缺口、结束原因和证据引用。未进入的子树只能标记未探索，不能声称已检查。

这是设计流程演示，不是新设备运行或适配通过证据。

同一例子中的操作级绑定可读作：安全导航的点击操作绑定“点击前检查该菜单项文字”；开关的只读处理绑定“检查该开关文字、记录状态”，无需点击开关。确需检查操作结果时，在验证后handler明确指定结果目标/观察。规则首项命中决定采用哪一组操作，handler顺序决定该组检查次序。

## 6. 本轮定稿边界

本稿只定输入、执行、查询、暂停/修订和结果的语义关系。字段/类/状态枚举、具体算法、正式wire/Prompt、缺陷修复、跨进程恢复和场景适配实现后续处理。

本轮D1-D19及职责归属已保存为语义设计基线，架构评审通过。按Owner指令等待后续任务，不再为已定语义追加问题，不自动进入实现；正式字段、算法和验收在届时任务范围内处理。

原有高层Traverse、安全分类、记录投影、返回身份、动作支持及World投影有效性缺口仍在；设计定稿不代表它们已修复或已证明适配完备。原RUNTIME-PLAN-001的真实成绩和失败门槛不改写。
