# PNL-003 / WI-PNL003-011 — DSH Host Wrapper 验收证据

## 做了什么

把 DSH panel adapter 接入通用 Workspace App，形成 `panel → capabilities → WorkspaceQueryCore → createWorkspaceApp → mount` 的只读装配链路。

## 原来的问题

DSH adapter 已能提供 capability，但还没有一个与 Standalone 相同的 Host 入口，无法验证 DSH 侧是否复用通用 Query Core、Controller、View Model、Renderer 和 App 生命周期，也没有明确保证 DSH session identity 不泄漏到产品前端接口。

## 这次修改

- 新增 `dsh/uniclaw-task-workbench/src/create-workspace-host.js`。
- 显式接受 `resolveProductSession`，仅由 resolver 建立 `ProductSessionId → DSH session` 关联；无映射返回 `uncorrelated`。
- 对外提供 `start`、`stop`、`getApp`、`getController`、`getState`、`getError`。
- mount 收到的 state/View Model 与 public facade 对 DSH session identity 做脱敏；DSH session 只停留在 adapter 内部。
- 新增 fake panel 测试，覆盖主流程、未关联映射、panel/renderer/mount 错误和 stop→start。
- 未修改旧 DSH HTTP、typert、client、Product Runtime 或共享 web 代码。

## 结论

WI-PNL003-011 完成。DSH 现在只承担 Host 装配和来源能力，通用前端链路保持 Host-neutral；Standalone 与 DSH 已具备同一 App contract，下一验证边界是两个入口的实际运行和浏览器场景证据。
