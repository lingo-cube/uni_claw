# PNL-003 / WI-PNL003-013 — Query Core 失败 envelope 元数据证据

## 做了什么

修复共享 Query Core 的失败归一化，使 capability 失败事实继续携带 capability、source 和响应快照元数据。

## 原来的问题

能力返回 `{ok:false, capability, error, revision/snapshotId/observedAt}` 后，Query Core 以前只把 `error` 放进 read model。这样 UI 能看到“超时/无权限”，却不能知道来自哪类 capability 或对应哪个来源快照；Core 自己生成 stale 时也丢失 incoming revision。

## 这次修改

- `failureEnvelope()` 统一把失败结果中的 capability、source 和实际存在的 snapshotId/revision/observedAt 带入 read model。
- `getSession`、`getTimeline`、分页查询（Task/Trace/Evidence）和 `resolveDetail` 都使用该失败投影。
- Core 生成的 stale failure 复用 incoming envelope 的 capability 与元数据。
- 新增测试覆盖五类 capability 失败和 stale envelope；错误对象、错误码和 retryable 保持原值。

## 结果
