# PNL-003 / WI-PNL003-012 — 双入口与失败路径验收证据

## 做了什么

用同一组 Host-neutral App contract 场景对照 Standalone 与 DSH 入口，验证完整只读主流程、局部错误、未关联、restart 和 identity 边界。

## 原来的问题

Standalone 和 DSH wrapper 虽然分别可用，但尚未证明它们输出同一组 renderer-neutral 区域，也没有证明 DSH 的 Host session 不会通过 public state/viewModel 泄漏到产品前端。

## 这次修改

- 新增 `web/uniclaw-workspace/tests/dual-entry.test.js`。
- 新增 `dsh/uniclaw-task-workbench/tests/dual-entry.test.mjs`。
- 两套测试都覆盖项目→任务→session→timeline→trace/evidence→detail、请求→决策→结果、局部 permission/unavailable、未关联和 stop→start。
- DSH 测试确认 ProductSessionId 保持，输出中没有 `sessionId`/`dshSessionId`。
- 浏览器打开本地静态渲染结果，检查了 Uni-Agent 主线、Trace 分组、Evidence 明细按钮和 Metadata 卡片；Standalone/DSH 页面均可呈现。

## 验证结果

| method | expected | actual | evidence |
|---|---|---|---|
| Web `npm test` | 通用链路与 Standalone 双入口无回归 | 46/46 passed（含 Query Core 修复后测试） | test output 2026-10-02 |
| DSH `npm test` | DSH 原有行为与 Host 双入口无回归 | 47/47 passed | test output 2026-10-02 |
| 双入口主流程断言 | 两入口输出同一组 renderer-neutral 区域与请求/决策/结果分组 | passed | `dual-entry.test.js` / `dual-entry.test.mjs` |
| 浏览器静态预览 | 主线、Trace、Evidence、Metadata 可见 | Standalone 与 DSH 页面均可打开并呈现 | Codex in-app browser tab 3；本地 `/private/tmp/uniclaw-workspace-browser/*.html` |

## 新发现

DSH 页面因 project card 与 selected task list 同时渲染，在左侧出现重复任务卡；它不影响数据正确性，但影响产品级导航清晰度，已拆为下一步导航投影修复。
