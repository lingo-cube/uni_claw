# 目标推进与续额判断 SOP（讨论草案）

状态：Draft / Authority: NONE。依据state.md中的D1-D16；Q13-Q15已确认，Q12受托自查方案已纳入；整体提案待最终共同理解确认。供grill讨论，不是已安装的Product Skill或实施计划。

## 1. 核心思路

先敲定预期，再按预期选择和理解任务结构，据此推断待办与路径并作决定。Agent拥有方向判断；尽可能用集合变化、依赖关系和验证结果支持推断，避免把问题完全留给自由叙述。结构服务于预期，不能反过来以现有结构能统计什么来缩小原任务。

预算接近用完触发重新评估。额度耗尽本身不证明目标无价值或执行跑偏；未完成本身也不足以支持对同一失败路线盲目追加。

## 2. 当前全遍历的最小表示

- 范围限定为当前设备、账号、权限及系统状态下允许访问的菜单；需要登录或切换状态的条件分支记录条件和未覆盖原因，不为枚举它们额外切换状态，不扩大既有动作授权（D11）。
- 页面/入口及实际导航关系：当前页面、上级路径、同名目标的上下文身份、已知可达边。可按层级展示，实际存在回跳/多入口时保留真实关系。
- 在范围内的待验收事项：一级页面及各分支需要完成的访问、子页检查、返回等；以预期满足情况表示，不设无条件可计算的“分支已完成”结论（Q6已确认）。
- 剩余工作不必是详尽清单；允许按分支、范围或待查明问题表达，随观察细化。续额复核不能以列不出尚未知晓的全部页面为由否定有依据的下一段探索（Q10补充，D12）。
- 事实分别表示：未处理、处理中、已验证、受阻/不确定、跳过/不适用。跳过与成功访问分别显示，适用验收是否允许跳过另按任务定义。
- 每个事项关联现有Run/Contract/Decision/证据引用，不以相同文字标签直接合并不同目标。
- 初始任务范围与动态发现区分。尚未发现的分支不能算已完成，也不能凭空填数量。已知分母增加不必然意味着倒退。
- 入口发现与执行顺序分开：根页观察即可登记可见入口，保留全局未访问项；不要求先逐个进入一级页面才建立概览。当前深入的分支、已验证要求、阻碍与未确认范围分别表达，已发现入口不能冒充已观察到的目标页面。

这只是思考模型，不在此冻结枚举、DTO、独立registry或新数据库。

## 3. 每次需要决策时的流程

1. **敲定预期。** 当前目标要达到什么结果，作用范围和验收依据是什么；本阶段/本笔额度预期得到什么。预期仍不明确的部分如实列出，不由实现默认值悄悄替代。
2. **根据预期看结构。** 读取overview及必要证据，理解页面/入口、依赖和当前位置；区分已知结构与尚未探索的部分。其他目标选择适用结构，不强制套页面树。
3. **算清待办。** 根据预期与实际差异，列出尚需验证/处理/探索的事项，包括需滚动检查、展开或观察的区域，不能只列已经可见的入口。已验证事项按上下文身份去重，受阻与跳过独立保留；比较累计历史、上一轮与当前授额区间的结果。
4. **寻找路径。** 选择仍可执行且服务待办的路径，包括必要返回、滚动、取证和重规划。保留全局清单、沿当前有价值路径深入，由Agent结合连续overview中的预期成果、阻碍及下一路径判断何时切换；不固定先广或先深，不因其他一级项未访问就强制返回（D10）。当前分支受阻就记录阻碍，先继续其他可执行分支；不能因待办存在就盲目重复失败动作。
5. **作决定。** 对照本段预期与成果，选择继续、探索/恢复、重规划、补证据、报告受阻或提交完成判断。Runtime在资源接近阈值时主动触发明确复核；Agent需要继续且资源不足时，关联overview、下一检查点及用途申请额度。默认按Run初始额度的20%分别向上取整，可据下一段工作说明调整理由，不是方向正确或必须获授的证据。

执行后等待本步预期条件并重新观察、验证，再形成下一overview，从预期开始复核。回执只证明投递，稳定画面也不单独证明到达目标。新证据可修订路径，不得改写原目标、既有结果或本段消耗。

顺序：敲定预期 → 根据预期看结构 → 算待办 → 找路径 → 作决定 → 执行/观察 → 下一轮对照。

## 4. 数学和数据结构能推断到哪里

对已知、有限的验收事项集合，可比较已验证集合与待处理集合；对已知导航关系，可判断下一目标是否有路径；对连续overview，可对照新增验证、新发现、失败重复及依赖是否解除。这些能支持明确的结论，减少纯主观判断。

需要区分两件事：
- 当前已知待办是否仍有可行的下一段路径，通常有结构可查。
- 整个真实系统是否已穷尽、某路径是否永远不可能成功，部分观察下未必能证明。缺证据时保留Unknown，并有界取证。

“正确路径”不要求每一步都增加覆盖数。必要返回与探索可以服务下一个待办；持续做新动作也可能脱离任务。Agent需要解释当前路径与目标的关联，事实投影应提供核验依据。

## 5. 当前场景示例

| overview事实 | 建议推断（待最终规则定稿） |
|---|---|
| 一级页面仍有未处理项，存在已知安全入口 | 可继续遍历；临近预算时支持续额。 |
| 当前子页检查完成，需要返回进入另一一级页面 | 返回是必要路径，不因本轮未新增覆盖而认定无进展。 |
| 当前分支受阻，其他一级页面仍可处理 | 记录阻碍、转其他分支，不把局部失败扩大为任务终止（Q7已确认）。 |
| 最近授额只是在已验收页面间反复往返，没有实现检查点或产生新依据 | 解释偏差并改计划；不以更早成果为同路线重复续额。 |
| 已知一级事项处理完，但仍有适用子页未处理 | 不能仅以一级列表为空宣布全遍历完成；按已确认预期继续核对待办。 |
| 一级列表已处理，但未确认滚动后是否还有新入口 | 仍有探索义务；补充证据，不伪造完整分母。 |

## 6. 其他目标的复用方式

复用的是思考流程，不是页面树：任务可表现为清单、依赖图、目标状态约束或需消除的不确定性。根据实际目标选结构和验收方式，仍通过overview比较历史、本段成果、剩余义务和下一预期；本Change暂不为尚无真实消费者的任务预造通用规划引擎。

## 7. Q6：什么程度的“完成”可判断（Owner已确认方向）

未知UI结构中，已知待办为空不能证明分支已穷尽。当前实现的nested maxDepth=1、maxEntriesPerPage=1，以及“至少8个二级页面”等要求，只能反映其配置范围，不能证明该分支所有可能状态都已遍历。

建议overview直接表达：本次预期是什么、已验证哪些事项、已知待办多少、哪些受阻、哪些范围还未确认。不要自动产生“整个分支已完成”的绝对结论。

只有预期范围已明确、该范围内验收事项均有满足证据、相关探索义务也已满足时，才能提交“本次范围要求已满足”的完成判断，最终仍由既有Assurance/Outcome机制验证。

例：若预期明确为核验列明的3个入口，三者均验证后可以证明该项预期已满足；若预期是遍历该页面下所有可能入口，入口全集未知且缺少穷尽依据时，不能由“当前看不到新入口”推断全部完成。滚动到底等观察只证明相应观察范围，不能自动证明所有设备状态或权限分支。

有限已知集合可作集合差计算；开放、动态发现的页面空间必须同时保留探索完整性的未知。对已有证据作有界结论，不把不可证明的范围伪装成数学上已闭合。

## 8. 图模型复用（D9；具体缝待设计）

World Model已有图与关联的基础实现，当前产品未建立可用于跨页寻路的页面图。沿现有World Model补齐观察背书的页面身份和导航关系，向overview/遍历提供只读投影；任务已访问、验收、受阻与额度记录在原Owner侧关联，不写成World Graph中的目标/完成真相。

一级/分支可以树状展示，实际多入口/回跳保留图关系；未观察目标只作为入口候选。历史路径每次执行仍核对当前事实与权限，不能以图中存在边替代本步grounding和验证。当前单容器消费假设必须随图的真实页面粒度接入一并处理，不能直接换一个screen signature来绕过。

现有Coverage账本已有观察即发现、已验证进入后转入visited的局部能力；Snapshot和Heartbeat的当前可见集合不等于全局待办。设计应接通既有事实的投影消费，而不是为此另造一套可变状态。实际代码核验与行业资料见`docs/research/mobile-ui-traversal-sop-calibration-20261018.md`。整体提案见`proposal.md`，当前待最终共同理解确认。

## 9. Q11/Q12：续额复核的触发与下一段预期（Q11已确认；Q12受托自查方案）

Owner已澄清Q11所指为Kernel/Runtime。必须区分资源触发、目标相关判断及规则执法：前者按剩余额度即可计算；目标判断由Agent结合overview作出；规则侧校验提案并记录授/拒。程序主动发起复核不等于程序理解目标或自行续额。

当前调用链核查（2026-10-18，源码检查，非运行测试）：
- `KernelRunDriver.Drive / NeedDecision`在咨询前检查轮次，轮次耗尽直接返回consult-budget-exhausted；有额度时计算续额窗口并构造咨询。
- `IsRenewalWindowOpen`只按StepsRemaining/RoundsRemaining与阈值计算，不需要目标语义。
- `ConsultAgentV2`已传Objective、BudgetRemaining、RenewalWindow及计数式Progress；缺少本Change所需完整overview。
- `AgentDecision`中的Renewal为可选；`ProcessRenewal(null)`直接返回false，不代表Agent已明确拒续或完成复核。
- `ValidateRenewal`检查通道、窗口、正数及累计上限，不判断是否朝目标推进。Prompt要求适时申请，但这与协议中有明确复核结果不同。

已确认（D13-D16）：额度接近阈值，由Runtime在现有决策边界明确发起复核，提供目标、全局概览、本笔预期/实际和剩余额度；Agent明确选择继续并提议必要额度、调整路线、补证据或提交结束判断；Runtime按规则落实和记录。尽量合并正常决策咨询，不额外制造设备动作。须预留复核可用的咨询额度，不能到轮次归零后凭空补一轮；漏答给予一次计入既有资源的纠正机会，仍未完成则不授额并记录原因。授额及重规划不重置累计消耗、失败事实或上一段预期。

下一段预期按当前信息粒度表达：准备推进哪个分支/范围或查明哪个问题、依据什么、下一段应获得哪些可观察证据。路径只需说明可执行的下一段，不预演完整未知树；不要求固定新页数量或保证成功。受阻和偏差需解释，不能改写上一段预期或抹去消耗。

| 场景 | 校准后的要求 |
|---|---|
| 只知道一级入口，子页尚未知 | 可以提出进入该分支并辨识子入口，以观察作为检查点；不先编出子页清单。 |
| 返回根页才能进入其他待办 | 说明返回服务于哪个下一目标；必要返回不强制产生新覆盖数。 |
| 本段预期未达到，但明确查明前提不满足 | 保留未满足结果，另记探索所得；据新事实判断换路或下一段有界取证。 |
| 分支受阻、其他分支可执行 | 标明局部阻碍与可替代方向，不宣告全局失败。 |
| 动作持续成功但只在旧页面往返 | 动作成功不能支持续额；核对与预期的关联，需新依据或调整路径。 |
| 步数尚多、咨询轮次即将耗尽（或反向） | 分别查看所需维度，及时复核；不能只延长步数而没有后续咨询能力。 |

以上为源码和反例设计检查，不宣称已实现明确复核要求、语义推进校验或现场验证通过。20%基数及资源边界已由D14-D16确认，协议形状在整体确认后设计。正常推进且下一段有依据可持续逐笔续授；预期偏差、同路线无新成果或证据不足时加强历史对照和解释，不按无依据累计步数硬停；若另有明确资源授权边界则独立执行，不承诺固定步数内必然终止。
