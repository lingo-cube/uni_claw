## 5. 热点排序（全 benchmark 按 totalMs 降序；单次观测，非统计）

1. **WorldReconciliation ≈ 17.6 ms**（全部 phase 合计）——每条 evidence 全量
   copy parent WorldState（FrozenDictionary → Dictionary 重建）+ graph/conflicts
   复制 + association + occurrence 派生；输入规模随 revision 增长
   （scroll01：第 55 条时 copy ~50+ entries）。
2. **OccurrenceDerivation ≈ 5.6 ms**（⚠ wall-time 上含于 #1 的 reconcile
   span 内部，排序按独立缝测量，禁止与 #1 相加）
3. FastPerceptionStrategy ≈ 0.85 ms（corpus double = 内存查表；**真实
   OCR/YOLO provider 下此项会跃升为第一**，本数字不可外推）
4. EvidenceAdmission ≈ 1.2 ms（其中 ~0.7 ms 为首场景 JIT；稳态 ~µs 级/条）
5. SliceDerivation ≈ 0.96 ms / CurrentGrounding ≈ 0.37 ms（首调 JIT 主导）
6. ProposalEmission / CaptureArtifact ≈ 0.2 / 0.09 ms

结构性结论（静态可证，与耗时无关）：reconcile 的输入规模 = parent
world-state 条目数（线性增长），grounding/slice 的输入规模 = 当前
occurrence 景观（revision-local、有界）。

## 6. 测量限制（必读）

- **capture 为 host 侧测量**：v0.1 无 runtime capture 编排组件，CaptureArtifact
  在 fixture 包真实 `RawArtifact.Capture` 调用测量（真函数、真 SHA256 成本），
  非 runtime trace 绑定（LAT-001 D3）。
- **occurrence derivation 含于 reconcile**：独立数字来自 IUiObservationStrategy
  装饰器（真实缝），其 wall-time 是 world.reconcile span 的子集。
- **corpus double ≠ 真实 provider**：strategy/emission 的绝对值不可外推；
  本基线的结构性结论（调用次数、规模、复用路径）与成本分布无关。
- **单次运行、无迭代平均**：ms 数字含 JIT / GC / 首跑膨胀（golden 场景与各
  stage 首调明显偏高）；计数与规模断言确定性可复现，ms 不可。
- **观察自身开销**：InMemory trace + metrics 启用时的 span/Record 成本包含在
  stage 之外的驱动路径中；F5 已证 canonical 不受开关影响，但 wall-clock 会。
- **单线程、进程内**：无并发、无 IO、无真实设备。
- 无 slow escalation 路径（运行时未实现，未伪造数据）。

## 7. 非侵入性证明（A3）

- F5：trace × metrics 四象限下 EvidenceIds / relevance 序列 / revision 结构链 /
  Slice / GroundingView 投影全等（golden 全场景驱动）。
- F6：ThrowingRunTrace 在 perception / slice / grounding 新缝全吸收，canonical
  输出与禁用态一致（TRC-001 既有 Process 缝先例延续）。
- F7：span 拓扑 = 词表执法零违规（唯一 diagnostic = 观察 run 未发 RuntimeOutcome
  的诚实 Quarantined 降级）；perception 三 span 的 Artifact 因果与父子关系成立。

## 8. OTel 适配性结论（LAT-001 D9 摘要）

先不接；两层观察模型：TraceCatalog（封闭词表/确定性）= run 结构真相，
ActivitySource/Meter（BCL）= 未来组件集成契约层，OTel SDK = 出进程时宿主侧
可选路由。数据面适配：Metric 近 1:1；Trace 只能实时桥（冻结 artifact 无
时间戳，离线导出不诚实）；Event 无损；生命周期语义（Quarantine/深冻结/
StructuralOutcome）不映射。重开触发器：长驻 host / 真实诊断需求 / 多进程
拆分 → 先 BCL 桥。实现约束：埋点保持缝级、观察接口面窄稳、组件自报信号
永远非权威。

## 9. 对 P1（Frame Computation Reuse）的基线意义

- 判据已就位：P1 落地后同一 fixture 的 warm 相应显示 strategy invocation 从
  4 → 1（presentation 数不变、invocation 数下降），F5 形等价测试换缓存开关
  后继续证明 canonical 全等。
- 本基线同时预警：corpus double 下 reconcile 才是热点——P1 的端到端收益
  上限受 strategy 占比约束；真实 provider 下该结论会反转（§6）。
