# PNL-003 / WI-PNL003-016 — DSH Static Client / Browser Bridge 验收

## 做了什么

把共享 Workspace 的 browser bridge 接入 DSH classic static Client，并完成 profile 部署、专用 DSH 重启和真实浏览器入口验收。

## 原来的问题

DSH client 已能显示入口，但 Host Typert 返回的 `{ok, value: {success, ...}}` 没有被共享 capability contract 接收；观察运行产物里的 `productSessionId` 也没有进入导航实例；任务卡没有事件委托，点击后不会加载四个只读面板。

## 这次修改

- `entry.js` 在 DSH seam 解包 raw / `data` / `value` 三种 Typert 结果，补齐 `observedAt`，并把 host failure 转成 QueryError。
- browser bridge 注册共享 Workspace 的刷新、项目、任务、明细点击事件；选择任务后并行读取 session/timeline/trace/evidence。
- DSH artifact observed instance 保留显式 `productSessionId`，浏览器侧建立 ProductSession→DSH session 的内存只读映射。
- capability 调用增加 10 秒超时，避免 DSH 连接不可用时页面永久 loading。
- 生成并部署 `dsh/uniclaw-task-workbench/src/client.js`；profile drift 检查保持 clean。

## 新发现

专用 DSH 进程能读取运行产物索引，但当前进程没有旧实录对应的活动 session snapshot；因此真实浏览器只能验收到任务导航和 ProductSession 映射，session/timeline/trace/evidence 走结构化超时。完整对话时间线已经由共享前端 fixture 入口验收；接入新的真实 DSH session 后会沿同一事件链显示。

## 结果

WI-PNL003-016 的 bridge、bundle、profile 和真实入口验收闭合。Host session 数据是否存在由 DSH session authority 决定，Workspace 不伪造对话、Trace 或 Evidence。

## Trace / 页签 / 执行结果分层复验

真实页面复验发现原 Trace 投影缺少稳定的可读字段，renderer 退回为重复的 `trace` 文本；同时 Trace、Evidence、Metadata 和单轮执行结果共用三列卡片，信息层级不清。本轮按产品语义收敛为：

- 页签只承载可切换的观察面：`Trace`、`Evidence`、`详情`。
- `Metadata` 和单轮 `执行结果` 留在右侧摘要栏。执行结果是当前任务/单轮运行的结论，不是与 Trace、Evidence 并列的证据流，因此不放入页签。
- DSH Trace 由 adapter 生成 `source`、`label`、`summary`、`type`、`ts`、`seq` 等可读投影，前端不再用对象缺失的 `id` 作为展示前提，也不伪造 UniClaw runtime 产物。
- 当当前 session 没有 UniClaw runtime 执行产物时，右侧显示 `当前 session 尚无 UniClaw runtime 执行产物`；这是数据边界的明确状态，不把 DSH submission 误标成 UniClaw execution result。
