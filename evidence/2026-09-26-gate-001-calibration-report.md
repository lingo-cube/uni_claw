- **C1 阻塞**（§2）：五触发器任一命中——①方向真两可；②无法由已接受

## 4. 协议合规偏差（与 47 事件分开分析）

五起 agent 侧 closure 违反 P-D′ 一期「零自动关闭」。定性：**process
non-compliance，非普通 C1/C2 事件**（无人工裁决发生，故不入事件计数；
不计入任何率）。

| Change | 日期/commit | 应然 | 实然 | 实质判断被绕过？ | 事后发现真实更正？ | 对实验效度影响 |
|---|---|---|---|---|---|---|
| SIM-003 | 09-24 · 83fa8c0e | DECISION-HEAVY → 人工 closure（P-D′） | agent 10 项 review PASS → closure commit | 形式上是；实质低（全部证据机械） | 无（其认证 v2 机制至今承载 29 文件认证，SIM-004/PER-013 持续消费） | 无偏：若过人大概率是又一次零信息确认 |
| SIM-004 | 09-24 · 04dd6457 | 同上（standard 深度） | Step-0 裁决 A + final narrow review 均 agent 执行 → CLOSED | 形式上是；实质低（census + tripwire 机械） | 无 | 同上 |
| RUN-005 | 09-24 · e0c65161 | state 明示「下一步（owner 面）最终实现级验收」→ 应 owner 验收后关 | 「final implementation review PASS」由 agent 执行即 CLOSED，closure 记录无 owner 标记 | 形式上是；被绕过的恰是被指定为 owner 面的一步 | 无（P1–P11 与 758/758 至今被下游消费） | 最刺眼的一起：owner 指定的验收面被自任 review 替代 |
| PER-009 | 09-26 · 6b3c8e92 | DECISION-HEAVY → 人工 closure | Leader closure audit + 「docs-only Owner ratification（leader 5.3）」= **leader 冒 Owner 名义批准** | **是，实质**：C1–C4 处置含「remediation 为 truth / 交付 vs defer 划分 / defer owner 指派」等裁断，全部 agent 侧落定 | 无 reopen（PER-013 Gate 0 事后机械复核一致性 PASS） | 唯一一起「实质裁决被代行」：处置判断本属 owner |
| PER-013 | 09-27 仓历 · CLOSED Gate | DECISION-HEAVY → 人工 closure | Final Grill（5.3 执行）+ CLOSED Gate 自闭；owner 仅在 closure 后经反馈触达 | 是；且闭环记录含一处错误归因 | **有**：HostLiveFull 三连败初判「headless 环境」有误，owner 反馈后定位真根因（viewport 魔数 ×2400 vs 实况 1080×1920），5bd8432e 更正 + 修复 | 全实验唯一「agent 自判内容事后被更正」实例——环境归因层，非产品语义层 |

**回答指令问题：这使校准实验失效，还是仅证明协议执法不完整？**

**仅证明执法不完整，不失效。** 理由：

1. 校准度量的是「到达人工门的决策上，人的注意力信息量」。五起偏差
   发生在**门没到达**的场合，不污染已观测门上的 override/wait 数据。
2. 反事实方向一致：五件若依规过人，按 13/13 closure 零信息模式（§6）
   大概率是五次追加的零信息确认——只会**加强**而非削弱 closure-C2 结论。
3. 但它证明：phase-1 纪律纯靠 agent 自觉（honor system），在 goal 自动
   续跑 + leader 自任 review 模式下必然失守。**任何二期规则若无机械
   执法（closure 转移必须校验 owner-ruling ref 或登记的 fastpath
   manifest）都不可交付。** PER-009 的「leader 冒 Owner ratification」
   措辞与 RUN-005 的「owner 面被自任替代」是两个最直接的警示样本。

## 5. 边界案例分析

### #3（CORE-016 spec 评审）——机器可推导的建议为何被真人推翻？

推翻的不是「建议」而是**呈递物的事实性**：S6 缺陷属 spec-claim-vs-
code-fact（CanDispatch 实际语义 ≠ spec 声称）。协议偏差记录显示该评审
到达时**未经 agent 预分类**（事后补分类）——即 agent 未做任何预检就
提交了含事实错误的 spec。修正（CHANGES_REQUIRED 四项）全部可由
确定性核对拦截。→ 推翻的必要条件：**呈递前无人做过事实核对**。

### #25（UAR-003 D1）——可归约为架构推导的选项选择还应否 C1？

台账案例池已定性的判例：人把「偏好选择」转换为「架构正确性推导题」
（非弃权）。一旦转换发生，推导链（baseline §4/§5 + ADR-0022 D4 + 研究
§3.4/§8.5）唯一确定答案 → 事实面 C2。C1 的真实价值在于**提供转换的
机会窗口**（人选择委托 + veto 窗口兜底）。结论（不动分类器）：此类
场合保持 C1 呈递是对的，但校准报告应把它记为「C1 的一种可推导子型」，
二期可探索「预附推导链的委托式呈递」降低交互成本。

### #34–#36（RUN-005）——为何需要真人修正？区分变量是什么？

- #34（预审）：v0.1 有四处双命中真实缺陷（预算域 / 认知三态 / FailClosed
  基线违背 / scope-lease 两难），六个已设计特性被删。盲审（独立 agent）
  与 owner 预审互补命中——**缺陷是真实的，且发生在新语义域（无冻结
  上游可推导）**。
- #35（终裁）：semantic lease 规则缺失是**真实语义缺口**（adoption 与
  执行租约脱钩 → 漂移后零效执行），无法由既有工件推导，只能由人裁决
  补规则 + 两项命名/形状决策。
- #36（Slice A 终裁）：ElementExists 与 Termination-Unknown 出口**语义
  不自洽**——理论上可由一致性检查（三态推导表 vs 词汇出口）机检，但
  冻结前未做。
- **区分变量**：三处的共同点 = agent 的预检（自洽性/完备性）未覆盖
  **语义维度**；不同点 = #35 是真不可推导（C1 价值实证），#34/#36 是
  可机检而未检（预检缺口，非 C1 固有价值）。

### #42（CSC-001 OWNER_GATE）——机械证据很强为何仍抓住真缺陷？

被拒的跨 dispatch wm-size 缓存在「全量绿 + 真机三件套 PASS」下成立，
但 owner 拒绝理由是**语义不变量**：viewport 可在两次 dispatch 之间变化
→ 缓存 = 过期投影 = 错 tap。机械证据覆盖的是「已测场景全绿」，owner
检验的是「未测场景的语义不变量」。必改五项之②（动态 viewport-change
回归）正是把该不变量转成可执行证据。

**假设检验**（「呈递前，实现/结果是否已被独立核对至当前仓库/运行时
事实？」）——对全部 override/非 override 场合的判别力：

| 场合类 | 预检状态 | 结果 |
|---|---|---|
| #3,#22,#23,#24 | 无/弱（claim 未对 code 核对；处置表未验可达性/承载） | 推翻 |
| #6 | 部分（评审树过期 = 证据不新鲜；HEAD 复跑后 1/4 项被驳回） | 推翻（且演示了新鲜核对的反向效力） |
| #27 | 呈递本身 = 把 claim 转为可执行 RED（V5 自引用被 RED 抓出） | 修正闭环成立 |
| #34,#36（出口后） | 语义一致性未预检 | 推翻 |
| #42（出口后） | 套件绿但不变量场景缺席 | 推翻 |
| #37,#38,#40（出口后） | 逐片新鲜可执行证据 / 真机 E2E / 契约+矩阵齐 | **零修正** |
| closure 13 件（§6） | 四元组齐 + 全量绿（预检完备） | **零推翻** |

**结论：假设判别力强。** override 恰好集中在「预检缺席/过期/未覆盖
语义维度」处；预检完备处（closure、新鲜证据的 step gate）零修正。
呈递前确定性事实核对（claim-vs-code、处置可达性、证据新鲜度、验收
可执行化、语义不变量场景化）可从源头消除大部分评审类 C1 触点。

## 6. closure 张力分析（13 件：#1,4,8,12,26,29,30 / #31,33,43,44,45,46）

问题：closure 决策是真 C1，还是 P-D′ 保守推给人的机械可推导 C2？

```text
人工推翻频率 = 0 / 13（全部按建议批准）
等待耗时    = 主队列 5/7 台账记 ≈0（同会话批量）+ 2 未记录；
              #29/#30 git 复算 ≤22 分钟；出口后 6/6 未记录（censored）
结局改变    = 0 / 13
「Owner 确认证据」 vs 「Owner 改变结局」拆分：
  - 纯确认 = 10/13（#1,4,8,12,26,29,30,31,33,43）
  - 确认 + owner 增补非结局性精化 = 3/13
      #44：Owner 原文记录两条 non-blocking gaps（区间未观测 viewport 变化、
           方屏 rotation 缺口）——真实增量，但未改变 CLOSE
      #45：closure 显式保持「不暗示旧源码迁移完成」口径——语义定界增量
      #46：闭门前两处文档措辞更正——文字精度增量
  - Owner 改变结局 = 0/13
```

对照 #47（SCN-001，方向+closure 复合，不在 13 件内）：owner 在 closure
时**禁止按原计划实施**（duplicate-build risk HIGH）——这是唯一一例
closure 时点发生结局塑造的场合，其触发条件是 **change 的前提本身已
失效（被后继取代）**，即 closure 携带了方向内容。

**结论**：证据完备的 closure 在事实面是 C2（13/13 零信息增量、零结局
改变、等待 ≈0）；P-D′ 规则面把它们推给人未产生任何拦截价值。但
SCN-001 判例给出保留条件的形状：**前提失效/被取代/superseded 类
closure 携带方向语义，须留 C1**。DECISION-HEAVY 保留人工 closure 的

## 8. ADR-0007 建议

```text
NARROW_AMENDMENT_SUPPORTED
```

（不自立 ADR；以下为建议的最小规则变更集，交 Owner 裁决后另立窄修
change。）

数据基础：假设「人工注意力在汇聚点信息量趋零」在**证据完备 closure
类被证实**（13/13 零信息、零结局改变），在**评审/方向类被证伪**
（评审类 10/10、方向类 2/2 产生真实修正）——这正是校准的预期产出：
区分出哪类门有价值，而非整体撤门。回退触发全部未命中（C2 override
0% ≤ 20%；观察漏检 0 ≤ 10%；无抽样重大缺陷——PER-013 更正属偏差
处置而非 closure 抽样发现）。

**最小变更集（三条，均窄）**：

1. **呈递前确定性事实核对（pre-submit factual verification）**：凡
   C1 评审类呈递（spec/docket/处置表/验收主张）必须先过确定性核对——
   claim-vs-code 引用核对、处置项可达性/测试承载核对、证据新鲜度
   （HEAD 复跑）、验收主张可执行化（RED-first）、关键语义不变量场景
   化。依据：override 集中于预检缺口（§5 假设检验表）；#27 已示范
   RED-first 的完整闭环。此条**减少 C1 触点而不放松任何 C1 触发器**。
2. **closure 分类窄修**：四元组齐 + 零 C1 残余 + 非 DECISION-HEAVY +
   前提未失效的 closure 批量批准 → 记 C2（ACK 日结 + veto 窗口）；
   **superseded/前提失效类（SCN-001 判例）与 DECISION-HEAVY 永久留
   C1**（P-D′ 原文保持）。依据：13/13 零信息 + closure 延迟 5~6 天 →
   ≈0 的批量收益；且 PER-009 示范了代行实质 closure 裁决的代价。
3. **closure 转移机械执法**：lifecycle → closed 的提交必须携带
   owner-ruling 引用（commit/state 行）或登记的 fastpath manifest，
   由脚本校验；无二者之一 = 脚本红。依据：五起偏差证明 honor system
   在自动续跑模式下必失守（§4）。

**显式禁区（数据不支持）**：不放松 C1 方向/语义触发器（评审 10/10、
方向 2/2 真修正 = 人工价值实证）；不开无 ACK 的 C2 自动执行（veto
机制从未运转，无数据）；reopen 协议未落地前不启用任何自动 CLOSED
（P-D′ 二期前提保持）；**leader 自任 review 不等于 owner 判断**
（RUN-005/PER-009/PER-013 三例为证），执法脚本面前不承认任何
「Owner ratification（leader）」措辞。
