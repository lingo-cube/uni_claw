# Android Automotive UI 自动化测试

## 使用范围

当任务需要通过 Android UI 观察状态、执行受控交互并交付可核对的结果时使用本 Skill。你负责理解测试目标并提出可执行方案；Task、有效授权与产品策略定义本次测试的边界。Skill 本身不授予 Capability、Effect 或 Memory 权限，也不替 Kernel、Runtime 或具体 handler 执行工作。

正式载荷的唯一来源是本运行已装配的 UniClaw Agent Product Protocol：`uniclaw.agent.protocol.v1` / `uniclaw.agent.schema.v1`，Schema 标识为 `https://uniclaw.dev/schemas/agent-protocol/v1`，决策定义为 `AgentDecision`。使用当前工具提供的 Schema、目录及装配指纹解释精确字段；本 Skill 只提供领域指导，不复制 Schema，也不要求从标识地址联网加载协议。

## 指导流程

1. **理解独立期望与授权预算。** 提取任务给出的目标、必需结果、禁止行为、作用范围、有效授权和剩余资源。测试期望来自任务、用例或需求；可指出歧义并建议补充，但不得自行降低目标，再用降低后的目标判定通过。若目标、授权资格或关键约束缺失，说明缺口并请求适当输入，不用探索补造。
2. **整理当前事实与未知。** 阅读本次运行提供的 UI、世界状态、历史记录和能力目录。区分当前可验证事实、历史证据、推断和未知；保留各事实已有的来源与时效边界。只有缺少完成方案所需的 UI 事实时，才提出有目的、有界的观察；说明要确认什么、停止条件是什么，以及观察结果如何影响下一步。
3. **按声明目录选择操作与策略。** 只选择本次有效目录中已经声明的策略、操作、检查、条件和参数。遵循适用 Task、产品 policy 与正式契约：弹窗或危险操作的资格必须由有效策略明确支持；无法确定时停止该路径并报告。不要复制或另造授权名单、假定页面、车型/OEM 脚本、能力 ID 或定位事实。
4. **选择合适的计划粒度。** 对跨页面、结构未知或需重复遍历的任务，组合已声明的 PlanTree/Traversal 结构；对已知且确定的目标，使用依赖阶段或目标态策略；对单个明确动作，可直接提出精确 Act。只选完成任务所需的结构，不要求 direction、execution、precise 等固定三轮咨询，也不为形式齐全而加入节点。
5. **校验并按策略演练或修订。** 提交前检查步骤依赖、输入来源、作用范围、停止条件、必需验证和所需能力是否满足正式契约。只有当所选策略、预算和反馈要求时才演练或补证。校验拒收时依据返回的位置、原因和合法修正范围处理：可补充事实、调整计划或请求缺失信息；修订必须保留独立期望、授权边界与已消耗预算。不得把拒收自动当作重试许可；有界预算用尽或约束冲突时停止并说明。
6. **按操作绑定有序 handlers。** handler 仅放在该操作声明的 `before` 或 `afterVerified` 中，并严格按声明顺序处理：所有 `before` 满足其继续条件后才执行操作；`afterVerified` 仅在原动作独立验证成功后运行。`ReadOnly` 不产生额外点击或其他 Effect。按照正式契约设置 `required`（绑定是否必需）与 `requirePass`（领域结果是否必须通过）；领域不符合或 Unknown 是专业检查结果，调用失败、超时或取消是调用生命周期结果，两者分别保留。
7. **交由 Kernel 运行时协调执行。** 计划或 Act 通过正式协议提交后，由 Kernel 运行时协调已声明能力，并由各 Owner 按既有职责执法。Skill 只提出测试意图，不直接执行 handler、不赋予 handler 执行 Owner 的权力，也不绕过每个现实动作已有的授权、绑定、验证与状态更新链。handler 为异步时等待既有调用并查询其状态；`Running` 只表示调用仍在等待，不能当作成功，也不能据此重复提交计划或 handler。
8. **消费反馈并遵守恢复边界。** 根据本次运行返回的调用状态、领域检查结果、验证事实、预算变化和失败原因，判断可继续、需修订、需补证或应停止。是否暂停、重试或进入 Recovery 由既有策略及其 Owner 决定。执行后事实已变化时，不把重新生成的计划当作从头安全重放的许可；只按 Kernel 运行时给出的当前位置与恢复边界继续或交回处理。不得用继续或重提来重开已超时的必需调用；迟到结果不覆盖终态。
9. **交付结果与证据。** 逐项对照原始独立期望，报告通过、未通过、未验证及阻塞项。为每项结论给出 method、expected、actual、evidence；引用本次运行产生的协议回执、检查结果和证据标识，并说明仍未知的部分。历史记忆只可辅助解释，不能替代当前验证。

## 失败与安全

遇到未知页面、事实过期或冲突、能力缺失、策略不适用、权限不足、验证不可用或证据缺口时，不猜测坐标、不虚构能力、不扩大权限、不静默重试。指出已知事实、具体缺口及所需的策略、能力或人工输入，再按当前正式边界停止或交回处理。探索必须有明确目的、预算和停止条件；每次观察后说明计划是否因此改变及依据。
