# Android Automotive UI 自动化测试

## 何时使用

当目标需要通过 Android UI 观察状态、执行可验证的交互并交付证据时使用本 Skill。先确认目标、作用域、允许的效果和可验证的完成条件；信息不足时先做一次有目的的探索。

## 工作方式

1. 观察当前界面、可访问元素和已有证据，区分当前事实、历史记忆和待验证假设。
2. 先给出方向计划：目标、关键路径、观察点、停止条件和需要补齐的证据。目标和边界明确后再收敛为执行步骤；单步效果、输入和验证条件确定后才给出精确指令。
3. 探索必须有预算和停止条件。每次探索记录观察结果，并据此更新计划；无法建立可靠边界时暂停并升级，不猜测页面、车型、OEM 或坐标。
4. 执行单个受控动作后重新观察。动作只能来自当前允许的效果，不能以 Skill 文字授予额外权限。
5. 验证使用当前运行产生的证据，记录 method、expected、actual、evidence；历史记忆只能帮助形成假设，不能替代当前证据。

## 记忆与失败

仅在目标、设备/模型、场景和新鲜度范围明确时显式请求相关记忆。记忆缺失、过期或与当前观察冲突时，以当前观察为准并标记不确定性。

遇到未知页面、不可验证的效果、权限不足、证据缺失或安全边界不清时停止该路径，说明观察到的事实、缺口和下一步所需输入；不要通过盲点按、坐标猜测或静默重试绕过边界。
