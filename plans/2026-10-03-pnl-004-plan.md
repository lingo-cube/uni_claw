# PNL-004 Plan — Task Launch、分阶段元信息与本地 Query Storage

> PlanType / Status: ADOPTED  
> Change State: `changes/PNL-004/state.md`  
> 目标：把已冻结的 launch/query 边界变成可替换的本地实现；不把文件目录、DSH Session 或测试集资产升级成 Product truth。

## 垂直切片

```text
S1 Contract
  → S2 Test Catalog assets
  → S3 Task Launch + Local Storage
  → S4 Query projection + shared metadata view
  → S4.1 Trace source context remediation
  → S4.2 Production Runtime/Host adapter registration
  → S5 real/negative verification
```

S2 可先于 S3 独立完成；S3 必须依赖 S1/S2；S4 依赖 S1/S3；S5 依赖全部前置。

## S1 — Launch / Metadata / Storage Contract

冻结语言无关契约：

- `TaskLaunchRequest`：project/testSet/task refs、`version: default`、可选环境配置、requester/correlation/idempotency。
- `TaskLaunchAck`：稳定 `launchId`/`taskInstanceId` 引用、阶段状态和已生成字段；允许部分完成。
- `LaunchStageRecord`：stage、source、authority、availability、`valueOrigin`、correlation、时间和诊断原因。
- `valueOrigin` 只允许 `configured | generated | observed | derived`；与 availability 分开。
- `LocalStorageNamespace` 与 Query response 的逻辑引用；不暴露物理目录。

产出：schema、正反例、validator 更新、字段 Owner/Authority README。

## S2 — Repository Test Catalog

在现有 `testsets/` 下为 Android Settings 与 Workspace Contract 增加最小 `manifest.json`：

- projectRef、testSetRef、`version: default`、tasks、fixtures、sourceRevision（可选）。
- 任务、fixture 和验收条件使用逻辑引用；目录结构不进入公共响应。
- 校验缺字段、重复 id、引用不存在、非法 version/sourceRevision。

## S3 — Task Launch + Local Storage Adapter

实现本地 Host adapter：

1. 接受 S1 launch request，解析 S2 catalog asset。
2. 通过既有 Product/Runtime/Host seams 创建或取得 Task Instance、Product Session、`runId`、primary Host Session。
3. 创建/恢复 storage namespace，按阶段追加记录。
4. 以幂等键重试不重复创建；阶段失败保留 partial/unavailable 和诊断原因。
5. 不从目录名、artifact 文件名或 DSH Session 推导 Product identity。

优先复用现有 `TaskRepository` 和 `instantiateTask`，但要修正“Host Session 已创建而 repository 写入失败”时的恢复/补偿语义。

## S4 — Query Projection + Shared Metadata View

- Query capability 继续保持只读五类接口；Task Launch 不加入 Query schema。
- Task/Session/Trace/Evidence/Detail projection 增加逻辑引用、launch stage、`runId`、source/authority/availability/valueOrigin、snapshot/observedAt。
- shared Query Core 和两个入口只消费逻辑引用；前端展示 configured/generated/observed/derived 标签。
- DSH/UniClaw Trace 保留 source-native 结构，合并视图不伪造 OTel Span parent/duration。
- 旧 capability 和旧 task/instantiate API 保持兼容投影。

## S5 — Verification

覆盖：

- configured + generated + observed + derived 同时存在的真实 Android 场景。
- 无 artifact 的 Session。
- 未关联 Host Session。
- Runtime/Host/storage 任一阶段失败。
- 同一 idempotency key 重试与 Host 重启恢复。
- Trace 分页/截断、局部 Query 失败和详情读取。
- 独立 Web 与 DSH 两个入口，真实 3083 浏览器场景。

## S4.2 — Production Runtime/Host adapter registration

当前契约实现只在测试上下文注入 `uniclawRuntime`。生产代码仍需要一个显式
adapter：接收逻辑 project/testSet/task refs 与 launch metadata，由 Runtime
生成并持久化 `runId`，创建/返回 Product Session，再把 `runId` 与
`productSessionId` 注入 HostRunner/DSH consultation，并注册为 DSH plugin 的
`uniclawRuntime` capability。adapter 不能把逻辑 projectRef 当 filesystem path，
也不能修改 AGT-001/RUN-005 或让 DSH Session 成为 Product truth。
