# PNL-005 Plan — Runtime Run 状态、事件与查询投影

Change State：`changes/PNL-005/state.md`

## 目标

在 PNL-004 的真实 DSH Host launch 之上，建立 Host-owned RunStore 和稳定 Runtime 查询契约，让 Workbench 能读取运行状态、来源事件和产物引用，而不依赖进程内存或本地目录。

## 阶段

### S1 — Contract

- 冻结 `RuntimeRunProjection`、`RuntimeRunEvent`、Run response、events response schema。
- 冻结 HTTP status 与业务错误对象映射。
- 增加 valid/invalid examples 和 schema validator 覆盖。

### S2 — Domain / Store

- 在 Host 边界实现 RunStore abstraction。
- 文件 adapter 保存 snapshot、append-only events 和 artifact index。
- 维护 sequence、revision、observedAt、consistency。
- 不改变 Kernel 的证据 authority。

### S3 — Runtime HTTP

- `POST /api/uniclaw-runtime/runs`：创建 Runtime-owned identity，返回 `202`。
- `GET /api/uniclaw-runtime/runs/{runId}`：返回 RunProjection。
- `GET /api/uniclaw-runtime/runs`：按 status、productSessionId 和 opaque cursor 返回摘要列表。
- `GET /api/uniclaw-runtime/runs/{runId}/events`：分页和 source filter。
- 统一错误业务对象和 HTTP 状态。

### S4 — Workbench Adapter

- 将 Runtime projection 映射到 TaskInstance projection。
- 页面只通过 adapter 查询，不访问 runs 目录。
- 提供 fetch-based host-neutral adapter；DSH、ego-lite 和 standalone host 只需提供 HTTP/detail seam。
- 保持 DSH trace、UniClaw trace、Evidence 和 Outcome 的来源包络。

### S5 — Verification

- 契约测试、确定性 store 测试和负向场景。
- 真实 3083 DSH → 3090 Runtime Host → emulator-5556 验收。
- 验证大 payload 分页、绝对路径拒绝、interrupted/failed/completed 区分。

## Review gates

- Run identity 只由 Runtime authority 生成。
- Workbench 不拥有 Run lifecycle。
- DSH Session 不被升级为 Product Session。
- 事件只追加，不由 snapshot 反写历史。
- 所有 detail 引用都是逻辑引用，不能成为任意文件路径。
