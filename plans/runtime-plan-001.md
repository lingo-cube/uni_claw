# RUNTIME-PLAN-001 — 产品执行Plan实施

2026-10-18。设计已确认；本文件规定实现顺序及可执行验收。Owner新增实施授权已记录于Change State；当前按此推进，设备行为仅以本Change新证据确认。WHAT/WHY以[Change State](../changes/RUNTIME-PLAN-001/state.md)为准，架构取舍见[ADR-0053](../docs/adr/0053-composable-product-plan-with-bounded-local-execution.md)。不绑定开发模型/Host，不建立第二份生命周期。

## 1. 先证明的行为

Agent给出当前允许范围的遍历规则后，系统处理多个已知入口；新发现入口仍被规则覆盖时继续；遇到有证据且可安全绕开的局部阻碍，记录后处理其他项；到预算检查点暂停复核，获授且明确沿用Plan后从原处继续。每个动作仍用当前事实校验和验证。目标是减少逐动作完整决策，而不是减少必要观察或隐藏模型调用。

## 2. 开工基线与修改归属

- 共享checkout当前存在大量其他Change修改。开始实现前重新记录状态与恢复快照，确认ADR-0052实况及相关文件所有权；不清理、覆盖或搬走无关编辑。既有入口/定稿快照见Change State。

## 3. 切片一：小范围动态遍历贯通

先写能暴露缺口的确定性场景，再贯通最小表达、正式通道、当前步guard、规则展开及中途复核；不先完成一套通用语言。可用受控输入使A可处理、B有证据受阻、处理后发现C；每次物化都读取最新候选和语义目标。

验收必须可从trace/journal复查：

1. 一份采纳Plan至少产生多次独立验证的动作，新出现C在规则允许时本地处理；除初始/预定检查点/必要复核外，不为每次点击请求完整Agent。
2. B受阻有Owner事实来源且可安全继续，保留原因而非标完成；若前提/许可未知或当前无法安全换路，正确回Agent，不强求本地继续。
3. 到资源阈值后，在当前动作对账的合法边界暂停；检查点位置、已完成事项与消耗保持。
4. 仅获续额不自动发动作；明确沿用当前Plan引用且仍适用时继续。同版本/节点的不同迭代和实际尝试具有不混淆的证据关联，已确认动作不重发。
5. 正式Schema、converter与Prompt一致；先用协议fixture证明形状，再由实际产品模型证明能生成/消费。fixture不冒充模型或设备实测。

阶段产物是这条行为的代码、回归及证据；线性Plan往返只是基础，不能替代上述动态验收。

## 4. 切片二：结果、修订和失效边界

沿用同一操作/执行接口，补完以下有现实后果的反例：

| 输入/触发 | 可判定期望 |
|---|---|
| 前提已证不成立 | 无新Effect，仅按已声明规则跳过/备选或咨询，不算已完成 |
| Guard未知/冲突 | 保留未知及既有失效出口；不把未知当false，不隐式走本地动作fallback |
| Observe取得缺失事实 | 只有合法观察/Control路径可补证；工作量/调用记账，重检后才决定下一动作 |
| 动作在途时暂停/再次驱动 | 继续同次结果接收/对账，无重复dispatch，不在屏障前切换分支 |
| 动作已对账但未达预期 | 保留失败；只有规则及当前事实足以支持安全恢复才继续，否则咨询 |
| 相关前提变化/普通页面更新 | 前者重检或失效；后者规则仍覆盖可继续，不能按任意revision变化一刀切废弃 |
| Agent修订Plan | 在对账边界采用新版本接替未执行内容，旧结果/失败/预算保留 |
| Agent改为Act/NoAction | 显式处置旧Plan，遵守该决策原有语义；不偷偷拼接或续跑旧规则 |
| 零Effect条件/观察空转 | 达到局部工作界限让出，不自动清零重开，不宣布任务完成 |
| 当前候选为空 | 有已支持探索规则则继续；范围未证时报告未知，不认定遍历全部完成 |

这张表定义要证明的行为，不要求每行新增一种公共类型或镜像实现的单元测试。优先从公开消费缝和现有Driver场景验证。

## 5. 切片三：不同结构买方与overview

使用现有仿真条件组织记录核验任务：记录集合、状态依赖、明确补证、核验结果与局部受阻，不包含页面树或返回菜单。更换事实/操作实现和参数，运行相同Plan组合及执行核心；若需要在核心加入场景名特判，先回设计找耦合。

沿用既有overview，把Plan版本/位置关联到本段预期、实际已验证成果、事项/未知/阻碍及复核历史。通过“处理2项又发现5项”证明待办增加也可有目标相关进展；通过旧事实重复/无关新日志证明它们不能支持新的授额。事实与授权、进度和完成权威仍归原Owner。

## 6. 切片四：真实Settings及三组性能对照

现场环境按[模拟器测试规范](../docs/agents/test-emulator.md)预检，固定允许范围并保存初态；禁止将任务限制放宽后与窄范围基线直接比较。

对已知多步和动态候选两类任务段分别运行：逐步Agent、固定已知短Plan、动态规则Plan。各组使用相同目标、权限、模型及观察/验证要求；合法路径可以不同。先保存基线和数值验收门槛，再读取新方案对照结果。若只能得到探索性小样本，明确报告，不能宣称普遍改善。

每次试验记录真实达成/未知/受阻结果、完整决策及其他模型/慢感知调用、输入输出token/可得费用、总时延、设备动作、错误提案/纠正/重规划及失败运行消耗。关键样例重复并报告样本量/差异，不只计成功轨迹。若调用下降但总费用/时延未改善，定位主因并如实保留未达标状态。

## 7. 同步与收尾要求

相关正式协议、Prompt、Schema/类型及hash生成物、公开面执法/场景重认证、文档及索引随同一实现同步；运行的检查由实际修改面选择，不因文档准备提前运行全套设备测试。

Review单独判断职责、协议和改动质量；Verify按method/expected/actual/evidence证明上面的行为、真实与仿真证据以及性能限制。未满足动态规则/续行/泛化时，不以短Plan通过宣称全部完成；小范围Settings也不等于全遍历。跨进程自动恢复、完整BT/HTN平台与在线代码技能不在首版范围。
