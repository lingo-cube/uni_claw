### 详细说明

#### Phase 1: FetchTasks (获取任务)
```bash
openspec instructions apply --change "<name>" --json
```
**输出**: 任务列表、进度、上下文文件

#### Phase 2: AssignTask (分配任务)
**规则**:
- 优先处理无依赖的任务
- 检查依赖任务是否已完成
- 按优先级排序

#### Phase 3: Implement (实现任务)
**Agent**: Opus (架构师级别)
**流程**:
1. 读取设计文档和规范
2. 理解任务需求
3. 实现代码
4. 确保代码质量

#### Phase 4: SelfVerify (Multi-agent验证)
**并行执行**:
- Agent 1 (Sonnet): 需求符合性验证
- Agent 2 (Sonnet): 代码质量验证
- Agent 3 (Sonnet): 边界异常验证

#### Phase 5: Battle (Agent对抗验证)
**并行执行**:
- Battle 1: 挑战需求验证结果
- Battle 2: 挑战质量验证结果

#### Phase 6: Judge (Opus裁决)
**Agent**: Opus (架构师级别)
**输出**: 
- overall_score: 0-100
- can_complete: boolean
- critical_issues: []
- recommendations: []

```

  │

  ▼                                   ▼

  │
  ├─────────────────────────────────────────────────┐
  │                                                 │
  ▼                                                 ▼

│ 生成评估报告       │                        │ 生成遗留问题列表   │

  │                                                 │

  │       reportPath: reports/..TEST_EVAL.md         │       issuesPath: issues/.._ISSUES.md
  ▼                                                 ▼
┌───────────────────────┐                         │

```

### 详细说明

#### Phase 1: ParseTask (解析任务)
**输入**: `module|task`
**处理**: 分割字符串，提取模块名和任务描述

#### Phase 2: ReadDocs (读取文档)
**文件读取**:
- `docs/architecture/modules/{module}-design.md`
- `docs/testing/{MODULE}_TEST_SCENARIOS.md`

#### Phase 3: Generate (生成+评估)
**Agent**: Opus (一次性完成)
**任务**:
1. 生成完整测试用例列表（5步法）
2. 与现有用例比对
3. 评估质量

**输出JSON**:
```json
{
  "scenarios": {
    "total": 数量,
    "list": [{"id", "title", "given", "when", "then"}]
  },
  "comparison": {
    "new_unique": 数量,
    "existing_unique": 数量
  },
  "evaluation": {
    "score": 0-100,
    "grade": "A/B/C/D/F",
    "summary": "摘要"
  }
}
```

#### Phase 4: Report (报告生成)
**输出文件**:
1. `docs/reports/{MODULE}_TEST_EVAL.md` - 评估报告
2. `docs/issues/{MODULE}_ISSUES.md` - 遗留问题列表

## 9. 关键设计决策

### 为什么test-scenario-evaluation只用1个Opus调用？

**原因**:
1. **效率**: 8个phase + 10+agent调用太慢
2. **集成**: 将生成+比对+评估合并到一次Opus调用
3. **简化**: 不需要复杂的任务分配和循环

### 何时使用哪个workflow？

**使用 self-driven-task-execution 当**:
- ✅ 需要执行PRD任务
- ✅ 需要代码实现
- ✅ 需要多轮迭代

**使用 test-scenario-evaluation 当**:
- ✅ 需要测试用例生成
- ✅ 需要覆盖率评估
- ✅ 需要问题追踪
