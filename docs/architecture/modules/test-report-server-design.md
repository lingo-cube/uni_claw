## Executive Summary

The Test Report Server (`dashboards/test_report_server.py`) is a standalone HTTP server that provides real-time visualization and analysis of standardized test results generated by the module-test skill. It reads from the `test_results/` directory and serves both a web dashboard and REST API for test result aggregation, analysis, and triggering.

### Key Features

1. **Test Results Data Source** - Reads and caches `test_results/{module}_unit.json` files
2. **Test Results Analyzer** - Aggregates statistics, calculates pass rates, identifies trends
3. **Test Runner API** - HTTP endpoints for triggering test runs via the module-test skill
4. **Web Dashboard** - Real-time visualization of test results, failures, and coverage
5. **REST API** - JSON endpoints for programmatic access to test data

## Component Design

### 1. TestResultsDataSource Class

**Purpose**: Manages reading, caching, and validation of standardized test result JSON files.

**Location**: `dashboards/test_report_server.py` (inner class or top-level)

**Responsibilities**:
- Load `test_results/{module}_unit.json` files
- Validate JSON schema compliance
- Cache results with TTL for performance
- Watch for file changes (optional, for real-time updates)
- Extract module names from filenames

**Interface**:

```python
class TestResultsDataSource:
    """Data source for standardized test results."""

    def __init__(self, results_dir: Path, cache_ttl: int = 30):
        """
        Initialize the data source.

        Args:
            results_dir: Path to test_results directory
            cache_ttl: Cache time-to-live in seconds (default: 30)
        """
        self.results_dir = results_dir
        self.cache_ttl = cache_ttl
        self._cache: Dict[str, Tuple[dict, float]] = {}
        self._validator = TestResultValidator()

    def load_results(self, module: Optional[str] = None) -> Dict[str, Any]:
        """
        Load test results for a module or all modules.

        Args:
            module: Module name (e.g., "trace", "simulation")
                   If None, loads all modules

        Returns:
            Dict with module names as keys and result data as values

        Raises:
            FileNotFoundError: If results_dir doesn't exist
            ValueError: If JSON schema validation fails
        """

    def get_cached_data(self, module: Optional[str] = None) -> Dict[str, Any]:
        """
        Get cached results if available and fresh.

        Args:
            module: Module name (optional)

        Returns:
            Cached result data or None if cache expired
        """

    def invalidate_cache(self, module: Optional[str] = None):
        """
        Invalidate cache for a module or all modules.

        Args:
            module: Module name (optional)
        """

    def list_modules(self) -> List[str]:
        """
        List all available modules with test results.

        Returns:
            List of module names (e.g., ["trace", "simulation"])
        """

    def validate_schema(self, data: dict) -> bool:
        """
        Validate result data against schema.

        Args:
            data: Result data dictionary

        Returns:
            True if valid, False otherwise
        """
```

**Implementation Details**:

1. **File Discovery**:
   - Glob pattern: `test_results/*_unit.json`
   - Extract module name from filename: `"{module}_unit.json" -> module`

2. **Schema Validation**:
   - Required fields: `module`, `timestamp`, `summary`, `failures`
   - Summary fields: `total`, `passed`, `failed`, `error`, `skipped`
   - Data consistency: `total == passed + failed + error + skipped`

3. **Caching Strategy**:
   - In-memory dictionary with timestamps
   - TTL-based expiration (default 30 seconds)
   - Per-module cache keys

4. **Error Handling**:
   - Missing files → empty dict (not an error)
   - Invalid JSON → log warning, skip file
   - Schema violations → log warning, skip file

### 2. TestResultsAnalyzer Class

**Purpose**: Analyzes test results to generate insights, statistics, and trends.

**Location**: `dashboards/test_report_server.py` (inner class or top-level)

**Responsibilities**:
- Aggregate statistics across all modules
- Calculate pass rates and coverage metrics
- Identify failing tests and error patterns
- Detect trends (improving, degrading)
- Generate summary reports

**Interface**:

```python
class TestResultsAnalyzer:
    """Analyzer for test results data."""

    def __init__(self, data_source: TestResultsDataSource):
        """
        Initialize the analyzer.

        Args:
            data_source: Data source instance
        """
        self.data_source = data_source
        self._history: List[dict] = []  # For trend detection

    def aggregate_statistics(self) -> Dict[str, Any]:
        """
        Aggregate statistics across all modules.

        Returns:
            {
                "total_modules": int,
                "total_tests": int,
                "passed_tests": int,
                "failed_tests": int,
                "error_tests": int,
                "skipped_tests": int,
                "overall_pass_rate": float,
                "modules_with_failures": List[str],
                "coverage_summary": {
                    "modules_with_coverage": int,
                    "average_line_rate": float,
                    "average_branch_rate": float
                }
            }
        """

    def calculate_pass_rate(self, module: Optional[str] = None) -> float:
        """
        Calculate pass rate for a module or overall.

        Args:
            module: Module name (optional)

        Returns:
            Pass rate as float (0.0 - 1.0)
        """

    def identify_failing_tests(self) -> Dict[str, List[dict]]:
        """
        Identify all failing tests across modules.

        Returns:
            {
                "module_name": [
                    {"name": "test_name", "message": "...", "type": "failure"},
                    ...
                ],
                ...
            }
        """

    def detect_trends(self, window: int = 5) -> Dict[str, str]:
        """
        Detect trends in test results over time.

        Args:
            window: Number of historical data points to consider

        Returns:
            {
                "module_name": "improving" | "degrading" | "stable",
                ...
            }
        """

    def get_freshness_report(self) -> Dict[str, Any]:
        """
        Report data freshness for each module.

        Returns:
            {
                "fresh_modules": List[str],
                "stale_modules": List[str],
                "missing_modules": List[str],
                "oldest_timestamp": str,
                "newest_timestamp": str
            }
        """

    def generate_summary(self) -> Dict[str, Any]:
        """
        Generate a comprehensive summary report.

        Returns:
            Combined data from all analysis methods
        """
```

**Analysis Algorithms**:

1. **Pass Rate Calculation**:
   ```python
   pass_rate = total_passed / total_tests if total_tests > 0 else 0.0
   ```

2. **Trend Detection**:
   - Compare recent pass rates with historical baseline
   - "improving": pass_rate increased by >5%
   - "degrading": pass_rate decreased by >5%
   - "stable": change ≤5%

3. **Freshness Check**:
   - Current time - timestamp > 48 hours → stale
   - Missing file → missing

4. **Coverage Aggregation**:
   - Average line rate across modules with coverage
   - Average branch rate across modules with coverage

### 3. TestRunnerAPI Class

**Purpose**: Provides HTTP-triggerable test execution via the module-test skill.

**Location**: `dashboards/test_report_server.py` (inner class or top-level)

**Responsibilities**:
- Trigger test runs for specific modules
- Trigger test runs for all modules
- Track running test executions
- Cancel in-progress runs
- Return test run status and results

**Interface**:

```python
class TestRunnerAPI:
    """API for triggering and managing test runs."""

    def __init__(self, project_root: Path, test_runner_path: Path):
        """
        Initialize the test runner API.

        Args:
            project_root: Path to project root
            test_runner_path: Path to module-test/test_runner.py
        """
        self.project_root = project_root
        self.test_runner_path = test_runner_path
        self._active_runs: Dict[str, subprocess.Popen] = {}
        self._run_status: Dict[str, dict] = {}

    def run_module_tests(self, module: str) -> str:
        """
        Run tests for a specific module.

        Args:
            module: Module name

        Returns:
            Run ID for tracking

        Raises:
            ValueError: If module name is invalid
            RuntimeError: If test runner is not available
        """

    def run_all_tests(self) -> str:
        """
        Run tests for all available modules.

        Returns:
            Run ID for tracking
        """

    def cancel_run(self, run_id: str) -> bool:
        """
        Cancel an in-progress test run.

        Args:
            run_id: Run ID returned by run_module_tests()

        Returns:
            True if cancelled, False otherwise
        """

    def get_run_status(self, run_id: str) -> dict:
        """
        Get status of a test run.

        Args:
            run_id: Run ID

        Returns:
            {
                "run_id": str,
                "status": "running" | "completed" | "failed" | "cancelled",
                "start_time": str,
                "end_time": str,
                "modules": List[str],
                "results": dict  # Only available if completed
            }
        """

    def list_active_runs(self) -> List[dict]:
        """
        List all currently active test runs.

        Returns:
            List of run status dicts
        """
```

**Implementation Details**:

1. **Run ID Generation**:
   - Use ULID or UUID for unique run identifiers
   - Format: `"run_{ulid}"` for readability

2. **Process Management**:
   - Spawn subprocess: `python .claude/skills/module-test/test_runner.py {module}`
   - Store Popen objects in `_active_runs`
   - Monitor process status via polling

3. **Status Tracking**:
   - Update `_run_status` as process progresses
   - Parse stdout for test progress (optional)
   - Load final results from `test_results/{module}_unit.json`

4. **Cancellation**:
   - Use `process.terminate()` or `process.kill()`
   - Clean up `_active_runs` entry

### 4. HTTP Request Handler

**Purpose**: HTTP server that handles API requests and serves the dashboard.

**Location**: `dashboards/test_report_server.py`

**Base Class**: `http.server.SimpleHTTPRequestHandler`

**Request Routing**:

```python
class TestReportRequestHandler(SimpleHTTPRequestHandler):
    """HTTP request handler for test report server."""

    # Class variables set by server setup
    data_source: TestResultsDataSource = None
    analyzer: TestResultsAnalyzer = None
    test_runner: TestRunnerAPI = None

    def do_GET(self):
        """Handle GET requests."""
        if self.path == "/api/results":
            self._serve_results()
        elif self.path == "/api/aggregate":
            self._serve_aggregate()
        elif self.path == "/api/failures":
            self._serve_failures()
        elif self.path == "/api/freshness":
            self._serve_freshness()
        elif self.path == "/api/trends":
            self._serve_trends()
        elif self.path == "/api/runs":
            self._serve_runs()
        elif self.path.startswith("/api/runs/"):
            run_id = self.path[11:]  # Strip "/api/runs/"
            self._serve_run_status(run_id)
        elif self.path == "/" or self.path == "":
            self._serve_dashboard()
        else:
            super().do_GET()

            run_id = self.path[13:]  # Strip "/api/cancel/"

            self._serve_error(404, "Not found")
```

## Configuration

### CLI Arguments

```bash
python dashboards/test_report_server.py [--port PORT] [--host HOST] [--results-dir DIR]
```

| Argument | Default | Description |
|----------|---------|-------------|
| `--port` | 8003 | HTTP server port |
| `--host` | 127.0.0.1 | Host to bind to |
| `--results-dir` | test_results | Test results directory |
| `--cache-ttl` | 30 | Cache TTL in seconds |

### Environment Variables

| Variable | Description |
|----------|-------------|
| `TEST_REPORT_PORT` | Override default port |
| `TEST_REPORT_HOST` | Override default host |
| `TEST_REPORT_RESULTS_DIR` | Override results directory |

## Error Handling

### Data Source Errors

| Error | Handling |
|-------|----------|
| Directory not found | Return empty results, log warning |
| Invalid JSON | Skip file, log warning |
| Schema validation fail | Skip file, log warning |
| Permission denied | Return error response |

### Test Runner Errors

| Error | Handling |
|-------|----------|
| Module not found | Return 400 error |
| Test runner not found | Return 500 error |
| Process spawn failure | Return 500 error |
| Run not found | Return 404 error |

### API Errors

All errors return JSON with `error` field:

```json
{
  "error": "Error message",
  "code": "ERROR_CODE",
  "details": {...}
}
```

## Security Considerations

1. **Local Development Only**:
   - Default to 127.0.0.1 (localhost)
   - No authentication required
   - Explicit `--host 0.0.0.0` for network access

   - Validate module names (alphanumeric + underscore)
   - Sanitize run IDs
   - Validate query parameters

3. **Process Isolation**:
   - Test runs in subprocesses
   - Resource limits (optional)
   - Timeout on hanging runs

4. **CORS**:
   - Allow origin for local development
   - Configurable for production

## Performance Considerations

1. **Caching**:
   - In-memory cache with 30s TTL
   - Reduces file I/O
   - Cache invalidation on test runs

2. **Lazy Loading**:
   - Only load files when requested
   - Pagination for large failure lists (future)

3. **Background Processing**:
   - Test runs in subprocess
   - Non-blocking API calls

4. **Scalability**:
   - Designed for <1000 test results
   - For larger scale, consider database backend
