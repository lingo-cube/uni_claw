## 1. Buyer and exact claim boundary

**Buyer:** DSH-side consumption of the UniClaw Profile Core with Codex-identical Profile / WorkItem / routing semantics — the concrete DSH adapter left unspecified by `.ai/workflows/uniflow-coding-workflow.md` §10「DSH 边界」 (per proposal.md「Buyer」).

This receipt claims only that:

1. a read-only DSH Profile Source / Loader / Adapter exists (`tools/dsh_profile_adapter.py` + `.dsh/profile-adapter/profile-source.yaml`) that loads the upstream Profile via `profile_source` config (root / schema_version / source_revision / validation_command / mode), executes `validation_command` on activation, refuses workflow activation on any schema_version / source_revision mismatch or validation failure, and never writes under the Profile Source path (spec `Profile Source 校验后才可激活工作流`; proposal.md What changes 1–2; design.md architecture position);
2. Profile composition delegates every semantic decision to `tools/agent_profile_validator.py` as the single upstream authority (`compose_profile`, `validate_work_item`, `validate_work_result`, `validate_change_set`, `build_context_manifest`, `resolve_module_for_path`, `profile_context_key`, `rule_digest`) — DSH never re-implements upstream merge semantics, and rule conflicts return `LeaderDecisionRequired` carrying the conflicting rule ID and source references, never silent override (spec `Profile 合并与冲突语义与上游一致`; proposal.md What changes 1; design.md Decision 1);
3. model bindings live only in the DSH-side `model_bindings` config: `decision_frontier.primary` = zai/glm-5.2/high, `decision_frontier.fallback` = opencode-go/glm-5.2/high, `implementation_efficient` & `semantic_read` = opencode-go/deepseek-v4-flash, `tool_only` = model none with zero model calls; provider names follow the DSH Host's actually registered route (this deployment registers `opencode-go`; `opencode` is not registered and dispatch fails closed with `NO_ADAPTER`); primary and fallback never hold Leader authority simultaneously; fallback triggers only on the allow-listed platform reasons (provider_unavailable, connection_failure, timeout, platform_tool_failure, structured_output_repeated_failure) and restores the latest LeaderCheckpoint on takeover; business failures never trigger fallback; changing model config never changes RoleProfile permissions (spec `模型绑定与 Profile 解耦且 Leader 权威唯一`; proposal.md What changes 2; design.md Decisions 4, 14);
4. WorkItem dispatch is unicast with exactly one scalar `worker_owner`; fanout of the same WorkItem is rejected; Workers never create SubAgents or re-delegate; concurrent cross-WorkItem writes never overwrite the same file; dependent WorkItems schedule in order; write-heavy defaults to serial (spec `WorkItem 单播与 Worker 边界`);
5. ModuleContext auto-loads on WorkItem receipt (module-worker RoleProfile + current ExecutionProfile + specified ModuleProfile + validator `context` manifest with effective AGENTS / entrypoints / contracts / test gates / ProfileContextKey) and is cached by the upstream `profile_context_key` semantics, with invalidation on any profile version / RuleDigest / source revision / ModuleProfile / ModelBinding change or Worker block / protocol violation; the DSH-side store is the authoritative ModuleContext state (`.dsh/profile-adapter/state/`), the model session is cache only (spec `ModuleContext 自动加载与缓存失效`; design.md Decision 5);
6. WorkResult acceptance runs the ordered gate (WorkResult Schema → Profile version → base revision → Worker Owner → actual modified files → write scope → local rules → invariant → forbidden → tests & evidence → scenario gate → Accept/Reject); Worker natural-language conclusions never replace diff/test evidence; only an accepted `module_context_delta` updates the DSH ModuleContext (spec `WorkResult 接收门与 ModuleContext Delta`; design.md Decision 8);
7. LeaderCheckpoint stores only references and decision summaries (frozen decisions, invariants, contracts, completed/pending/blocked work, module_context_refs, evidence_refs, active_leader_provider) — never full reasoning or full Worker transcripts — and the event log is restricted to the 12 spec events (`profile.source.validated`, `profile.loaded`, `profile.conflict`, `workflow.route.selected`, `work_item.dispatched`, `worker.context.loaded`, `worker.completed`, `worker.blocked`, `work_result.accepted`, `work_result.rejected`, `leader.fallback.started`, `checkpoint.updated`) (spec `LeaderCheckpoint 与最小事件`; design.md Decisions 6, 7);
8. DSH runtime fields (protocol_version / session_id / run_id / correlation_id / profile_version / work_item) exist only in the outer `dsh_work_envelope`; unwrap returns a deep-equal WorkItem that still passes upstream `validate_work_item` unsullied (spec `DSH Work Envelope 不改变通用语义`; design.md Decision 3);
9. routing decisions match `.ai/workflows/uniflow-coding-workflow.md` §7: deterministic → tool-only (no model call), single-module atomic → module-worker, test writing → test-author, verification → verifier, semantic analysis → semantic-analyzer, public interface / lifecycle / Invariant / strongly-coupled cross-module → coding-leader without early dispatch (spec `路由策略与 tool-only 不调用模型`);
10. ExecutionProfile write-boundary permissions are decided entirely by upstream `validate_work_item` (development may write owned+test paths; test-authoring only test paths; verification / semantic-analysis no source write scope) and DSH never relaxes them (spec `ExecutionProfile 权限门由上游裁决`);
11. `dispatch_work_item()` is the sole legal dispatch entry; inputs must be JSON objects conforming to `.ai/schemas/work-item.schema.json` — Markdown headings, natural-language task text, missing required fields, or non-object `semantic_brief` are rejected (`WorkItemRequired`) — and pre-dispatch checks cover Schema, Profile, single `worker_owner`, `scope.write`, `leader_decisions_frozen=true`, `unresolved_architecture=[]`, and ExecutionProfile/task-shape consistency; `tool-only` WorkItems satisfy no-Subagent, model=none, no source/test write scope, no semantic judgment, failing closed on any violation (spec `强制 WorkItem 派发门`; design.md Decision 9);
12. DispatchGate resolves ExecutionProfile → binding role (`development` / `test-authoring` / `verification` → `implementation_efficient`; `semantic-analysis` → `semantic_read`; `tool-only` → `tool_only`, model none) per `profile-source.yaml` `model_bindings`, writing runtime metadata (binding role, provider, model, reasoning, profile version, binding config revision/digest, work_item id, worker_owner) into `dsh_work_envelope.model_binding` — never into the generic WorkItem — with actual values from the DSH binding config, not hardcoded in RoleProfile / ExecutionProfile / WorkItem / worker prompts (spec `DispatchGate 解析 ModelBinding 进入 DSH Envelope`; design.md Decision 10);
13. the Host dispatch seam (`DshHostClient`) reads provider/model/reasoning explicitly from the verified Envelope into Subagent creation, never session-default / auto / worker self-reported models; an unsupported requested binding throws `RoutingCapabilityRequired` (code `ROUTING_CAPABILITY_LIMIT`) before any file modification or dispatch record; `tool-only` never goes through the Host seam; where no controllable Host seam exists or the Host cannot produce model receipts, that is reported honestly — no simulated guarantee (spec `Host 派发与能力 fail-closed`; design.md Decision 11);
14. the Host generates an operational receipt after Subagent start (session/subagent id, work_item id, worker_owner, actual provider/model/reasoning, binding config revision/digest, started_at) that model-text self-description never substitutes for; receipts enter DSH run metadata / event log; a pre-execution receipt check precedes Worker file writes, and WorkResultGate re-verifies requested-vs-actual binding, work_item id, worker_owner, and profile/binding revision — missing or mismatched receipts cause result rejection, no ModuleContext Delta, `model_receipt_missing` / `model_binding_mismatch` recording, and `ROUTING_CAPABILITY_LIMIT` with no silent fallback (spec `实际模型回执与 WorkResultGate 核对`; design.md Decisions 12, 13);
15. UniFlow startup records the Host-provided Leader receipt and asserts the leader primary binding zai/glm-5.2/high (`assert_leader_primary`); a mismatch fails closed without silent downgrade; Leader fallback accepts only the allow-listed platform-level reasons, revokes the predecessor's `leader_authority`, grants unique authority to the new endpoint, restores the latest LeaderCheckpoint, and records the actual Host receipt (spec `Leader 绑定与唯一 authority`; design.md Decision 14).

No claim is made for: a second WorkItem/WorkResult schema; any edit to `.ai/profiles/`, `.ai/schemas/`, or `.ai/model-routing.yaml`; a new Agent Runtime; Data Plane / Fact Store / Event Sourcing; model IDs inside generic profiles; or open-ended fanout (non-goals per proposal.md「Non-goals」).

## 3. Scenario receipts and falsifiers

The change files record no explicit falsifier section (no `evidence/` directory; design.md contains no falsifier section); rejection/negative requirements are defined in `specs/dsh-uniflow-profile-adapter/spec.md`:

- **Profile Source 只读 (negative):** DSH MUST NOT write any file under the Profile Source path; the scenario asserts Profile Source root file content and mtime remain unchanged under any adapter operation; activation MUST be refused on schema_version / source_revision mismatch or validation failure.
- **合并语义不重实现 (negative):** DSH MUST NOT re-implement `compose_profile` / `merge_mapping_strict`; rule conflicts MUST NOT be silently overridden — `LeaderDecisionRequired` with rule ID and source references is mandatory.
- **Leader authority 唯一 / fallback 限制 (fail-closed):** primary and fallback MUST NOT simultaneously hold `leader_authority: true`; business failures (test failure, decision error, rule conflict, goal change, unreasonable split) MUST NOT trigger fallback; modifying model config MUST NOT change RoleProfile permissions; tool_only MUST NOT call a model.
- **Worker 边界 (negative):** fanout of a WorkItem MUST be rejected; Worker MUST NOT create a SubAgent or re-delegate; concurrent cross-WorkItem writes MUST NOT overwrite the same file.
- **缓存失效 (negative):** any profile version / RuleDigest / source revision / ModuleProfile / ModelBinding change or Worker block / protocol violation MUST invalidate the ProfileContextKey cache.
- **Delta 仅接受后生效 (negative):** Worker natural-language conclusions MUST NOT replace diff and test evidence; an unaccepted `module_context_delta` MUST NOT take effect.
- **Checkpoint/事件最小化 (negative):** LeaderCheckpoint MUST NOT store full reasoning or full Worker transcripts; events MUST be restricted to the 12 spec events.
- **Envelope 不污染 (negative):** `dsh_work_envelope` unwrap MUST yield a WorkItem deep-equal to the original that still passes upstream `validate_work_item`.
- **tool-only 零模型 (negative):** tool-only routing MUST return model none with a zero model-call count; strongly-coupled cross-module with unfrozen contract MUST return coding-leader without generating a WorkItem.
- **权限不放宽 (negative):** DSH MUST NOT relax the upstream-decided write boundaries (test-authoring no production code; verification/semantic-analysis no source write scope).
- **派发门 fail-closed (negative):** Markdown headings / natural-language task text / missing required fields / non-object `semantic_brief` MUST be rejected with `WorkItemRequired` and no dispatch record; tool-only declaring a source or test write scope MUST fail closed (no Subagent, zero model calls).
- **Binding 不硬编码 (negative):** binding values MUST come from the DSH binding config, not hardcoded in RoleProfile / ExecutionProfile / WorkItem / worker prompts; binding fields MUST NOT enter the generic WorkItem.
- **Host 能力 fail-closed (negative):** session-default / auto / worker self-reported models MUST NOT substitute for the requested binding; unsupported capability MUST raise `ROUTING_CAPABILITY_LIMIT` before any file modification or dispatch record.
- **回执不可伪造 (negative):** model-text self-description MUST NOT count as a receipt; missing or mismatched receipt MUST reject the result, withhold the Delta, record `model_receipt_missing` / `model_binding_mismatch`, and return `ROUTING_CAPABILITY_LIMIT` without silent fallback.
- **Leader fail-closed (negative):** a Host receipt inconsistent with the leader primary MUST be judged `model_binding_mismatch` with no silent downgrade; business failures MUST NOT trigger Leader fallback.

## 5. Final conclusion

**GRADUATED.** The DSH UniFlow Profile Adapter — read-only Profile Source with activation validation, upstream-delegated composition, decoupled model binding with unique Leader authority, unicast dispatch under a mandatory DispatchGate, ModuleContext caching, the ordered WorkResult gate, minimal checkpoint/events, envelope isolation, Host-receipt verification, and Leader binding — is human-authorized (proposal.md「Human Gate」) and bounded by the evidence recorded in the change's own files: all 10 slices and all 10 apply-increment tasks complete in tasks.md, the 30-case suite designed 1:1 to the spec scenarios in design.md, and the recorded validation commands; the change's files record no build/test-run numeric evidence.
