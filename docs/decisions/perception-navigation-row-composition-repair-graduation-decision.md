## 1. Buyer and exact claim boundary

**Buyer:** per proposal.md, the Runtime normalization and Settings campaign validation-buyer consumers of perception fusion output that were blocked by duplicate navigation signatures and description-only navigation sources — one deterministic, provenance-preserving navigation-row candidate per provable physical row.

This receipt claims only that:

1. widget-aligned title, description, and overlapping detector boxes belonging to one row anchor compose into exactly one logical navigation-row candidate with one deterministic primary title/bounds, and the contributing raw YOLO/OCR identifiers are preserved as provenance (proposal.md What Changes; specs capability Requirements "One logical navigation candidate per provable physical row" and "Composition preserves evidence provenance");
2. a row description is no longer emitted as an independent actionable `menu_item`, and an overlapping same-text primary visual box is classified `NonInteractive` only when exactly one unique primary `menu_item` proves the same row (proposal.md; evidence/IMPLEMENTATION-RESULT.md "Implemented and Retained");
3. composition keys on unique row anchor, never on text equality, so spatially distinct rows — including repeated labels and tightly adjacent rows — stay distinct (design.md Decision 1; specs capability Requirement "Distinct rows are not collapsed");
4. ambiguous anchor assignment or ambiguous primary-title choice never promotes text, preserving the raw evidence non-actionable (specs capability Requirement "Ambiguous row membership fails closed"; design.md Decisions 1 and 6);
5. uniform vertical-list inference is frame-local and gated: it activates only from at least four confirmed current-frame rows with a stable title column and adaptive cadence; only complete, uniquely bracketed one-to-three-slot gaps are recovered; inferred roles never exceed confirmed anchors and never exceed 50 percent of the final row inventory (30 percent continuation cap); trailing controls, ambiguous/incomplete slots, irregular layouts, and proven clipped edge rows fail closed; continuation is current-frame bounded (design.md Decisions 5–7; specs capability Requirements "Uniform-list inference is frame-local and gated", "Only complete bounded bracket gaps may be recovered", "Proven partial edge rows do not enter inventory", "Continuation is current-frame bounded");
6. processing remains perception-only deterministic: exactly the existing single YOLO/OCR/fusion pass, no LLM/VLM, no second screenshot or model pass, no Memory; the raw `yolo`/`ocr` arrays remain unchanged (proposal.md What Changes; design.md Constraints/Decision 4; specs capability Requirement "Perception-only deterministic processing");
7. Runtime authority is unchanged: exact ordered-overlap normalization and fail-closed rules continue to apply, and with explicit primary Vision source metadata, auxiliary-only rows are excluded from completeness identity and campaign inventory/branches; Agent/FSM/Traversal/GoalEvidence/ExplorationLedger/completion authority is untouched (proposal.md; design.md Decision 8; specs capability Requirement "Runtime authority remains unchanged"; evidence/IMPLEMENTATION-RESULT.md AuthorityDelta = `NONE`).

No claim is made for: IR-G0 closure or Phase 2.6A unblocking — the change's own files record IR-G0 as NOT closed and Phase 2.6A still blocked (evidence/HUMAN-GATE.md, evidence/IMPLEMENTATION-RESULT.md); canonical perception deployment promotion — `NOT_AUTHORIZED_NOT_PERFORMED` (evidence/IMPLEMENTATION-RESULT.md); the three-anchor activation / 2/3 inference-cap relaxation — `REVERTED_UNSAFE` (evidence/HUMAN-GATE.md, evidence/IMPLEMENTATION-RESULT.md); YOLO retraining or a new model/relation-head deployment; general document-layout understanding or semantic classification; Runtime normalization tolerance, fuzzy identity, or auxiliary-defined identity; toggle/local-control redesign, VLM fallback, or Memory; XML/UI-hierarchy dependence, content-meaning rules, variable-height/card/grid layout inference, or cross-frame state (design.md Non-Goals).

## 3. Scenario receipts and falsifiers

| Falsifier | Result |
|---|---|
| Global same-text deduplication could repair the duplicate navigation signatures | **Falsified (evidence/BASELINE.md)**: one physical row is represented by title, description, and overlapping detector boxes each promoted at the fusion boundary — shared OCR occurrences with separate YOLO boxes (`Network & internet` ×3 on `det_12`/`det_22`/`det_17`; `Connected devices` ×3 on `det_18`/`det_14`/`det_25`; `Storage` ×2 on `det_4`/`det_7`; descriptions such as `Recent apps, default apps` promoted as `menu_item`); composition must therefore be anchor-based, never text-based (design.md Decision 1). |
| Three YOLO row anchors are sufficient to activate row grouping (2/3 inference cap) | **Falsified (evidence/IMPLEMENTATION-RESULT.md, evidence/HUMAN-GATE.md)**: candidate `v1n` emitted the subtitle `Volume, vibration, Do Not Disturb` as a `menu_item` while omitting real titles such as `Display`, `Wallpaper`, and `Accessibility`; a real-emulator false positive, marked `REVERTED_UNSAFE`, with negative side-effect evidence frozen at `evidence/after/candidate-v1n-campaign-round1-frames.json`; the retained operator again requires four confirmed anchors and never infers more roles than confirmed rows. |
| Expanding primary bounds to the union of all row components | **Not retained (design.md Decision 2)**: would enlarge tap geometry and overlap adjacent controls without identity value; the primary candidate keeps its original title bounds so Runtime grounding targets visible title text. |
| A missing anchor for a neighboring row could make its description appear compatible with another anchor | **Not falsified (mitigation in design.md Risks)**: unique nearest-anchor assignment plus bounded horizontal/vertical subordinate geometry are required; otherwise the raw evidence stays non-actionable and is not composed. |
| Primary selection could choose a combined box rather than the title box | **Not falsified (mitigation in design.md Risks)**: candidates are ordered by upper edge first, then tighter height, then confidence, with reality fixtures for title+description rows. |
| An unseen layout has fewer than four reliable row anchors | **Not falsified (confirms the boundary)**: the operator stays inactive; a tested three-anchor relaxation produced description-as-menu false positives and was reverted (design.md Risks; evidence/IMPLEMENTATION-RESULT.md "Reverted Experiment"). |
| A static note between navigation rows could resemble a missing row | **Not falsified (mitigation in design.md Risks)**: V1 requires a proven uniform navigation segment, exact one-slot bracketing, title-column fit, unique title, no trailing control, and a bounded inferred-row ratio; any failed predicate leaves the text non-actionable. |
| Variable-height lists or section breaks could produce false cadence | **Not falsified (mitigation in design.md Risks)**: stable direct-gap support is required and gaps that are not one or two pitches are rejected; no extrapolation across section/card/grid layouts. |
| A short but complete edge title could be demoted | **Not falsified (mitigation in design.md Risks)**: edge demotion requires an abnormal title-height ratio against at least four complete peer rows; normal-height first/last rows remain actionable. |
| Spec negative requirements as test-first falsifiers | **Covered (tasks.md 2.2 and 6.3)**: title-only rows, repeated labels on distinct anchors, tightly adjacent rows, ambiguous anchor assignment, provenance union, bracketed recovery, description grouping, local controls, irregular layouts, consecutive gaps, ambiguity, inference cap, and edge rows — results recorded as the focused suites `27 passed, 3 subtests passed` and `28/28` PASS in tasks.md "Validation Receipt" and evidence/IMPLEMENTATION-RESULT.md "Validation". |

## 4. Deferred scope

The following remain outside this graduation and require separate authorization:

- IR-G0 closure and Phase 2.6A unblocking: IR-G0 is not closed and Phase 2.6B was not entered; closure requires a separately authorized perception direction — detector retraining for stable navigation-row anchors, a dedicated visual row-grouping model/relation head under a new OpenSpec, or acceptance of the current fail-closed boundary (evidence/HUMAN-GATE.md "Boundary"; evidence/IMPLEMENTATION-RESULT.md "Decision"/"Stop Condition").
- Canonical perception deployment promotion: `NOT_AUTHORIZED_NOT_PERFORMED` (evidence/IMPLEMENTATION-RESULT.md "Deployment Receipts").
- YOLO retraining, threshold tuning, or a new model deployment; a dedicated visual row-grouping model / relation head whose output is checked by the deterministic operator (would be a future Human-gated ArchitectureDelta under a separate OpenSpec) — design.md Non-Goals; evidence/IMPLEMENTATION-RESULT.md "ArchitectureDelta"/"Reality Result".
- General document-layout understanding or semantic classification — design.md Non-Goals.
- Runtime normalization tolerance, fuzzy identity, or auxiliary-defined identity; using XML as canonical identity is explicitly not recommended — design.md Non-Goals; evidence/HUMAN-GATE.md "Boundary".
- Toggle/local-control redesign, VLM fallback, or Memory — design.md Non-Goals.
- XML/UI-hierarchy dependence, content-meaning rules, variable-height/card/grid layout inference, three-anchor activation, or cross-frame state — design.md Non-Goals.
- Residual perception risk: primary row-anchor recall remains viewport-sensitive, OCR/title-role instability still breaks exact ordered overlap, and geometry-only low-anchor recovery creates false menus — evidence/IMPLEMENTATION-RESULT.md "Remaining Risk".

## 5. Final conclusion

**GRADUATED.** The change's deterministic, provenance-preserving same-frame row composition (unique-anchor grouping, primary-title selection, immutable raw evidence with unioned provenance) and its gated, fail-closed frame-local uniform-list grouping operator were implemented, retained, and validated with the recorded focused/perception/.NET suites, live Settings baseline and real-emulator campaign evidence, and consistency/OpenSpec checks. This receipt does not claim IR-G0 closure, canonical deployment promotion, or any change to Runtime/Agent/FSM/Traversal authority, which the change's own files record as open or unchanged; archival of the change is performed on 2026-08-30 as a separate lifecycle operation in this batch.
