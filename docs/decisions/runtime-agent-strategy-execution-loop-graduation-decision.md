## 1. Buyer and exact claim boundary

**Buyer:** per proposal.md — a bounded Strategy execution loop that connects the accepted Strategy Contract (`uniagent-runtimeagent-strategy-contract`) with the Agent-owned pre-terminal checkpoint (`runtime-agent-pre-terminal-cycle-contract`), so RuntimeAgent can maintain a transactional, evidence-driven execution hypothesis throughout the same Agent-owned Run without creating a second execution controller or moving action, lifecycle, recovery, or completion authority out of Agent.

This receipt claims only that:

1. one run-scoped `StrategyExecutionReasoningSession` binds one accepted `RuntimeExecutionIntent` to RuntimeAgent-owned hypothesis and reasoning revision history for one Agent-owned Run, created after admission and Agent RunId assignment but before the first eligible checkpoint, and never starting, restarting, extending, or controlling the Run (proposal.md "What Changes"; design.md Decision 3; specs Requirement "One Accepted Strategy SHALL Create One Run-Scoped Reasoning Session");
2. an immutable, typed, scenario-neutral `StrategyExecutionEvidenceView` projects only accepted evidence and correlation facts needed for bounded reconciliation — no mutable World internals, free-form scenario strings, actions, selectors, routes, concrete targets, branch ordering, completion flags, GoalEvidence mutation, FSM commands, lifecycle callbacks, or executable delegates (proposal.md "What Changes"; design.md Decision 4; specs Requirement "Strategy Execution Evidence SHALL Be Immutable, Typed, and Scenario Neutral");
3. RuntimeAgent evaluates each eligible Agent-owned checkpoint using internal `ExecutionHypothesis`, `RuntimeDecision`, and `HypothesisAdaptation` records and returns only the existing passive `PreTerminalContinuationProposal` dispositions (`ContinuationSupported` / `ContinuationSupportedAfterRevision` / `ContinuationNotSupported`), with no lifecycle, recovery, continuation, or completion commands exposed (proposal.md "What Changes"; design.md Decision 5; specs Requirement "Runtime Decision and Adaptation SHALL Remain Internal");
4. proposed reasoning revision N+1 remains uncommitted until Agent validates freshness, correlation, parentage, and authority through the existing compare-and-accept seam; rejection discards N+1 and leaves accepted reasoning history unchanged (proposal.md "What Changes"; design.md Decision 6; specs Requirement "Reasoning Revision SHALL Commit Only Through Agent Acceptance");
5. exactly one reasoning mode (`PreTerminalStrategy` or the existing non-pre-terminal behavior) is selected per Run at admission and is immutable for the Run, so the same accepted evidence cannot be reconciled through both pre-terminal and post-run paths (proposal.md "What Changes"; design.md Decision 10; specs Requirement "One Run SHALL Use One Reasoning Mode");
6. runtime reasoning convergence is separated from Agent-owned execution completion — convergence never produces `Completed`, `GoalSatisfied`, `Terminal`, a completion flag, or an equivalent terminal assertion (proposal.md "What Changes"; design.md Decision 9; specs Requirement "Reasoning Convergence SHALL Not Imply Execution Completion");
7. the existing generic discovery and traversal engine is preserved — this capability supplies no concrete target, route, action, branch ordering, or DFS policy, and the capability consumes only the bounded evidence view with no direct dependency on mutable World/DFS internals (proposal.md "What Changes"; design.md Decision 8; specs Requirement "Evidence Projection SHALL Isolate RuntimeAgent From World Internals");
8. authority is preserved mechanically: UniAgent owns Strategy generation and selection; Agent owns RunState, checkpoint acceptance, action authorization, recovery, GoalEvidence, and terminal outcome; FSM owns lifecycle transitions; Traversal owns concrete execution; Environment owns observation acquisition (proposal.md "Impact"; design.md Decisions 1, 11; specs Requirement "Frozen Authority SHALL Be Mechanically Preserved").

No claim is made for: Strategy replacement during an active Run; user-intent interpretation, Strategy generation, or user-level Plan inside RuntimeAgent; action, target, route, selector, DFS ordering, recovery command, lifecycle command, completion assertion, or execution callback in reasoning contracts; semantic capability protocols, external knowledge packages, scenario migration, or external semantic dependencies; DFS or Traversal redesign, recovery redesign, or Environment redesign; new Run, successor Run, outer loop, or Multi-Run orchestration; or external wire operation or Strategy payload changes (proposal.md "What Changes" exclusions and "Impact"; design.md "Non-Goals").

## 3. Scenario receipts and falsifiers

The change's files record no explicit falsifier section and contain no `evidence/` directory (verified: the change contains only `.openspec.yaml`, proposal.md, design.md, tasks.md, and specs/runtime-agent-strategy-execution-loop/spec.md). Rejection/negative requirements are defined in `specs/runtime-agent-strategy-execution-loop/spec.md`:

- **Session cannot become an execution controller** — when the reasoning session evaluates evidence or records an accepted revision, it invokes no action, Traversal operation, FSM transition, recovery path, Run start, or terminal operation (Requirement: One Accepted Strategy SHALL Create One Run-Scoped Reasoning Session, Scenario: Session cannot become an execution controller).
- **Mutable or authority-bearing projection fails closed** — a proposed evidence view exposing mutable Runtime state or an executable, lifecycle-bearing, target-bearing, or completion-bearing field is rejected before RuntimeAgent reasoning can use it (Requirement: Strategy Execution Evidence SHALL Be Immutable, Typed, and Scenario Neutral, Scenario: Mutable or authority-bearing projection fails closed).
- **Useful revision would replace Strategy** — the reasoning session does not replace the Strategy and returns no authority-expanding fallback (Requirement: Strategy and Execution Hypothesis SHALL Remain Distinct, Scenario: Useful revision would replace Strategy).
- **Internal records never become commands** — `RuntimeDecision` and `HypothesisAdaptation` MUST NOT be returned to Agent as lifecycle, recovery, continuation, or completion commands (Requirement: Runtime Decision and Adaptation SHALL Remain Internal).
- **Stale evidence view is rejected** — any accepted-observation, belief, structural-progress, trace, intent, session, or reasoning-parent correlation difference at validation time causes Agent to reject the proposal, discard N+1, and authorize zero action from it (Requirement: Reasoning Revision SHALL Commit Only Through Agent Acceptance, Scenario: Stale evidence view is rejected).
- **Terminal Run cannot reopen reasoning** — the sealed session accepts no further checkpoint or revision and cannot reopen, extend, replace, or create a Run (Requirement: Strategy Reasoning SHALL Be a Participant Inside One Agent Run, Scenario: Run is terminal).
- **One mode prevents dual-ledger interpretation** — a Run using pre-terminal strategy reasoning MUST NOT perform post-run reconciliation or adaptation over the same evidence; terminal finalization MUST NOT create another decision, adaptation, continuation proposal, or accepted revision (Requirement: One Run SHALL Use One Reasoning Mode).
- **No hidden external dependency** — the strategy execution loop MUST NOT require or invoke an external semantic capability (Requirement: Abstract Exploration SHALL Reuse Existing Execution Ownership).
- **Convergence is not completion** — reasoning convergence MUST NOT produce `Completed`, `GoalSatisfied`, `Terminal`, a completion flag, or an equivalent terminal assertion; coverage evidence alone does not complete the Run and only Agent may establish completion from GoalEvidence (Requirement: Reasoning Convergence SHALL Not Imply Execution Completion, Scenario: Coverage evidence appears sufficient).
- **Frozen authority is mechanical** — no dependency path may permit RuntimeAgent to generate an action, select a concrete target, define a route, order DFS branches, invoke Traversal, issue an FSM command, mutate RunState, decide recovery, mutate or satisfy GoalEvidence, replace Strategy, start another Run, or orchestrate multiple Runs (Requirement: Frozen Authority SHALL Be Mechanically Preserved, Scenario: Authority surface is inspected).

Additionally, design.md "Risks / Trade-offs" records design-time risk records with mitigations (evidence projection duplicating World, a hidden controller, the passive proposal being treated as authorization, tentative-history leakage, pre-terminal/post-run divergence, indirect branch priorities, coverage as shadow completion, external enrichment as hidden dependency) — these are recorded risk mitigations, not falsifier results; no falsifier section with results exists in the change files.

## 4. Deferred scope

The following remain outside this graduation per proposal.md "What Changes" exclusions and design.md "Non-Goals" and require separate authorization:

- Strategy replacement during an active Run (no mid-Run Strategy alteration).
- User-intent interpretation, Strategy generation, or user-level Plan inside RuntimeAgent.
- Action, target, route, selector, DFS ordering, recovery command, lifecycle command, completion assertion, or execution callback in reasoning contracts.
- New traversal algorithm, DFS rewrite, Traversal rewrite, recovery redesign, or Environment redesign.
- Semantic capability protocol, external knowledge package, scenario migration, or external semantic dependency; any optional evidence enrichment remains an upstream, separately-scoped concern.
- New Run, successor Run, outer loop, or Multi-Run orchestration.
- External wire operation or Strategy payload change.

## 5. Final conclusion

**GRADUATED.** The bounded claim — one run-scoped Strategy reasoning session and immutable, scenario-neutral evidence projection participating transactionally in the existing Agent-owned Run through the existing passive pre-terminal proposals, with one reasoning mode per Run, frozen authority, and convergence separated from completion — is human-authorized on the evidence recorded in the change's own files (tasks.md: build 0 warnings / 0 errors; loop contract tests 19/19; combined Strategy and pre-terminal tests 71/71; deterministic Runtime 1849/1849 then 1971/1971 plus Semantic 32/32; guards, consistency C1–C12, `git diff --check`, and strict OpenSpec validation all PASS). Archival is performed on 2026-08-30 as a separate lifecycle operation in this batch.
