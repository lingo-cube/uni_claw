# wf-apply 详细流程文档

## 概述

wf-apply 是一个工作流驱动的任务执行系统，结合 OpenSpec 和智能模型路由，实现自动化任务执行。

## 核心架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          wf-apply 架构                                    │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  ┌─────────────┐    ┌──────────────┐    ┌─────────────────────────┐   │
│  │   Skill     │───▶│   Workflow   │───▶│   Multi-Agent System    │   │
│  │  (wf-apply) │    │  (调度器)     │    │   (执行与验证)          │   │
│  └─────────────┘    └──────────────┘    └─────────────────────────┘   │
│                             │                       │                  │
│                             ▼                       ▼                  │
│                      ┌──────────────┐    ┌─────────────────────────┐   │
│                      │   OpenSpec   │    │   Haiku / Opus /       │   │
│                      │   (任务源)   │    │   Sonnet (模型池)       │   │
│                      └──────────────┘    └─────────────────────────┘   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 详细流程

### 阶段 1：变更选择与验证

#### 1.1 接收输入
```
输入参数：
- change_name (可选): 变更名称
- 从上下文推断：如果未提供，从对话历史中推断
```

#### 1.2 变更选择逻辑
```
if change_name 为空:
    运行: openspec list --json
    获取活跃变更列表
    
    if 只有一个活跃变更:
        自动选择该变更
    elif 有多个活跃变更:
        使用 AskUserQuestion 让用户选择:
        - 显示变更列表
        - 用户选择一个
        - 确认选择
    else:
        报错：没有可用的变更
else:
    使用指定的 change_name
```

#### 1.3 变更状态预检
```
运行: openspec instructions apply --change "<name>" --json

解析响应:
{
    "state": "ready" | "blocked" | "all_done",
    "tasks": [...],
    "message": "..."
}

状态处理:
- state == "blocked":
    → 显示阻塞消息
    → 建议使用 /opsx:continue-change 解除阻塞
    → 退出执行
    
- state == "all_done":
    → 恭喜消息
    → 显示所有已完成任务
    → 建议使用 /opsx:archive 归档
    → 退出执行
    
- state == "ready":
    → 继续执行
    → 显示: "✓ Change status: OK (N pending tasks)"
```

### 阶段 2：工作流调度

#### 2.1 工作流调用
```
调用: /Workflow self-driven-task-execution-final <change_name>

参数传递:
{
    "change_name": "<name>",
    "mode": "apply",
    "context": {
        "conversation_history": "...",
        "current_state": "..."
    }
}
```

#### 2.2 工作流内部处理（核心）
```

│                   工作流内部流程                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Step 1: 获取任务列表                                           │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ 运行: openspec instructions list --change <name> --json    │ │

│  │   ├─▶ 结果处理                                             │ │

│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 阶段 3：多代理协作（核心）

#### 3.1 模型路由决策

```
┌─────────────────────────────────────────────────────────────────┐
│                      模型路由决策                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  输入分析:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ task.title: "实现用户登录功能"                               │ │
│  │ task.type: "implementation"                                  │ │
│  │ task.complexity: "high" (推断)                              │ │
│  │ routing_memory: {                                          │ │
│  │   "implementation": {                                        │ │
│  │     "model": "opus",                                        │ │
│  │     "success_rate": 0.85,                                   │ │
│  │     "attempts": 12                                          │ │
│  │   }                                                         │ │
│  │ }                                                           │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                           ↓                                      │
│  决策逻辑:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ if routing_memory 存在且成功率 > 0.8:                       │ │
│  │     → 使用记忆中的模型                                      │ │
│  │ elif task.complexity == "high" or task.type == "implement": │ │
│  │     → 使用 Opus                                             │ │
│  │ elif task.complexity == "low" or task.type == "test":       │ │
│  │     → 使用 Haiku                                            │ │
│  │ else:                                                       │ │
│  │     → 使用 Sonnet (默认)                                     │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                           ↓                                      │
│  输出:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ selected_model: "opus"                                      │ │
│  │ reasoning: "高复杂度实现任务，使用 Opus 保证质量"              │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.2 主代理执行

```
┌─────────────────────────────────────────────────────────────────┐
│                    主代理执行流程                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Step 1: 准备执行上下文                                          │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ context = {                                                 │ │
│  │   "task": task_data,                                        │ │
│  │   "change": change_info,                                    │ │
│  │   "conversation_history": recent_history,                   │ │
│  │   "codebase_context": get_relevant_files(task)             │ │
│  │ }                                                           │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                           ↓                                      │
│  Step 2: 调用主代理                                             │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ agent = Agent(                                               │ │
│  │   name="primary_executor",                                  │ │
│  │   model=selected_model,                                     │ │
│  │   prompt=EXECUTION_PROMPT,                                  │ │
│  │   context=context                                           │ │
│  │ )                                                           │ │
│  │                                                             │ │
│  │ result = agent.execute(task)                                │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                           ↓                                      │
│  Step 3: 处理执行结果                                           │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ if result.success:                                          │ │
│  │     → 进入验证阶段                                           │ │
│  │ elif result.retryable:                                      │ │
│  │     → 记录失败，准备重试                                      │ │
│  │ else:                                                       │ │
│  │     → 标记为失败，生成 issue                                  │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.3 多代理验证（核心亮点）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    多代理验证系统                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  验证策略选择:                                                           │
│  ┌─────────────────────────────────────────────────────────────────────┐ │
│  │ if task.type == "critical" or task.complexity == "high":            │ │
│  │     → 使用 "完整验证" (3 代理)                                      │ │
│  │ elif task.type == "test":                                            │ │
│  │     → 使用 "对抗验证" (2 代理)                                      │ │
│  │ else:                                                               │ │
│  │     → 使用 "快速验证" (1 代理)                                      │ │
│  └─────────────────────────────────────────────────────────────────────┘ │
│                           ▼                                          │
│                                                                         │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │                   策略 1: 完整验证 (3 代理)                       │  │
│  │   用于: 关键任务、高复杂度任务                                    │  │
│  │                                                                   │  │
│  │   Agent 1 (Haiku)                                                │  │
│  │   ┌─────────────────────────────────────────────────────────────┐  │  │
│  │   │ 角色: 快速检查者                                             │  │  │
│  │   │ 任务: 检查基本完整性、语法、明显错误                         │  │  │
│  │   │ 输出: {ok: bool, issues: [], confidence: 0.8}              │  │  │
│  │   └─────────────────────────────────────────────────────────────┘  │  │
│  │                                ↓                                 │  │
│  │   Agent 2 (Haiku) - 不同随机种子                                  │  │
│  │   ┌─────────────────────────────────────────────────────────────┐  │  │
│  │   │ 角色: 独立验证者                                             │  │  │
│  │   │ 任务: 独立检查相同内容，发现不同意见                          │  │  │
│  │   │ 输出: {ok: bool, issues: [], confidence: 0.8}              │  │  │
│  │   └─────────────────────────────────────────────────────────────┘  │  │
│  │                                ↓                                 │  │
│  │   Agent 3 (Sonnet)                                               │  │
│  │   ┌─────────────────────────────────────────────────────────────┐  │  │
│  │   │ 角色: 最终裁判                                               │  │  │
│  │   │ 任务: 审查前两个代理的结果，解决分歧，给出最终判断             │  │  │
│  │   │ 输入: Agent1_result + Agent2_result                           │  │  │
│  │   │ 输出: {final_decision: "pass|fail", reasoning: "..."}        │  │  │
│  │   └─────────────────────────────────────────────────────────────┘  │  │
│  │                                                                   │  │
│  │   决策逻辑:                                                       │  │
│  │   - Agent1 和 Agent2 都 pass → 通过                              │  │
│  │   - Agent1 和 Agent2 都 fail → 失败                              │  │
│  │   - Agent1 和 Agent2 不一致 → Agent3 裁决                        │  │
│  └───────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │                   策略 2: 对抗验证 (2 代理)                       │  │
│  │   用于: 测试任务、需要发现边界情况                                │  │
│  │                                                                   │  │
│  │   Agent 1 (Haiku) - 支持                                         │  │
│  │   ┌─────────────────────────────────────────────────────────────┐  │  │
│  │   │ 角色: 证明者                                                 │  │  │
│  │   │ 任务: 找出实现的正确之处，证明任务完成                        │  │  │
│  │   │ 输出: {correct_points: [], pass: bool}                       │  │  │
│  │   └─────────────────────────────────────────────────────────────┘  │  │
│  │                                ↓                                 │  │
│  │   Agent 2 (Sonnet) - 反对                                        │  │
│  │   ┌─────────────────────────────────────────────────────────────┐  │  │
│  │   │ 角色: 反驳者                                                 │  │  │
│  │   │ 任务: 找出实现的问题、漏洞、未覆盖情况                        │  │  │
│  │   │ 输出: {issues: [], fail_reasons: []}                         │  │  │
│  │   └─────────────────────────────────────────────────────────────┘  │  │
│  │                                                                   │  │
│  │   决策逻辑:                                                       │  │
│  │   - Agent1 找到的正确点 - Agent2 找到的问题 = 净收益              │  │
│  │   - 净收益 > 阈值 → 通过，否则 → 失败                             │  │
│  └───────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │                   策略 3: 快速验证 (1 代理)                        │  │
│  │   用于: 简单任务、文档更新、配置修改                                │  │
│  │                                                                   │  │
│  │   Agent 1 (Haiku)                                                │  │
│  │   ┌─────────────────────────────────────────────────────────────┐  │  │
│  │   │ 角色: 快速验证者                                             │  │  │
│  │   │ 任务: 快速检查基本正确性                                     │  │  │
│  │   │ 输出: {ok: bool, notes: []}                                 │  │
│  │   └─────────────────────────────────────────────────────────────┘  │  │
│  │                                                                   │  │
│  │   决策逻辑:                                                       │  │
│  │   - ok = true → 通过                                              │  │
│  │   - ok = false → 失败，可能重试                                   │  │
│  └───────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 3.4 验证结果聚合

```
┌─────────────────────────────────────────────────────────────────┐
│                   验证结果处理                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  输入: 多个代理的验证结果                                         │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ results = {                                                 │ │
│  │   "agent1": {ok: true, issues: [], confidence: 0.8},       │ │
│  │   "agent2": {ok: true, issues: [], confidence: 0.9},       │ │
│  │   "agent3": {final_decision: "pass", reasoning: "..."}      │ │
│  │ }                                                           │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                           ↓                                      │
│  聚合逻辑:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ if 使用了 3 代理验证:                                        │ │
│  │     decision = results.agent3.final_decision               │ │
│  │     reasoning = results.agent3.reasoning                   │ │
│  │                                                             │ │
│  │ elif 使用了 2 代理验证:                                      │ │
│  │     net_score = count_correct(results.agent1) -            │ │
│  │                  count_issues(results.agent2)               │ │
│  │     decision = "pass" if net_score > threshold else "fail" │ │
│  │     reasoning = f"对抗验证得分: {net_score}"               │ │
│  │                                                             │ │
│  │ else: # 1 代理                                               │ │
│  │     decision = "pass" if results.agent1.ok else "fail"      │ │
│  │     reasoning = results.agent1.notes                         │ │
│  └─────────────────────────────────────────────────────────────┘ │
│                           ↓                                      │
│  输出:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ {                                                           │ │
│  │   "verified": true,                                        │ │
│  │   "decision": "pass",                                      │ │
│  │   "reasoning": "所有验证代理一致通过",                       │ │
│  │   "agent_count": 3,                                         │ │
│  │   "total_confidence": 0.85                                  │ │
│  │ }                                                           │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 阶段 4：失败处理与问题生成

#### 4.1 失败分析

```
┌─────────────────────────────────────────────────────────────────┐
│                     失败分析                                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  if verification.decision == "fail" or execution.failed:       │
│                                                                 │
│  判断失败类型:                                                   │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ if retry_count < max_retries:                               │ │
│  │     → 尝试重新执行                                           │ │
│  │     → 可能更换更强模型 (Haiku → Sonnet → Opus)              │ │
│  │     → retry_count += 1                                      │ │
│  │                                                             │ │
│  │ elif retry_count == max_retries:                            │ │
│  │     → 标记为持久失败                                         │ │
│  │     → 生成 issue 文档                                        │ │
│  │     → 记录到 routing_memory: {task_type: avoid_model}      │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

## 多代理协作总结

### 协作模式

| 模式 | 代理数量 | 模型选择 | 适用场景 |
|------|----------|----------|----------|
| **完整验证** | 3 | Haiku + Haiku + Sonnet | 关键任务、高复杂度 |
| **对抗验证** | 2 | Haiku + Sonnet | 测试任务、边界检查 |
| **快速验证** | 1 | Haiku | 简单任务、文档更新 |

### 协作流程

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   主代理     │────▶│  验证代理1   │────▶│  验证代理2   │
│  (执行任务)   │     │  (检查/支持)  │     │  (反对/审查)  │
└──────────────┘     └──────────────┘     └──────────────┘
       │                      │                      │
       └──────────────────────┴──────────────────────┘
                              ▼
                       ┌──────────────┐
                       │  裁决代理     │
                       │  (最终决策)   │
                       └──────────────┘
```

### 成本优化策略

1. **简单任务用 Haiku**: 测试、文档、配置
2. **复杂任务用 Opus**: 核心实现、架构设计
3. **验证用混合**: Haiku 做初筛，Sonnet 做终审
4. **路由记忆**: 学习最佳模型分配，避免浪费

### 质量保证机制

1. **多重视角**: 不同代理有不同的角色和目标
2. **对抗思维**: 支持者和反驳者互相制约
3. **分层验证**: 快速检查 → 独立验证 → 最终裁决
4. **失败重试**: 自动升级模型进行重试
