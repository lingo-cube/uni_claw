# ADR-0055：各类存储采用异步批量写入，成功仍以原提交边界为准

状态：accepted（2026-10-25，所有者明确要求“异步＋批量写入，减少阻塞和磁盘次数”）；目标决策已接受；九路径生产迁移及关闭验收已完成，实施证据和故障范围见`changes/RUNTIME-STORAGE-001/state.md`。

本决策只替代ADR-0023第3条“提交路径禁异步/批量缓冲”的实现限制。可靠执行源仍归Effect Boundary，发送前必须等待真实提交成功；原三值结果、未决发现、追加记录和失败处理不变。入队、返回Task、开始写入均不能报提交成功。异步批量是存储机制，不是新的Owner、恢复授权或跨存储原子事务。

Run、Evidence、World、Control、Runtime Plan、资源、咨询及执行记录的关键写入均须沿各自领域存储接口走原生异步确认；Host选择介质与批量策略，核心不依赖文件或队列实现。合法的一批保留每条原序列、原来源身份和顺序，成功在适配器声明故障范围内可恢复读取后返回。单条逻辑操作亦可异步提交，不能为凑批次越过先提交、后咨询/投递/发布的因果屏障。

批量必须有数量、字节和等待时间上限，并在背压时等待而不丢关键记录。已接受写入后的取消不等于未写；部分写入、确认丢失与后续故障保留原未决/阻断语义，不能盲重试。正常关闭须等待已接受记录完成或明确报出未确认项；不能靠进程退出时的Dispose补足先前的成功承诺。

诊断Trace继续保持异步、可关闭可丢弃，与可靠来源分开；不能复用其丢弃/超时规则承担恢复记录。生产验收须同时证明调用者等待不阻塞、真实批次减少写入/flush次数，以及原故障/Kill读取行为；仅增加Async名称、Task.Run包同步写或入队即返回不构成完成。旧同步实现和既有故障范围在新实现验证并切换前仍有效，不据此声称断电/跨节点耐久性。
