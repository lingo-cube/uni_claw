UniClaw 架构总览UNICLAW · TARGET ARCHITECTURE v0.1 · 一页看懂

一个「眼见为实」的智能执行系统：不猜界面——先取证、再判断、后动手、动手必验证。 每一步都留下可追溯的证据链；完成要有证明，不确定就诚实说不确定。
证据驱动三权分立失败即关门 fail-closed 动作后必验证完成需证明能力可换·权威不变能力集·可扩展·可替换·可管理

② 五大件两条大循环：认识世界 × 改变世界

系统的全部工作 = 蓝色「看清楚」循环 + 橙色「做并验证」循环，周而复始直到交卷。

━➤ 蓝色·证据流：设备 → 感官 → 证据账本 → 世界模型 ━➤ 橙色·效果流：控制环 → 绑定 → 安检 → 闸门 → 驱动 → 设备 ╌➤ 绿色·验证流：动手后重新观察，验证通过才允许下一个动作 ╌➤ 紫色·咨询流：执行核只在拿不准的语义决策点问大脑

③ 执行核内部六域分工 + 三条固定流水线（给工程师）

六域各持唯一权威、互不越界；三条流水线次序冻结、不可合并——这是全部正确性的来源。

责任域唯一权威（别人都不许碰）它不做的事（同样重要）生活化类比
证据账本
Evidence Ledger		证据准入：记录是否完整、来源是否可溯不判断真假、不判断相关性、不判断够不够用证据管理员：只管登记合格，不管断案
世界模型
World Model		世界观版本：屏幕上有什么、状态如何（随证据演进）不拥有目标、不做计划、不接受「期望」改写观察测绘员：画地图，不指挥行军
运行模型
Run Model		运行状态：契约、进度、义务、终局记录不判断证明成立与否（只记录安检的结论）考务处：发卷、计时、归档成绩
控制环
Control Loop		意图签发：下一步观察/行动/恢复的唯一出处不能直接动手、不能自证安全提出动议的议员
安检
Assurance		裁决：可不可做、够不够新、安不安全、效果真没真、完成成立否不签发意图、不执行动作法官+质检章
效果边界
Effect Boundary		目标绑定与执行：所有对现实的动作唯一出口不做策略、不重试、不扩权法警：只执行判决书，判多一点也不行
流水线 A · 观察（认识世界）
admission(准入)
  → relevance(相关吗)
    → reconciliation(并入世界观新版本)
冲突不覆盖：两种说法并存记录
流水线 B · 行动（改变世界）
intent(想) → bind(锁定目标)
  → judge(裁决) → gate(放行)
    → dispatch(执行) → receipt(回执)
      → 回流(留痕)
裁决被拒 ≠ 目标失效；放行前先登记执行台账
流水线 C · 终局（交卷）
proof(证明成立)
  → terminal(终局记录·冻结)
    → outcome(一次性交卷信封)
交卷后投递闸门永久关闭
为什么这样设计 —— 组件级优势（天真做法 vs 我们的设计）
🧠 大脑 UniAgent：天真=模型全包(想+干+自评)｜设计=认知与执行分离，评价只读不回写｜买到：换模型不动执行纪律
⚙️ 执行核 Uni Kernel：天真=多处入口都能动车｜设计=一切效果过闸门+唯一交卷口+终局关门｜买到：查一处=查全部；僵尸运行不存在
📚 证据账本：天真=感知输出直接当事实｜设计=准入只查合格、append-only｜买到：反幻觉第一道结构闸
🗺 世界模型：天真=新数据覆盖旧「真相」｜设计=版本化+冲突并存｜买到：过期可判定；不丢反例
📋 运行模型：天真=执行者自报进度｜设计=义务清单+记录判定分离+终局冻结｜买到：完成=核对表，非话术
🎮 控制环：天真=LLM 计划当状态｜设计=战术假设可废弃+恢复重入闭环｜买到：世界变了计划立刻让位；禁盲重试
⚖️ 安检：天真=执行前自查｜设计=独立裁决+三件套+消费相对新鲜度｜买到：授权精确可审计；拒绝≠失效
🚪 效果边界：天真=拿到坐标就点｜设计=绑定钉版本+闸门只执法+台账先行｜买到：点的永远是裁决过的；崩溃可对账

④ 流程一次点击的完整旅程（十条铁律顺口溜）

  1. 截图：从设备拿新鲜画面（原始像素）
  2. 感知：快通道 YOLO+OCR、慢通道大模型、层级 XML，产出「观察提案」
  3. 准入：证据账本登记——来源/时间/范围齐全才收
  4. 并入世界观：世界模型出新版本（旧版本只读留档）
  5. 拿主意：控制环在契约范围内签发意图（想点哪个）
  6. 锁定目标：效果边界把「想点的那个」绑定到当前世界版本的具体控件
  7. 安检裁决：够不够新？在允许清单内吗？有冲突吗？——三关全过才授权
  8. 放行执行：闸门只执法不重判；驱动落到真实屏幕坐标/原生键
  9. 回看验证：必须重新观察确认世界真的变了——回执≠效果
  10. 交卷：义务全部有证据支撑 → 终局证明 → 一次性结果信封 → 大脑评价
⚠️ 串行验证屏障：上一个动作验证清偿之前，绝不发出下一个现实动作。批量点击、盲目重试、拿回执当成功——都被结构禁止。

⑤ 生命周期从用户开口到盖棺定论

六个阶段各归其主；Run 内部循环任意次，但终局只有一次、不可复活。

1
会话 Session
关联根：一切的唯一索引
2
目标 Goal
大脑拥有：用户要的结果
3
契约 Contract
范围·红线·验收标准（版本化）
4
执行 Run
合法激活后内核自驱
5
结果 Outcome
一次性信封·附证据清单
6
评价 Evaluation
大脑打分·不回改事实
🔁 Run 内部：观察→决策→行动→验证 循环 N 次（次数不限，基数不变：1 会话 : 1 目标 : 1 运行）
⛔ 终局后：投递闸门关闭——迟到的事件、回调、绑定一律拒绝，「僵尸运行」结构上不可能

⑥ 设计优势六大卖点：客户问什么，指哪张卡

左列是所有「裸 Agent」的通病，右列是本架构的结构性答案——不是靠提示词约束，是靠结构保证。

😰 "AI 说点完了，真的点了吗？"
动作后必验证：每次操作后强制重新观察，回执≠效果、尝试≠成功。
图上位置：绿色验证回流线（②）· 流水线 A/B 闭环（③）
😰 "模型幻觉当成屏幕真相怎么办？"
三层分离：证据≠世界观≠现实。世界观只随合格证据演进，冲突并存不覆盖。
图上位置：证据账本+世界模型两域（③）
😰 "谁来拦住危险/越权操作？"
三权分立：想(控制环)、裁(安检)、干(效果边界)分属三域；不确定=拒绝，fail-closed。
图上位置：流水线 B 的 judge→gate（③）
😰 "怎么证明任务真完成了？"
完成需证明：四分类终局（成功/失败/安全停/升级）；证据不足=诚实未知，绝不装。
图上位置：流水线 C + 生命周期 5/6（③⑤）
😰 "换模型/换设备要重写系统？"
能力集可运营：可扩展（协议缝+注册入集，不改核心）、可替换（仿真⇄真件、模型互换）、可管理（注册·健康·生命周期）；六域权威链不变。
图上位置：Capability Plane 大蓝框（②）
😰 "这种系统怎么测试？"
同一套真件可仿真：录制→封存→确定性回放，两次运行逐字节一致；仿真不掺产品路径。
图上位置：Codex 仿真线（①）· 双宿主对称

⑧ 术语十个小词典（开会不掉线）

Observation 观察提案：感知产出的「我看到了这些」原始申报，登记合格才叫证据。
Evidence 证据：登记在册、可引用、带来源的依据记录。只回答「依据什么」，不回答「是不是真的」。
WorldBelief 世界观：系统当前对屏幕的判断，版本化演进，冲突并存。
Intent 意图：控制环签发的「想做什么」，不是命令、更不是授权。
Binding 绑定：把「想点的那个」钉到当前世界观版本的具体控件上。
Judgment 裁决：安检对（意图+绑定+世界观版本）三件套的一次性判断。
Receipt 回执：指令送达的留痕——只证明「发了」，不证明「成了」。
Verified Effect 已验证效果：动作后重新观察证实世界真的变了。
Outcome Proof 终局证明：义务是否有足够证据支撑的最终判定（成功/失败/安全停/升级）。
fail-closed 失败即关门：任何不确定一律安全拒绝，绝不「先试试」。

⑨ 演进引擎三个自我优化循环：越跑越强

UniAgent 本身是五层可插拔装配（Profile→Skills→Prompt→宿主绑定→Realization）；三条回流让系统随使用变强——自我驱动程度递减、落地程度递增。

① 经验循环 · 设计冻结/实现占位
交卷信封+评价 ─▶ Memory 持久化 ─▶ 下次 Run 召回当先验/假设/观察策略参考
边界：recall 永不单独建立当前判断——记忆变聪明，污染不了现实
② 测试资产循环 · 已落地
运行 Trace ─封存▶ 场景库 ─▶ 确定性回放回归（digest 一致）
跑得越多回归网越密——运行本身在生成测试资产
③ 配置演进循环 · 已落地
Profile/Skill/Prompt 版本化+hash ─▶ C1–C11 conformance 验收 ─▶ 生效
换模型/调提示词/升 SOP 都有验收门——优化不失控
🧠 UniAgent 五层可插拔装配（与能力面四层装配对偶）：① Profile 产品身份（不含模型名）→ ② Skills 领域 SOP（hash 锚定）→ ③ Prompt 纪律（hash 锚定）→ ④ 宿主绑定（模型/端点只在宿主侧）→ ⑤ Realization（Codex 仿真 / DSH 产品，整体可换）。 双 realization 差分对比 + conformance 场景 = 宿主无关、语义不漂移的可优化体系。
