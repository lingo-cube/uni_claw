# 决策粒度与策略分层场景推演 v0.1

## 0. 核心命题

**每轮都问不合理。** 咨询有真实成本（延迟 + 计算 + 上下文组装），而大量
任务的动作序列具有**规则重复性**——同一判断规则应用 N 次。正确形态是把
「重复决策」换成「一次规则 + 驱动器机械展开」，异常时才降级回精细咨询。

## 1. 提案的三层粒度（L0/L1/L2）

| 层 | 名称 | 形态 | 例子 | 现状 |
|---|---|---|---|---|
| **L0** | 精细指令 | 单步或极少步，每步带完整目标表达 | 「点这个验证码」「抓取偏移后重新对位」 | ✅ 已有（AgentActionStep） |
| **L1** | 路径计划 | 有序多步（≤16），路径已知 | 「主页→网络→Wi-Fi→开开关」 | ✅ 已有（≤16 步提案） |
| **L2** | 泛化策略 | **谓词 + 动作模板 + 终止条件 + 守卫 + 预算**，驱动器生成性展开 | 「对每屏：点击所有非危险可点项，叶子后返回，直到树尽」 | ❌ 未有（RUN-005） |

L2 五要素：**作用于什么**（谓词）、**做什么**（动作模板）、**何时停**（终止）、
**何时不适用**（守卫→异常边界）、**最多几次**（预算，防失控）。

## 3. 粒度选择原理（从目录归纳）

```text
粒度 ∝ 决策密度 / 重复度          （高风险项强制 L0，无论重复度）

L2：低密度 × 高重复（遍历/循环/批量）——问一次规则，机械展开
L1：路径已知的中等序列（导航/流程）——问一次路线
L0：高密度 / 高风险 / 低可预测（语义判断/异常恢复/精密操作）
混合律：L2 常态运行，任何守卫触发/失败边界 → 一律降 L0 精细重议，
        恢复后 Agent 可再发 L2 继续（降级-恢复循环）
```

**异常降级不需要新机制**：就是 RUN-004 的 StepRejected / 
VerificationFailed 边界——L2 提案失败作废、带上下文回咨询，Agent 
自然改发 L0。协议本身对粒度无感。

## 4. 代表场景推演（三轮）

### 4.1 A2 空调温度（「每轮都问」的浪费实证）

```text
朴素多轮（每按键一问）：温度 24→20 按四次减号 = 4 轮咨询，
  每轮上下文几乎相同、答案几乎相同（"按减号"）——3 次纯浪费。
L2 策略（一次咨询）：
  AgentActionPolicy{
    谓词:   当前温度 > 20
    模板:   tap role=减号 desired=temp-1
    终止:   温度=20
    守卫:   连续 2 次观察温度不变 → 中止上报     ← A2 的异常出口
    预算:   ≤8 次 }
  → 驱动器机械展开：观察→按键→验证→谓词判定→循环；1 轮咨询搞定。
  温度卡住 → 守卫触发 → VerificationFailed 边界 → L0 重议。
```

### 4.2 B6 翻页找商品（L2 循环 + 命中降级）

```text
L2：{谓词: 屏上无目标商品, 模板: 向上滚动一屏, 终止: 谓词不成立, 预算: 20}
  → 命中（策略终止）= StepVerified 边界 → L0 咨询「点进商品→加购」
  → 预算尽未命中 = 诚实失败（找不到就是找不到，不硬凑）
```

### 4.3 A1 全树遍历（L1 vs L2 的咨询经济学对比）

| 方案 | 咨询次数 | 前提 |
|---|---|---|
| L1 逐屏打包（上轮推演） | ~17–21 次 | 每见新屏一问 |
| **L2 策略** | **2–5 次**（1 次发策略 + 弹窗/异常时 L0） | RUN-005 |
| uni-agent 实测参照 | 35 次派发（其 Traversal 层≈内置 L2 执行器） | 旧线分层先例 |

开关禁点在 L2 下天然更稳：谓词本身就写「checkable=true 的不点」——
规则一次声明，比每屏重新问一遍更不易漏。耗时记录照旧免费
（每步 journal 时间戳 → 派发耗时 = 验证帧时间 − 派发时间）。

## 5. 对规格的影响（结论落点）

1. **RUN-004（多轮协议）不变仍为第一步**——L0/L1 已能在其上运行，
   且 L2 必须依赖它的异常边界与 Defer 语义；
2. **RUN-005（策略提案形态）立项**：Act 提案增加 policy 形态
   （谓词/模板/终止/守卫/预算五要素）；**协议零改动**——策略仍是
   一个边界一次的 AgentDecision，驱动器只是多会一种展开方式；
   策略执行状态（已访问/已尝试计数）归驱动器执行态，进度进上下文；
3. **B5（验证码）与 C3（力控装配）是慢感知/精密执行的未来买家**，
   记入排队依据，不现在立项；
4. 预算合同声明制（RUN-004 修正项）在 L2 下更关键：策略预算 +
   轮次预算双层，防泛化策略失控。
