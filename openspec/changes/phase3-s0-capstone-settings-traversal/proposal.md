## Why

SC-S0-CAPSTONE-001 is the S0 graduation integration target: it proves the frozen Runtime capabilities compose end-to-end in one deterministic four-level Settings world with exactly one Popup obstruction and exactly one external Launcher drift. All 13 capability prerequisites are frozen (SC-P1-001/005, SC-P2-001/003, SC-P3-001/002/003, SC-P3-CAND-004/005/006/007/008/009), the legacy baseline classification is frozen (2026-08-09, 47 cases, 0 `UNKNOWN`), and `S0_BASELINE_READY` is declared by HUMAN gate `ACCEPT_S0_BASELINE_READY_AUTHORIZE_CAPSTONE_OPENSPEC`.

The only missing authority is the Scenario purchase for the integration run itself. Per the Scenario-First principle, an Active Scenario must purchase the Capstone's integration behavior, Fake-world construction contract, completion evidence, and replay contract. A `CAPSTONE` integrates frozen capabilities and does not directly purchase new production semantics.

- Registers the Capstone integration Scenario as an OpenSpec change with zero production delta.
- Fixes the deterministic S0 world construction contract: the Fake world may define visible elements, dispatch outcomes, world transitions, Observation data, Popup appearance, and Launcher drift, but must not encode production conclusions such as Container identity, Recovery authority, progress completion, or Goal success.
- Fixes the disturbance schedule: exactly one local Popup/Overlay obstruction and exactly one external drift to Launcher/desktop.

- Fixes the stop-extract-gate clause: if execution exposes a new Reality Distinction, stop, extract one bounded Candidate Scenario, run its Semantic Gate, prove/freeze that capability, and only then return to the Capstone.
- Purchases nothing in production: zero types, fields, enums, interfaces, components, and mutable state; ownership and authority deltas NONE.
