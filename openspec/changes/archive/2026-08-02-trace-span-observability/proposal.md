## Why

The trace is a flat event list — `ExecutionRecord` rows classified by an 11-value `SpanType` enum, with no parent-child timing tree. It cannot support (a) real-time early termination ("enough entries observed + end-of-list reached → stop"), (b) performance bottleneck localization ("which step waited on what?"), or (c) cross-run baseline comparison ("how many entries does this scenario typically have? p95 step count?"). The existing `ITraceService` tree queries (`ReconstructTree`, `GetStepTimeline`, `GetBySpanType`) operate on that flat list and carry no start/end timing or attribute bags. This change introduces an OpenTelemetry-style `TraceSpan` tree (parent-span-id, timing, attributes) **alongside** the existing system, the `ITraceQuery` read surface, real-time `CompletionAnalyzer`/`ErrorAnalyzer` via a polling `CompletionMonitor`, and an offline `BaselineBuilder` whose `artifacts/baselines/<scenarioId>.jsonl` feeds data-driven termination thresholds. Phase 2 (the `[TraceSpan]` source generator that replaces manual `StartSpan`/`EndSpan` calls) is explicitly **DEFERRED** to a future change — the design doc itself stages it ("等 source generator 成熟后再迁移，阶段性 commit").

## What Changes

- **NEW `TraceSpan` record + span JSONL** (Core): `TraceSpan(SpanId, ParentSpanId?, SpanType string, SpanName, StartTime, EndTime?, Status, TraceContext?, Attributes?)` with `DurationMs`. New `"span"` `record_type` in trace JSONL, parallel to `execution`/`state_transition`/`page_transition`/`ai_call`. Stored in a new `_spans` list in `InMemoryTraceStorage`, coexisting with the existing `_executions`/`_transitions`/`_pageTransitions`/`_aiCalls`/`_errors` — existing consumers unchanged.
- **NEW `ITraceRecorder.StartSpan/EndSpan`** (Core): span lifecycle (`StartSpan` returns `string spanId`; `EndSpan` closes with status + final attributes). Distinct from the existing `ITraceCoordinator.PushSpan/PopSpan` engine-internal stack — the two coexist; `StartSpan/EndSpan` is the new general-purpose span API the analyzers and instrumentation call. `InMemoryTraceStorage` + `FileTraceStorage` gain span write/read.
- **NEW `ITraceQuery : ITraceService`** (Core): `GetRootSpan`, `GetSpansByType(string)`, `GetChildSpans(parentSpanId)`, `GetSpan(spanId)`, `GetAllSpans`. `InMemoryTraceService` implements `ITraceQuery`. The existing 12 `ITraceService` methods are unchanged.
- **Phase 1 manual instrumentation** (Core + Host): `engine.run`/`engine.step` (`TraversalEngine.RunAsync`), `entry.generate`/`entry.observed`/`entry.ignored` (`DynamicChildManager.Generate` — requires wiring its currently-null `_trace` field, see Impact), `entry.visited` (`InterceptionHandler.OnBranch`), `entry.skipped` (`SafeActionExecutor` deny path), plus `action.*`, `ai.call`/`ai.analyze`, and `analyze.completion`/`analyze.error_loop` written by the analyzers. Phase 2 `[TraceSpan]` source generator is **DEFERRED**.
- **NEW `completion-monitor` capability** (Host): `ICompletionAnalyzer` + `CompletionVerdict` + `EnumerateCompletionAnalyzer` + `ErrorLoopAnalyzer` + a polling `CompletionMonitor` (500 ms) that writes `analyze.completion` spans and cancels the engine via a linked `CancellationTokenSource` on Halt/Terminate. Confidence→action mapping, cold-start rules (baseline < 10 → only Halt + Warn fire), and the documented edge cases (corrupt baseline, repeated Recommend dedup, observed-spike abnormal guard).
- **NEW `baseline-builder` capability** (Host): `BaselineBuilder` extracts per-run aggregates from spans into `artifacts/baselines/<scenarioId>.jsonl`; p50/p95 thresholds computed once ≥ 10 records accumulate; loaded by `EnumerateCompletionAnalyzer` for data-driven thresholds (replaces hardcoded p50=14).

## Capabilities

### New Capabilities

- `trace-span`: `TraceSpan` record, the spanType taxonomy (engine / entry / action / ai / analyze), `ITraceRecorder.StartSpan/EndSpan`, `ITraceQuery`, the `"span"` JSONL `record_type` + storage, and the Phase 1 manual instrumentation points.
- `completion-monitor`: `ICompletionAnalyzer` / `CompletionVerdict`, `EnumerateCompletionAnalyzer`, `ErrorLoopAnalyzer`, the `CompletionMonitor` scheduler, the confidence→action mapping, and the cold-start + edge-case rules.
- `baseline-builder`: `BaselineBuilder`, the `artifacts/baselines/<scenarioId>.jsonl` format, p50/p95 threshold computation, and the run→baseline→threshold data-closed-loop.

### Modified Capabilities

- *(none — additive only. The existing `ITraceRecorder` / `ITraceStorage` / `ITraceService` / `ITraceCoordinator` surfaces receive new methods/records but no existing requirement's behavior changes. The `SpanType` enum is untouched — the constitution-locked C-11 guard is sidestepped by design via the string `spanType` field. Phase 2 source generator is a separate future change.)*
