## 二、重构目标

### 2.1 主要目标

**简洁性** (Simple):
- 消除文档重复，一题一文档
- 每个文档职责清晰，不交叉

**清晰性** (Clear):
- 概念层与实现层分离
- 文档定位准确，易于查找

**实用性** (Practical):
- 文档反映当前实现状态
- 删除过时和错误的文档
- 保持文档的可维护性

### 2.2 成功标准

1. **无重复**: 每个主题只有一个权威文档
2. **分层清晰**: 概念、集成、实现三层分明
3. **位置准确**: 文档放在合适的目录中
4. **引用正确**: CLAUDE.md中的所有链接有效
5. **归档完整**: 过时文档有历史记录

**问题**: 3个文档重复同一主题  
**解决方案**: 整合为1个综合文档

**执行操作**:

2. 整合3个文档的核心内容：

### 3.2 状态机文档分工 📋

**问题**: 概念和实现内容混杂  
**解决方案**: 明确分层，概念层专注理论，实现层专注技术

**执行操作**:
1. 更新 `docs/architecture/concepts/state-machine-design.md`:
   - 添加概念层说明
   - 专注于状态定义、转换规则、设计理念
   - 引用实现文档获取技术细节

2. 更新 `docs/architecture/modules/state-machine-design.md`:
   - 添加实现层说明

**分层原则**:
- 概念文档: "WHAT" 和 "WHY" - 是什么，为什么这样设计
- 实现文档: "HOW" - 如何实现，技术细节

### 3.3 过时文档归档 📊

**问题**: 规范文档与模块文档重复  
**解决方案**: 归档过时规范文档

## 七、长期维护

### 7.1 文档维护原则

**单一真相来源**:
- 每个技术主题只有一个权威文档
- 避免多个文档描述同一主题

**分层清晰**:
- 概念层: 设计理念、架构决策
- 实现层: 技术细节、API文档
- 应用层: 使用指南、最佳实践

**及时归档**:
- 过时文档及时归档，不直接删除
- 保留历史，但明确标注状态

### 7.2 文档更新流程

**新增功能**:
1. 更新概念文档（设计理念）
2. 更新实现文档（技术细节）
3. 更新CLAUDE.md（导航索引）

**架构调整**:
1. 先更新架构文档
2. 再更新相关模块文档
3. 最后更新索引和引用

**过时内容**:
1. 评估是否仍有价值
2. 如有历史价值，移至archive
3. 如无价值，添加说明后删除
