# 连续执行概览、页面图与目标推进驱动续额：整体提案

状态：Accepted（2026-10-18）。Owner已在整体提案交付后授权指定Leader/Worker实施；本文件为ADR-0052的实施范围，changes/RUNTIME-OVERVIEW-001承载计划、验收和状态。接受提案不等于实现或验收已完成。

## 1. 原来的问题与目标行为

当前Agent能看到当前页面、执行计数和续额窗口，但不足以稳定知道全局已发现入口、历史待办与本笔额度究竟推进了什么。续额仍是可选字段；省略不能区分明确拒续和漏答。现有World Model有图基础，但Settings没有真实页面导航图生产与消费；旧停滞计数及任务上限也可能在续额前截断执行。

目标行为是：根页观察即积累已发现入口，保持全局清单并沿当前有价值路径深入；连续overview同时呈现目标、结构、历史、本段成果和未知。Runtime在资源接近阈值时明确发起复核，Agent按目标判断继续、调整或结束，Runtime校验与记录。正常推进可逐笔续额，局部受阻则转其他可行分支。

## 2. 职责与事实来源

| 事项 | 来源与职责 |
|---|---|
| 页面、当前交互上下文、导航关系及不确定性 | World Model持有belief；图边必须有实际观察依据，历史路径不替代本步grounding。 |
| 已访问、已验证要求、受阻、跳过、探索范围 | 各既有任务/Progress/Evidence Owner记录，关联世界身份和证据；不写成World Graph中的任务真相。 |
| 初始额度、消耗、申请、授拒、剩余额度 | Runtime既有预算及决策记录，授额一次生效；保留原始基数与累计消耗。 |
| 是否朝目标推进、下一段预期 | UniAgent对照目标与事实作判断，单独记录依据；不能将自评覆盖事实。 |
| overview | Runtime按上述Owner提供的显式投影组合成同源只读视图，不绕过缝读取私有状态，不建立第二套可变进度。 |
| 完成与Effect许可 | 仍由既有Assurance/Outcome、grounding及Effect Boundary执法，续额不扩大目标或权限。 |

## 3. overview更新与信息量（Leader建议，随整体确认）

接受观察、验证及预算事件后更新可用事实；每次既有咨询提供最新精简overview，复核时补足本笔额度的预期/实际和相关历史对照。更新不新增模型咨询或设备点击。输入仍使用同一Run、Contract与任务范围，事实标记各自来源revision/事件水位；不能把未接收到的验证写成成功或混入别的Run结果。

概览应回答：
- 本次目标与允许范围是什么，当前位于哪个分支。
- 已知结构与未知范围是什么；剩余工作允许按分支、范围或问题表达，不要求详尽清单。
- 累计验证了什么，较上一概览发生了什么变化。
- 自最近一次获批额度起，原预期、实际成果、消耗、阻碍及差异是什么；初始工作段同样保留起点。
- 下一段方向、预期证据与理由是什么；Agent判断依据哪一份事实。

人和Agent读取同源事实，展示可以不同。精简版须区分“未知”“没有”和“已省略”；保留关键阻碍、范围未知和复核依据，不用一个百分比遮盖这些差异。历史快照与来源引用随运行记录保留；加强复核时由Runtime主动补充相关历史，不假定Agent已具备任意历史检索工具。首版交付Agent输入与可查看的运行记录/报告，不新增控制台、图编辑器或独立检索服务。

## 4. 图与入口清单

根页观察到入口即可登记已发现、未访问；未进入入口不提前铸造目标页面身份。实际到达后，World Model按上下文和证据建立页面身份与导航关系，关联入口和目标；同名页面不直接合并，滚动视口变化不自动产生新页面。Contains/Overlays不能冒充导航关系，TransitionContext本身不构成边的证据。

图投影保留来源revision、范围和不确定性，明确当前交互锚点。多页面图接入时同步修正“全部容器总数必须为1”的消费假设，不能让历史页面参与本步grounding。现有配置种子与动态发现合并呈现时分别标注；未观察的种子不算已发现，配置目标也不因动态候选排除它而变成策略跳过。

遍历维持全局已知待办，可继续深入当前分支；由Agent根据本段预期、实际所得及下一可行路径决定切换，不固定先广或先深。范围限定当前设备/账号/权限/系统状态，条件分支记录缺少的前提，不为枚举全部状态额外切换。

## 5. 明确复核及授额

1. Runtime按独立配置的资源阈值提前触发复核，预留作答及一次纠正所需的咨询机会；不能等轮次耗尽后凭空免费咨询。
2. Agent对照overview明确回应继续、调整、补证据或提交结束判断。需要资源时，说明下一段方向/待查问题、可观察证据、理由和请求数量；不要求预言完整未知页面树。
3. 单笔默认量为ceil(本次Run初始获批额度×20%)，步数/咨询轮次分别计算，按所需维度申请。初始96步/112轮对应默认20步/23轮。可说明理由调整，不是每次必授量，不能按累计授额复利增长。
4. Runtime校验当前复核关联、已确认资源规则和提案合法性，记录授/拒及原因；同一决定重放不得重复加额。续额不是Contract修改，也不重置Run、Session、历史、累计消耗或失败事实。
5. 漏答复核给予一次明确纠正机会，资源照常记账；仍未完成则不发放额度，记录复核失败，不伪造成目标失败或成功。有效明确拒续与漏答分别记录。

明确结果还需表达当前不续哪些维度、什么条件需要重新复核，避免同一已处理复核被每次咨询机械重复。新授额区间以实际授予事件为边界；旧剩余额度结转、累计授额和累计消耗仍保留，不把区间成果误记为新额度独自购买的成果。

## 6. 加严复核、停止与旧策略兼容

最近一笔额度的成果为续额复核重点；历史用于全局理解。正常沿目标推进且下一段有依据时可持续逐笔续额，不按未经任务标定的256步自动结束。

偏离预期、同一路线反复申请而无新成果或证据不足时，提供更完整相关历史、原计划、实际变化及重复失败情况，要求解释差异并给出调整依据。必要返回、排除错误路径、恢复和查明条件可以是有价值结果，但与成功覆盖分别记录；只改写理由、增加动作数或重复观察不构成新成果。

旧停滞计数首先是复核信号，不能单独替代目标相关判断。Director当前按计数直接bounded-stop、账本的滚动/连续失败/最终额度等出口，需要逐项区分明确资源或安全约束、局部策略约束与无进展信号，避免一边授额一边被旧路径提前终止。明确不可执行的动作仍不得执行；新策略不以删除所有停止条件实现。

局部受阻且其他方向可行时继续其他分支；没有可行方向或依据不足以继续时，报告未满足事项及原因。提交完成仍需证据支持本次已声明范围，并经过既有验证。任务若有明确时间/费用等资源授权边界，应按真实来源与计量执行；本Change不凭空增加费用估算或新计费服务。无独立有限边界时不主张必然在固定步数内终止，这一取舍记录于accepted ADR-0052。

## 7. 可判定验收

| 情形 | 应证明的行为 |
|---|---|
| 只观察根页、尚未进入其他入口 | overview已能呈现已发现入口及未访问事实，不额外点击建立概览。 |
| 深入一个分支，其他一级未访问 | 全局待办仍可见；当前有目标相关成果时不强制返回。 |
| 新发现扩大已知范围 | 保留新增与未知，不因分母增大认定倒退或伪造完成率。 |
| 已发现入口与实际到达页面 | 候选、页面身份和证据可区分；图边有前后观察，失败尝试不生成成功导航边。 |
| 必要返回、恢复或查明条件 | 可解释与目标的关联，不冒充成功覆盖，也不被零覆盖增量直接误杀。 |
| 当前分支受阻 | 记录本地阻碍并选择其他可行方向，受阻不计成功。 |
| 反复成功点击旧页面或A/B往返 | 不能只靠动作成功或旧成果续额；加强对照并调整，缺依据时拒绝同路线延续。 |
| 额度窗口开启但漏答 | 自动明确要求复核，至多一次纠正；每次消耗与授拒可追，不自动发额度。 |
| 正常进展跨越旧256步 | 经有效复核可继续；不存在旧Host阈值提前截断或新硬编码任意顶。 |
| 重放决定、部分维度续额、重规划 | 无重复授额、无计数重置；未申请维度和后续复核条件明确。 |
| 已知待办为空但探索范围未知 | 不宣称全树完成；补证据或如实报告未知。 |
| 范围已满足或明确资源边界触达 | 分别进入既有完成验证或资源停止路径，不混淆原因。 |

每项实现验收须补齐method/expected/actual/evidence；确定性场景与真实设备证据分开。既有图18/18、入口账本1/1仅证明原有能力，不证明本提案已实现。整体确认后才制定实施计划、同步协议与ADR状态，并完成相应回归和现场验证；不把SETTINGS-COVERAGE-005的全遍历未完成改写为已完成。
