## 已定的行为

World维护实体节点、自身语义及有依据的关系。页面是Container的一种，完整上下文由节点与关系组合表达；详情结构可复用，实例归属有来源。一组局部Slice共同表达同一个Container已知内容，再计算为结构、语义、状态与布局的只读页面表达，复用已有Replay呈现与验证资产。

多次观察先经接纳与World reconciliation累计，局部Slice仍从选定World版本派生。当前可见、此前见过、当前是否仍成立分别表达；历史控件不因此获得当前定位。语义更新不必然换Container；有充分证据的归属纠正在新版本处理受影响关联，旧Slice及历史引用保留。

本期至少覆盖四类缺口的产生、只读消费、保持未知/解决及Agent实际可见。整体Goal评价、预算/Effect恢复实现、完整关系全集及跨会话重识别仍按原延期，不以这些跨线事项阻塞当前设计。

### Slice标识的具体约束

已确认CoreSemanticProjection.SliceId只取revision+root，无法区分现有API已经支持的不同InScope集合。候选修正原则为：固定来源版本、实体、归一化局部范围与实际影响投影语义的处理规则共同决定视图引用；相同固定输入应稳定，范围不同不能混同，集合次序/重复不应制造伪新视图。具体编码、兼容策略和旧引用解释需随真实consumer检查后决定，不在本稿冻结hash算法。

用户Q17提出版本分级，补充见version-layer-design.md：上述固定World来源锚与局部内容依赖标记分开；World统一派生节点/边/局部内容的变化依据，不另造多级可变Owner。来源World修订不同的快照保持可区分，相关依赖未变时可以复用纯内容计算；现有当前视图及Assurance freshness规则不被局部标记替代。行为规则已随Q17接受，具体字段、编码及兼容方案仍待工程细化。

这里只确定后续必须修复的行为，不表示已改实现或运行回归。已有Core TargetBinding的BasisSliceId和相关比较须一起核验，不能只改绘图文件名掩盖碰撞。

## 调用责任与接口位置

| 操作 | 输入→输出 | 复用点/待细化点 |
|---|---|---|
| 接纳后更新World | 原P3 accepted Evidence及合法上下文→新WorldBelief revision/未知/冲突 | 沿WorldModel既有reconciliation；累计及归属纠错由Owner裁决。没有允许Agent或Renderer直接改归属的public操作 |
| 读取局部Slice | 当前/选定版本与有界范围→不可变Slice及必要来源关联 | 复用WorldModel.DeriveSlice/UniKernel组合缝，核实页内范围请求和来源固定的最小扩展；不让caller从World aggregate自行造真值 |
| 解释累计页面内容 | 固定Container/版本和被认可的组成依据→只读页面表达所需信息 | World派生有据事实和限制；组合计算可以是纯派生消费，不能通过历史Slice拼接隐式创建新World revision。先确定现有事实/索引可复用部分，再判断最小新增领域记录 |
| 计算并绘制页面 | 有兼容来源、范围与布局依据的局部表达→可查看页面及缺口说明 | 复用Replay语义呈现/对照逻辑与资产；现有test-only Oracle不能变成生产事实源，产品也不依赖tests程序集。不另立展示平台或第二World |
| 给Agent提供信息 | World/Control/Runtime各自只读事实→正式咨询中的当前相关摘要 | 复用ExecutionOverview/AgentDecisionContext及decision channel；必要字段经严格codec与生成物同步，真实模型输入留证。只给引用不算可读 |

这些是职责级Interface候选，不是五个新接口/服务；既有模块若能完成，就在原seam扩展，不为每个名词新增Ixxx。

## 一条具体数据流

以稳定的设备详情长列表为受控例：第一次看到A、B，滚动后看到B、C。实际观察均有来源；页面关联已确认，滚动关系及重叠B有足够对应依据。

1. 两次观察分别接纳。World确认同一Container，记录有依据的观察关联，形成新revision。
2. 当前occurrence集合仍是第二次观察的B、C；A的旧观察保留历史/累计依据，不能拿A的旧locator直接执行。
3. World针对选定版本输出必要的局部内容及限制。A是否仍成立、布局是否可计算有各自依据；未证明的状态或位置仍未知。
4. 页面表达在有充分依据处合并重叠B，显示已知A/B/C及来源/状态差异。终点未证时覆盖仍为部分。
5. 现有Replay呈现规则把结果画出。若画面漏B或重复B，可由对照/lineage定位到World供给还是纯展示，不能用原图或人工GT把产品缺失内容补出来。
6. 如果新证据证明某局部原属另一Container，World先做正式归属纠错和受影响关联处理，生成新版本，再重算页面表达；旧视图不改写。

A/B/C只是示例内容标记，不是新身份规则；重叠去重仍需实际对应依据，不以同名文本猜测。

## 必须满足的正反例

| 输入/变化 | 应有结果 | 后续证据 |
|---|---|---|
| 同版本同root、不同局部范围 | 两个固定视图引用可区分，内容与范围对应 | SliceId及Core依据引用的负向回归，尚未运行 |
| 同范围以不同集合次序/重复提出 | 固定视图含义不漂移，不把重复当新信息 | 范围归一化与确定性用例，尚未运行 |
| 两个同模板但不同实例的详情页 | 依据各自上下文归属，不错合并 | 节点/边/局部视图与正式Agent输入，尚未运行 |
| 有据重叠/同名但不可判别的条目 | 前者正确合并，后者保留歧义 | 控制样例与真实输入分开验证，尚未运行 |
| 固定栏、嵌套滚动或配准不足 | 固定栏不随内容平移；无法定位的部分明确未知 | 复用已有滚动正反例，新增消费链证据，尚未运行 |
| 较早局部的状态已变化/缺时序依据 | 不把旧状态当当前，不以拼图完成掩盖未知 | World累计与渲染端分别留痕，尚未运行 |
| 充分证据纠正已确认归属 | 新版本归属及相关边/投影一致更新，历史引用仍可解释 | 纠错、缺证据及冲突反例，尚未运行 |
| 来源或覆盖信息缺失 | 部分/未知可读；未知不填0、不误报全部完成 | 正式codec→transport→模型输入及页面表达证据，尚未运行 |

每个最终交付仍须覆盖四类缺口的最小生产/消费/验收；上表的单页样例是tracer，不是把另外几类静默延期。
