# 历史稳定语义复用：一手资料与类比边界

日期：2026-10-23。Authority NONE。性质：设计参考，不改变已接受的World/Slice职责，不冻结公共字段或接口。

## 官方原意

- [RFC 5861 §3](https://www.rfc-editor.org/rfc/rfc5861.html#section-3) 定义 `stale-while-revalidate`：响应允许时，缓存可在指定秒数内先返回已过期响应，并应在继续服务期间尝试后台重新验证，以隐藏延迟。RFC 5861 标注为 **Informational**，明确不是 Internet Standards Track 规范。
- [RFC 9111 §4](https://www.rfc-editor.org/rfc/rfc9111.html#section-4) 规定缓存响应只有适用于当前请求，且满足fresh、明确允许返回stale或已成功验证等条件时才可复用。
- [RFC 9111 §4.1](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.1) 要求对 `Vary` 指定的请求字段进行匹配；不匹配时不能未经重新验证就使用该响应。
- [RFC 9111 §4.3](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.3) 描述基于条件请求与存储响应validator进行验证，并据响应更新适用的存储表示或用新响应替换。验证针对请求和对应表示，不是无条件接受较晚到达的数据。

## 对本设计的有限推论

- 可以先把前面版本已验证的稳定语义作为**有来源的历史参考**立即提供给Agent/页面；其历史性质应清楚可见，不妨碍后续核对。
- 当本轮已有足够的对应依据时，World可核验实体、范围、适用条件及未被纠错的依赖，再把稳定语义纳入新World revision/Slice；无需为相同稳定语义重复等待慢模型。来源链应保留。
- 本轮对应依据尚不足时，历史参考仍可供理解；当前动态状态、位置/布局、可见性和执行定位仍由各自原Owner按现有规则判定。
- 若纠错推翻了被复用语义的来源、归属或适用条件，World按依赖重判受影响的当前投影；旧快照不回写。

## 不能由RFC推出

- HTTP缓存是请求/响应表示的协议机制，不是页面事实或世界状态模型；它不能证明旧UI状态仍成立，也不能使旧locator重新获得当前执行资格。
- RFC 5861 的秒数窗口不构成本项目的TTL；RFC缓存验证条件不构成新的confidence分数或阈值。
- 此类比不要求所有模块、每次读取或每条历史语义都必须后台复核，也不要求后台重新运行模型。是否需要新处理由证据缺口与原Owner规则决定。

## 设计定位

本资料只支持“有标记地先提供历史参考，并在具备对应依据时核验复用”这一有限类比。版本身份、访问轮次、不可变Slice、纠错依赖传播及Q18整链验收仍以本线已接受的设计为准；本文不是产品实现或运行验收证据。
