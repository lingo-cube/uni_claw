# World场景与流程推导

2026-10-23；实施前审查。结论：已接受范围可继续工程实施，没有新增必须用户裁决的语义/Owner冲突；当前代码尚未满足整包行为。readiness的ready仅指设计审查，绝非产品PASS/CLOSED。读过的输入及hash见readiness.json，场景源码断言见scenario-inventory.md（简称N/V/P/S/CW/CS/RC/CK/R/H/C/F）。

## 当前代码会怎样运行

Ledger.Admit→World.Reconcile→Current/revision→DeriveSlice→Control/Grounding/Assurance/Effect→事后观察是既有主链。WorldModel.Semantics.SemanticContainer只允许与当前页面观察精确匹配的语义；World保留revision历史，但当前occurrence按观察替换。故“历史可读”“当前有据沿用”“纠正旧观察”不能靠延长现有current-only入口的时间窗实现。

CoreSemanticProjection.SliceId只拼SourceRevisionId+RootContainerId，现有DeriveSlice却允许不同InScope集合，构成源码可判定的范围碰撞。DeriveSlice返回原scope数组而用Distinct范围过滤；修复时要同时规范集合次序/重复，不能只换一个hash。scope-id负回归在当前C断言中缺失，未运行现场复现。

## 域、前提与性质

## Producer可提供性与工程结论

当前capture、EvidenceId/derived leaf、当前身份、导航/滚动验证来源、typed coverage、receipt/intent/binding链均可复用。缺的是：同身份重新进入发生来源的读取、精确处理来源、页内scope/跨观察字段适用与覆盖组合、旧观察纠错目标、World到实际消费的依赖/不完整边界、真实执行计数与结果、四类摘要与最终Agent输入留存。详见model-interface-disposition.md逐项责任。不能由测试Oracle提供这些答案给World。

首期“完备”是上述有据/不足路径和消费执法完整，不是provider保证识别所有世界状态。缺来源可保持未知，但不能省略受控合法正例或把四类只有enum称交付；live没有覆盖来源时明确限制。需要先补最小producer/Owner投影，随后写纵向验收，产品验收实际结果留实现会话。本审查未运行产品测试/仿真/设备/真实产品模型。
