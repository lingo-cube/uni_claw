# 任务持久化职责与可靠性契约

> RUNTIME-STORAGE-002的已确认需求细化；生命周期/范围/验收以state.md为准。本文件不是第二任务系统或通用存储实现设计。它记录目标契约，表中的要求不表示当前已实现。

## 1. 分类维度与事实清单

任务需求决定职责；职责决定可靠性；编码与保留期分别选择。同一文件/材料可以承担多种用途，以字段和真实消费方判断，不能按扩展名、所在程序集或能否重新计算分类。

| 记录/材料 | Owner与实际用途 | 目标职责与可靠性 | 编码/保留要点 |
|---|---|---|---|
| TaskInstance、ProductSession、Activation | Host铸造/绑定身份，启动准入与幂等查询 | 核心；确认前不发布成功，不因删除展示产物丢绑定 | 完整身份/绑定事实＋必要生命周期变化；保留幂等和失效语义 |
| RuntimeRunStore | Host启动/状态/幂等查询，HTTP读取 | 当前混合了事实与投影，逐字段确定；不是整体可丢缓存 | 事件目前无完整payload，不能声称可独立重建现有snapshot |
| Run合同/状态/Outcome | Run Model正式状态及原结果/依据 | 核心；终局不可改写 | 身份/合同/结果完整记录；可变状态最新＋版本变化 |
| Evidence入证、来源、lineage | Evidence Ledger原入证事实及证明依据 | 核心用途保护；保留原身份和引用闭包 | 新事实追加，不重复全账本；不强制给不可变事实做逆向补丁 |
| World原操作/修订 | World Owner实时状态；历史检查与诊断 | 当前状态参与执行；完整演变通常辅助；恢复/证明所需子集按用途保护 | 原始逻辑事实不变；辅助尽量增量，按成本引入独立基线/快照 |
| Control遍历、Runtime Plan | 原Owner提交/选择/采纳与历史查询 | 承担任务/恢复职责的事实为核心；只读历史不授继续许可 | 最新＋必要变化；保留selection/work/adoption/未决关联 |
| 资源账目 | Driver/Runtime原资源事实、咨询/执行来源末位核对 | 核心；不是单凭余额恢复执行 | 累计列表存在重复保存候选，采用变化与快照须保留来源末位与未决语义 |
| P25咨询journal | reserve/complete/reject，相关性与幂等 | 核心；导出失败不能替换原结算 | 稳定键、输入fingerprint、正式返回值/拒绝原因按原契约保存 |
| 可靠执行journal | Effect Boundary发送前准备、结果、反馈和retry/link关系 | 核心；prepare未确认零发送；发送后故障保留真实回执和未知 | 事实追加，保留发现未决能力，不用快照覆盖未知尝试 |
| 原身份归档、来源位置 | 原Run与各历史/资源源绑定 | 核心关联；不是执行授权 | 完整版本化绑定及可核验来源，不用目录猜身份 |
| Settings覆盖账目 | Ledger/任务buyer供Agent、屏障、overview及结果判定 | 实时判定事实不降为辅助；需要交付的覆盖结论及来源按要求保存 | 当前事件不含全部观察/步骤信息，report也不能由九源默认无损重建 |
| XML/PNG/窗口材料 | 实时使用内存；XML另有evolution-case复现消费 | 视任务证明、复现/交付或诊断用途分别保护 | 独立材料尽量不重复，保留capture关联；不可由EvidenceId猜路径 |
| consultations.json | Host实际上下文/原decision/guarded decision/耗时的诊断报告输入 | 普通导出辅助；若字段成为必交付唯一来源，对该来源额外保护 | 当前列表全量覆写是增量优化候选；正式P25journal不被取代 |
| traversal-recovery.json | 当前只写诊断镜像，未发现正式生产reader | 辅助；不得使原遍历结算失败 | 默认追加或按需镜像，不把文件名当恢复授权 |
| Trace、Settings trace、指标 | 诊断、First-Divergence、报告输入 | 可关闭/有界可丢；完整性要求按请求声明 | 追加/分段；不强制逆向快照；保留缺口/终态说明 |
| runtime-run-events导出、可重建索引/展示 | 来源事实的副本、读取方便 | 验证可重建以后才可按缓存回收 | 来源身份/版本要可查；不假定现存所有投影都能重建 |
| 必交付报告要求/状态及来源 | Host交付要求与本地产物，执行结果之外单独结算 | 要求/必要输入/状态可靠保存；报告不取得Runtime truth | 绑定请求身份、来源版本、生成器版本及产物校验信息；跨重启可查、显式重试 |

## 2. 增量、快照和提交

- 最新是可验证的逻辑版本，不等于每次修改都重写整个大对象。小状态可整条保存；大状态按buyer采用增量，保留可独立读取的基线/快照，并限制需要还原的链。
- 核心可变状态需要保留前/后版本及必要旧值、删除内容、字段/集合顺序；也可通过仍保留的可信基线与变化求得历史，但不能只保存不可逆的新值后声称可从最新版本反推。
- 辅助增量仅承担其读取需求，不为统一格式强制存before-image。日志是事件追加；PNG/XML等独立附件也不强行做跨文件差分。
- 持久化布局可分文件/分段，但最新状态与增量只能通过同一Owner已确认的提交位置发布。缓存更新丢失时可以按可信来源重建；核心提交未知时不能吞错或以陈旧缓存宣称最新。
- 每个快照声明来源身份、schema/数据版本和覆盖位置，跨Owner组合沿已有身份/末位关系验证，不引入全局原子事务。
- 数据还原不重新咨询、入证、reconcile、select或dispatch；反向读取不是业务撤销。
- 旧reader当前要求完整历史/hash/末位；新格式须扩展并验证相应读取契约，不能直接截旧链或放宽原校验。新快照不自动授权删除前缀。

## 3. 失败策略矩阵

| 场景 | 领域行为 | 对外读取/交付 | 关闭/重启 |
|---|---|---|---|
| 核心接受前取消/拒绝 | 不接受新操作，保留原状态 | 不声称提交 | 原未接受操作不因关闭补写为成功 |
| 核心接受后取消、部分写入、确认丢失 | 等待实际结算或保留未确认/未知；不越过后续屏障 | 不发布伪最新，不盲重试 | 新reader依声明故障范围校验；恢复检查不等于自动续跑 |
| 外部动作已发生，后续记录失败 | 保留真实Receipt，阻断不安全后续推进 | 已发生结果与存储故障分别呈现 | 按原未决发现与关联处理，不通过报告生成重发 |
| 辅助关闭/异常/停滞/拥塞 | 不改写正式决策、业务预算或Effect次数 | 标明缺失、丢弃范围或采集失败 | Host有界等待/关闭，暴露未完成项，不能后台无限积压 |
| 加速快照损坏/缺失 | 完整可信原链可用才回退重建 | 明确来源和实际版本 | 不能掩盖原源损坏/末位回滚；唯一恢复依据损坏则不可用 |
| 必交付报告输入/生成/产物验证失败 | 不改写Runtime Outcome | 执行已结束与交付未完成分开；可查原因 | 保存要求和状态，重启后显式重试；必要来源缺失不伪造 |
| 报告产物已落盘但交付确认丢失 | 不重新执行任务 | 核对同一请求/来源/产物后结算，不能凭文件存在判成功 | 同一要求幂等，避免重复交付与不必要重生成 |
| 容量或来源保护配额耗尽 | 核心不丢记录；按接收/提交契约显式拒绝或阻断 | 报告不能无限pin材料却宣称无成本；辅助按策略降级 | 不用自动删核心/待交付来源来掩盖容量不足 |

辅助隔离针对异常传播、等待、队列和资源额度，不承诺消除共享磁盘/CPU的物理争用。辅助缺失可以出现在报告中；报告是否允许不完整，以该交付要求的必需内容为准。

## 4. 保留、回收与维护

| 数据/条件 | 默认保护 | 回收前必须证明 |
|---|---|---|
| 活动任务及恢复所需材料 | 核心最新、必要增量/基线和关联完整 | 不破坏活动/恢复承诺；terminal本身不授权清理 |
| 核心历史 | 承诺保留范围内可正反核查 | 剩余快照与变化仍满足范围；原事实、顺序、身份和比较语义不变 |
| 身份/幂等、未决尝试、结果证明 | 不随展示文件清除 | 重复请求不能变成新执行；未决仍可发现；必要证据引用闭合 |
| 未交付报告要求与来源 | 请求、状态、必要来源受保护 | 只有交付状态/显式终止政策允许释放，不能因重启丢要求 |
| 辅助详细历史 | 近期详细，较旧按配置保留摘要/阶段信息 | 范围明确；保护引用无缺损；读者知道不能逐步还原的区间 |
| 可重建副本 | 可按明确策略回收 | 已验证稳定来源、版本及重建路径；不是仅凭命名判缓存 |
| 策略/期限未配置 | 不启用破坏性自动删除 | 后续提供明确配置和保护条件，不自行假设天数 |

维护清单只引用领域契约和Host配置唯一源，包含Owner、用途、初始化/关闭、提交边界、故障范围、数量/字节/等待限额、保留/删除条件、重建方式与兼容版本。清单是索引，不复制参数默认值或创建第二注册中心。

## 5. Interface职责与实施边界

| 职责 | 调用方需要知道 | 不能承担 |
|---|---|---|
| 领域提交 | 原Owner语义、确认位置、错误/未知结果、取消、顺序/幂等 | 改判业务事实、通用CRUD、跨Owner事务 |
| 最新/历史查询 | 来源身份、数据版本、覆盖范围、一致性位置和不可用原因 | 执行授权、通过观察面继续任务、假定跨来源原子一致 |
| 辅助采集/导出 | 可选性、缺口、限额、失败和关闭结果 | 使用可丢规则保存关键恢复记录；异常回流为正式咨询失败 |
| 报告交付 | 要求、来源与版本、必需内容、当前状态、失败原因、幂等重试 | Runtime Outcome改写、自动Agent/Effect重执行、远程发送 |
| Host资源与维护 | App/Project/Run/操作作用域、介质/配置、关闭、回收保护 | 接管领域初始化语义，绕过Owner直接造提交事实 |

实现先切断observer/Host输出与正式结算的错误耦合，并建立必需来源的可靠保护；再按真实消费方理顺生产async与兼容层、读写查询及资源归属；最后用增长型核心账目/World等buyer验证最新＋增量/快照和回收。具体垂直切片进入PLAN时落`plans/`，本文件不派工、不进入IMPLEMENT。
