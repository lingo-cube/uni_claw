# 必交付确定性报告：第二片契约

需求与验收以state.md A6及已确认Decisions为准。本片首个生成器是现有run-report；覆盖账目等原Owner结果仍保持原保存路径，不因本片变成诊断。交付指可校验、可读取的本地产物，不是远程发送或用户阅读确认。

## 公开职责
- `RequiredReportDelivery`属于Host报告交付域，引用任务/来源但不改Runtime Outcome，不持有Agent、Effect或任务续跑接口。
- Accept可靠接受要求并保存生成器内容/版本；Prepare绑定稳定来源并保存生成器实际消费的字节/缺失声明；Publish仅执行固定生成器、校验并发布产物；Confirm验证可读取后结算Delivered。Inspect/List只读，跨重启可发现尚未交付要求。
- 同一OwnerRef+RequestId为同一要求，异要求冲突，重复读取/确认不生成新任务或重复报告。新的报告版本须显式使用新的RequestId。
- 普通legacy工具调用仍兼容；显式必交付调用使用新流程。Runtime HTTP启动显式RequireReport时先接受要求再激活；默认普通报告行为不隐式扩大成新任务准入条件。手工请求run-report作为明确交付请求处理。

## 来源与生成器
- 输入清单和版本由生成器`--describe-inputs`唯一声明，Host不复制固定文件名列表；生成器原默认/strict行为保持，`--source-label`只保留原来源展示身份。
- 非strict交付至少需要facts，其他缺失按原报告的availability语义表达；strict沿原STRICT_REQUIRED。不把没有执行结果的空报告判作满足必交付要求。
- 要求接受时保留生成器原字节及SHA；输入固定后记录每份原材料的名称、原字节SHA/大小、可选材料缺失及整体来源fingerprint。后续生成只读私有不可变输入，不从已变化/已删除原目录猜测内容。
- 输入固定要求来自已停止写入的Run产物集；逐文件实际hash与完整性检查不宣称跨Owner全局原子快照。输入尚未固定时不能声称可离线生成；丢失材料明确待输入/失败，不重跑任务补材料。
- Runtime要求固定来源前核验facts中的RunId，固定后生成前再次核验私有输入身份；手工artifact-set要求绑定原目录名。别的Run或目录不能满足同一要求。
- 必交付要求/来源/已发布报告在本片不自动清理。大小/单任务额度、生成等待和未完成操作都受明确限制；容量不足显式失败，不删关键来源腾空间。

## 状态、确认和重启
`AwaitingInputs → Ready → Generating → Published → Delivered`；输入/生成/验证失败可有Failed，保留要求、已固定来源与原因。恢复读取不把Generating当成功；重新取得单writer租约后可以报告级重试。

- 要求、来源目录发布和状态各有真实确认点，正常成功均在声明的本机进程终止范围可重新读取后返回。接受后取消须完成正在确认的写入，不伪装未接受。
- 发布的产物有来源/生成器绑定和逐文件校验，文件存在本身不是成功。Published后确认丢失可在新Host核验并Confirm，不必再次运行生成器。
- Delivered是历史交付事实，读取仍另报当前产物可读性；损坏/缺失不能仅凭缓存状态返回可读取成功。
- 非合作生成器超时不能释放租约并允许无限并发重试；未结束操作保留所有权、限制新接收并暴露原因。生产只注入现有确定性脚本进程，取消会结束该进程，不调用产品模型。
- 实际Python进程自身持有每交付的OS锁，Host单独终止不释放此锁；遗留生成器仍运行时，新Host报告级重试显式busy，不执行第二个生成器本体。Host正常关闭追踪已有Runtime后台任务，有界等待；报告进程另有有界取消/等待，仍未确认的Run/交付操作引用明确输出。

## 测试与边界
已确认测试缝：Host公开要求/Prepare/Publish/Confirm/Inspect、RuntimeToolHost真实脚本入口、HTTP交付查询/重试接线。先一项行为RED，再逐条覆盖重开、原目录删除后重试、缺源/错hash、重复发布/确认、失败/取消/并发和真实子进程Kill窗口。

不建立通用任务队列/WAL/数据库，不新增报告种类或模型过程，不改现有核心提交边界，不借报告重试重发Effect。完整核心最新/逆向增量及辅助保留回收是后续切片，本片不冒报这些完成。
