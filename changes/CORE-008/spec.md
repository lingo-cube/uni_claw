# CORE-008 — Attempt/Trace 边界与跨领域 Slice 语义修订

## Problem Statement

CORE-007 已锁定最小候选基线并完成 UI 首版投影，但 Attempt 与 Trace 的职责边界、以及
Slice 是否为 UI 专用的表述仍可能引起误解。需要修订指南，不把 Attempt 简化为诊断 Trace
的别名，也不把 Slice 限定为视觉页面切片。

## Solution

- 保留 Attempt 作为某个 Effect 的一次有产品含义的执行尝试记录；它可以直接保存，也可以
  从满足完整性、历史留存和恢复要求的执行源记录生成。
- 普通诊断 Trace 不自动成为 Attempt 的唯一依据；Trace 与 Runtime 可以引用同一执行关联，
  但不得形成两套可独立改写、互相冲突的尝试事实。
- 发送前必须能可靠登记当次请求、绑定和尝试关联；该登记表示准备信息已留存，不表示请求
  已经发送；发送、回执、外部执行和结果仍分开表达。
- Slice 定义为 Segment 在明确来源版本、观察时间、范围和解释规则下的局部观察或派生表示，
  可用于 UI、机器人、文件、API 和数据库等领域。
- 来源、被观察对象、局部范围、原始观察时间和处理版本分开保存；历史用途不得回退当前查询
  或当前处理结果。

## Acceptance

1. 指南明确区分 Attempt 语义、执行记录产生方式、存储/投影方式。
2. 指南明确 Trace 的诊断契约不能替代恢复所需的完整执行依据。
3. 指南明确 Slice 跨领域且不等于视觉区域；保留历史时间与处理版本区别。
4. 不新增第二事实权威，不修改 Runtime/Trace 实现，不冻结存储方案。
5. 指南记录“关闭诊断 Trace 后仍能否恢复尝试依据”的验证问题，并标记为待验证。

## Out of Scope

- 直接实现 Attempt 持久化或 Trace 迁移。
- 决定 Runtime 是否复用现有 Trace 存储。
- 新增 Event、Expectation、Verification 或其他 Core 顶层记录。
- 为机器人、文件或 API 预先冻结具体字段或继承树。
