# UniClaw产品执行Plan：Harness研究与Grill收敛方案

状态：设计定稿；2026-10-18 Owner新增实施授权后进入实现，进展与验证以state.md及evidence/runtime-plan-001为准。2026-10-18。Owner在Q1-Q9、业界复审及现有代码检查/人话应用说明后回复“好继续”，确认将五项改进合入当前方案。架构取舍见[ADR-0053](../../docs/adr/0053-composable-product-plan-with-bounded-local-execution.md)，决定索引见[state.md](state.md)，后续实现步骤见[实施计划](../../plans/runtime-plan-001.md)。本文规定目标行为，不单独证明当前运行能力；正式协议、源码及现场验收按实施证据逐项确认。

## 1. 要解决的问题

Owner在第一轮grill明确：引入Plan首先是让产品具有泛化执行能力，降低每一步请求Agent带来的延迟和成本；采用产品级机制，在不同场景上细化策略/规则。阶段预期和进度可见性是支撑要求，不能取代这一目的。本文已据此调整原“阶段规划可追踪优先”的推荐。

本次问题不是单纯增加一种JSON类型。需要确定Agent怎样表达目标和策略，Runtime怎样依据当前事实展开成下一步动作、验证和继续，以及何种未知需要交回Agent；它们须与ADR-0052的overview、事项和续额复核关联。既要验证少调用Agent能否降低实际延迟与成本，也要验证同等目标、权限和证据要求仍然成立；不能只验证模型输出了Plan文本。

研究对象是通用Agent Harness的产品执行机制；开发侧UniFlow、Leader开发Plan和WorkItem只约束如何实现产品，不成为产品规划器。

## 2. 五种容易混淆的东西

| 概念 | 作用 | 不能据此认定 |
|---|---|---|
| 方向/阶段计划 | 说明目标、当前分支、下一检查点及预期证据，可保留未知 | 已生成全部可执行动作，或阶段已达成 |
| Todo/任务清单 | 展示工作分解、状态和注意力焦点 | 自动具有依赖求解、执行许可或完成证明 |
| Plan Mode | 人与Agent探索、讨论或审阅方案的工作模式 | 已安装typed Runtime执行计划或新执行权威 |
| 产品执行Plan | Agent组合具体步骤及已声明语义内的有界规则，Runtime依据当前事实逐步展开 | 可以用旧坐标、未来未知控件或一次授权覆盖所有步骤 |
| Act/工具循环 | 根据当前事实选择动作，取得结果后继续决策 | 没有进行规划；Act这个名字也不天然表示只能有一个步骤 |

此处为讨论用区分，不改写CONTEXT中开发Plan、Adaptive Planning或Agent Strategy State的已接受含义。

## 5. 已确定的方向与取舍

产品执行Plan让Agent表达“怎么推进这一段”，Runtime在明确语义内根据新事实展开，减少逐动作完整决策；不能仅展示计划文本。方向层允许粗阶段和未知，执行层使用具体步骤或可判定规则。Settings为首个真实买方，场景细化规则与限制，共同执行核心保持可替换。

| 选择 | 结论及理由 |
|---|---|
| 阶段意图＋逐步Act | 保留作性能对照；可改善目标保持，但不足以满足减少逐动作咨询的主要目标 |
| 阶段意图＋固定短Plan | 作为已知路径的一种形态；不足以覆盖运行时才出现的入口集合 |
| 具体步骤＋可组合有界规则 | 采用；Agent组合产品已有语义，Runtime本地选择、展开、验证，语义缺口再回Agent |
| 强制先生成完整动作树 | 不采用；未知页面无法可靠预编，容易猜目标或因正常发现频繁重规划 |
| 任意模型生成代码或扩展现有Policy为自由DSL | 不采用；不能逐项执法、授权及验证，且违反既有封闭协议边界 |

再次咨询按事件和阶段检查点触发：已有规则能覆盖的新页面/入口继续本地处理；计划内补证或恢复仍无解、需要新语义推断/策略调整、阶段评估、预算复核时回Agent。每步观察、语义策略、grounding、权限和结果验证保留。

首次交付覆盖同一运行实例内暂停、咨询、复核和修订后的继续，保留可审计证据；跨进程崩溃重启自动恢复另行设计。真实Settings与结构不同的仿真任务共同检验复用，性能与同条件逐步咨询基线实测，不先编造改善百分比。

## 6. 共同机制：有界展开，复用单一执行链

以下为依据D1-D10收敛的首版工程方案。规定可观察行为和职责，具体字段由实现买方验证；不建立新的计划平台。

### 6.1 输入及职责

一份可采纳Plan应能关联同一Run/生效Contract、阶段目标和依据、操作及条件、检查点/局部工作界限，以及调整理由。自然语言解释供Agent与人理解；实际执行只消费可校验的结构。全任务目标或授权范围的变化仍走既有Contract机制，不能用Plan修订实现。

同一份Plan区分两层内容：阶段预期说明这一段要取得什么证明、覆盖什么范围、何时评估；当前可执行段说明依据现有事实能够执行的步骤或规则。未来未知可保留为事项/范围，不预编动作树。符合已采纳规则的新入口继续本地处理，不因一段具体步骤较短就每页咨询Agent。前瞻范围、局部展开工作量及Run资源账本分别约束“承诺做到哪里”“本次机械展开做了多少工作”“实际资源授权”，不得混成一个通用步数顶。

| Owner | 输入与输出 | 权威边界 |
|---|---|---|
| UniAgent | 基于目标、同源overview和支持的操作，提出Plan或修订与理由 | 语义规划与方向判断；不直接写执行结果或扩大许可 |
| 场景规则提供方 | 将现有Owner事实投影为typed候选/条件，提供确定的选择、预期与语义动作校验 | 场景判据；不持有执行循环，不自行点击或授额 |
| Runtime / KernelRunDriver | 校验并记录采纳版本，展开下一操作，记录结果，在合法边界继续或咨询 | 唯一Run推进；使用已有Control/执行/验证链 |
| World、任务事实Owner、Assurance/Effect、预算Owner | 提供图belief、事项及证明、许可/结果与资源事实 | 各自原有权威；Plan记录及overview不能替代它们 |

场景缝提供的是可复用操作/条件的含义与参数限制，而非每个任务一份完整脚本。Agent选择、组合及参数化。比如“安全导航入口”的判断由Settings规则提供，Agent决定本阶段检查哪个范围、何时评估及如何处理可判定分支。核心不包含“Wi-Fi/显示”等菜单名。

### 6.2 首版最小语义与外露范围

首版以具体步骤、当前候选绑定/有界迭代及检查点组成最小表达；观察、单步动作和有限条件为其必要内容。下表列出要实现的行为，不要求将每项做成独立公开节点或允许任意嵌套。仅加入Settings与结构不同的仿真买方实际使用的组合；通用递归、任意表达式/跳转、通用DAG调度和在线生成代码技能不纳入。Agent可组合这些操作，各场景只提供语义判据，不封装一个“遍历整个Settings”的固定完整流程冒充泛化。

| 组合能力 | 行为与限制 |
|---|---|
| 有序段 | 按序展开下一操作；可表达已知多步路径，仍逐步重新定位与验证 |
| 观察 | 通过现有观察控制取得指定范围/深度的事实；缺失信息保留未知，重复观察计费且有界 |
| 单步动作及验证预期 | 描述语义目标、Effect类及结果预期；物化后每次通过既有动作链，不能携带未来坐标或永久绑定旧occurrence |
| 条件分支 | 使用已声明typed谓词；满足/不满足/未知分开处理。未知不选择可执行动作分支；补证只沿既有Control允许的有界观察路径，无法消除则暂停咨询 |
| 候选集合选择 | 从当前Owner投影按规则筛选/排序，绑定本次事项及语义目标；每轮重新读取，已处理/受阻状态由事实Owner提供，不凭Plan自身标记判定 |
| 有界重复 | 对候选或条件重复一段操作；结构有限、无任意跳转/动态代码，受局部展开工作量、动作资源及检查点约束 |
| 检查点/控制 | 在声明的阶段评估、语义缺口、复核或停止条件处让出；局部段结束不自动宣布全任务完成 |

这是组合所需的语义集合，不要求每一行变成一个公开类型或Capability。精确字段与复用现有类型的范围，以Settings与仿真两种买方形状的验证为依据。新操作或谓词必须有提供方、输入输出、未知语义及参数执法；未声明的名称不从自然语言猜实现。

集合筛选条件针对任务事实的typed属性与已支持关系，不是UI定位selector，不携带设备locator/occurrence。选择返回事项来源/稳定键和语义描述，执行时再定位当前真实对象。世界图可帮助找已知路径，图中的边或Agent列出的事项不能自动证明当前可达、已授权或已完成。当前候选为空只是一次集合结果；若仍有规则支持的滚动/展开等探索路径则继续，无法证明范围已满足则报告未知。

### 6.3 每轮推进

```text
Agent提出Plan → 校验表达/范围/支持语义 → 记录采纳版本
  → 读取当前事实，检查适用条件、资源与中断
  → 选择/展开一个操作
  → 若是动作：当前场景语义校验 → 既有Control/grounding/binding/Assurance/gate/dispatch → verify
  → 由既有Owner更新观察、事项及证明；Runtime记录本次执行位置和结果
  → 条件仍可判定且未到检查点：继续展开
  → 语义缺口、阶段评估、预算复核或无法局部恢复：保留位置与事实，回同一Agent咨询链
```

场景校验须使用当前事实并处于发出Effect前的合法链路，不能仅在咨询返回时用旧页面检查整个Plan。任何中断都要遵守现有在途动作屏障：已发出的动作先取得结果并对账；没有新许可时不再发下一Effect。精确插入点由现有grounding上下文与场景买方共同验证，不能绕过Control权威。

观察、选择与控制转移也计入局部展开工作量，防止“没有Effect所以不消耗步数”的空转。局部配额到达检查点即让出，不自动复位；续行须有当前事实/规则支持并接受现有资源检查。局部有界不恢复未经任务标定的全Run 256步上限，也不声称语义复核保证全局必然终止。

### 6.4 操作结果与下一步

每种可组合操作必须说明作用范围、相关事实依赖、适用前提、预期结果/证据、可暂停位置及错误出口。下表为既有Owner事实与执行记录的消费规则，不新增canonical Run状态机或共享success布尔值。

| 观察到的情况 | 下一步 | 禁止误读 |
|---|---|---|
| 前提有证据证明不成立，动作未发出 | 仅按已声明的合法备选/跳过规则处理；没有则回Agent | 不算动作执行失败或事项完成 |
| 必须的许可/动作条件未知或冲突 | 不选中动作，沿既有decision边界回Agent | 不将未知当false；不借Plan绕过Policy/Package的Guard Unknown出口 |
| 计划明确先观察，或既有Control合法定向复查 | 经既有观察路径补证，随后重新判断；工作量与调用计费 | 不是给失效Guard新增隐式fallback |
| 动作已发出，结果或验证仍在等待 | 保留同一次尝试，取得结果并对账 | 不再dispatch同一动作，不推断“暂停已撤销现实动作” |
| 本次操作结果已验证满足 | 记录本次尝试及证据，按规则继续 | 不自动证明整项任务/子树完成 |
| 结果已对账但未满足，或事项受阻 | 保留证据；现有事实/规则足以安全恢复或处理另一项时才继续，否则咨询 | 不在现实结果未明时强行重试，不抹掉失败 |
| 到阶段/工作量/预算检查点 | 在合法边界保留位置，进入评估/复核 | 不因让出而重置资源、默认授额或宣布完成 |

Runtime只机械求值已声明规则；新的目标解释、规则合成及语义方向判断归Agent。每次动作仍需Control签发意图。新的规则/恢复语义若需要修改已接受架构而不只是扩展Plan契约，应停止该项实现并明确裁决。

## 7. 用手机菜单遍历校准

目标是“在允许范围内检查菜单并保留证据”，并非预先知道整棵树。可采用下述组合；这是解释性流程，不是新脚本语言。

1. Agent先确定阶段预期，例如处理当前根页已发现且允许访问的一级入口；把可观察的结束条件、补证/探索规则及下一阶段评估点带入Plan。剩余待办可以是集合/范围描述，不要求逐项预知。
2. Runtime从当前候选和任务事实选择未处理的安全导航入口；当前页面重新定位、语义校验并执行进入，随后观察与验证。
3. 子页若仍满足同一导航/观察规则，就继续展开；正常进入新页面本身不请求完整Agent。需要未知语义判断，例如不能判明控件是否属于允许操作，才在规则内补证或回Agent。
4. 记录页面证据与事项结果；完成本段所要求的观察后，经逐步验证的返回路径处理其他入口。不能把“进入过子页”当成“子树全部完成”。若允许范围只含一级检查，也不能擅自把范围扩大成递归全树。
5. 滚动发现新入口时沿用稳定事项身份并更新当前候选；不能把队列暂空当穷尽。局部不可达事项保留受阻原因，有可判定的其他路径则继续，当前上下文无法安全返回/换路才暂停。
6. 阶段检查点或预算阈值到来，对照阶段原预期、已验证成果、剩余事项/未知及下一路径判断继续、调整、取证或结束。Plan耗尽或本段完成均不签发全任务完成证明。

同一规则并不保证适用于所有控件。安全导航、读取信息与修改状态有不同授权和验证要求；不把一次导航样例推广为开关/危险操作已支持。

## 8. 记录、修订、复核与恢复

Runtime记录实际采纳的Plan版本、执行位置、规则展开的事项/迭代、每次实际尝试与结果、中断原因及相关咨询。它们是运行证据及其只读投影，不能再造独立Run生命周期。至少区分“计划节点”和“本次展开/尝试”：循环重用同一节点、失败重试、版本替换后，实际动作/receipt与完成锚点仍必须唯一关联，不能继续单靠固定planItemIndex假设全程唯一。

| 事件 | 剩余Plan与版本 | 历史及资源 |
|---|---|---|
| 正常反馈/规则覆盖的新入口 | 同版本继续，以新事实展开下一操作 | 追加实际结果，保留稳定事项身份 |
| 仅咨询/暂歇，未改内容 | 核对当前事实、权限与适用性后同版本续行 | 咨询及动作计入原账本 |
| 预算复核，仅获续授 | 在对账后保存位置进入NeedDecision；获授且仍适用才续行 | 复用ADR-0052同源overview/明确复核/逐笔授额，不复制成果或重置消耗 |
| 需要修改执行内容 | Agent给新版本，在当前动作完成/失败并对账后替换未执行部分 | 保留旧版本、已做工作、失败、花费及调整原因，不自动从头重做 |
| 复核要求Replan或内容无效 | 不能仅凭Replan结论执行；须取得并采纳可执行的新提案 | 原有事实不变；无有效提案时不产生新Effect |
| 同一实例内恢复 | 从已对账位置重检后继续；适用性无法恢复则咨询 | 不重发已确认动作；在途动作遵守原屏障 |
| 进程崩溃/重启 | 首版不承诺自动恢复执行 | 保存的咨询/Plan证据供诊断；不是安全重放在途Effect的依据 |

跨overview需能看到阶段预期、版本/修订理由、上次检查点之后的已验证成果、当前位置、已知剩余/未知、暂停或复核原因，以及下一段依据。历史可压缩为有来源的摘要；不反复搬运全量指令或完整历史。模型能力/操作语义按既有首次Run声明及引用纪律提供，不借Plan让每轮都重复注入整份清单。

复核结果须明确区分“沿用当前采纳版本继续”“采纳修订”“改为另一个单步提案”及“暂不行动”。授额通过本身不选择下一动作；续行须引用当前版本/位置并重检适用性。不得偷偷把既有NoAction含义改成“继续旧Plan”，也不得将新Act隐式插入旧规则。准确载荷在正式通道实现时收敛，仍走同一咨询/采纳链。

overview沿用现有预期/实际、事项、成果键、未知、阻碍及复核历史，补上当前Plan关联即可；不另建进度数据库。优先展示目标相关的已验证成果、新发现范围、有证据排除的路径/假设及下段依据。处理2项又发现5项可能使待办增多，不能据此判退步；新增无关日志/旧事实重现也不能支持续额。范围未知时不显示虚假的总体完成百分比。

最小场景缝要能表达两类职责：一是基于当前Owner投影求值条件、选择候选并报告来源/未知原因，二是对当前物化动作作语义校验。是否复用既有delegate或需要收敛接口，由Settings及仿真买方共同验证；不在研究稿提前冻结通用注册中心或插件协议。

**现有Policy保持原有语义**：封闭谓词、固定ActionTemplate、独立局部租约及未知失效。新Plan组合不能偷塞到Policy字符串中，不让match推导隐藏动作目标。可复用三态判定和既有执行机制，不能把Policy当通用UI脚本执行器。AGT-009当时只冻结线性Plan及wire范围，本方案须用新决定明确扩展其PlanItem/校验上限含义、展开良基、完成锚点、失效/续行与wire范围（原决定1/2/7-10/13），不能重写旧验收历史。

[架构基线§24.2](../../docs/architecture/product-architecture-baseline-l0-l3.md)关于单一驱动、Control意图权威、advisory提案及每动作完整链保持；不借Plan扩展去开放完整Decision Package/任意循环通道。既有Policy已实现的有限子集及其Guard失效出口保持。未知不能选中动作，补证只沿既有Control合法路径；新规则不能自行创造Tactical Hypothesis。相关取舍已记录于[ADR-0053](../../docs/adr/0053-composable-product-plan-with-bounded-local-execution.md)，接口扩展和运行执法尚待实现，不能以adapter绕行代替协议更新。

实现先完成一条小的动态遍历：正式Plan通道、逐步场景guard、发现/处理多个候选、一个局部阻碍、检查点/续额后原位继续。已知多步是该切片的基础，不能单独作为主要目标达成。随后补齐修订/失败/未知边界、以不同结构仿真检查同一核心，最后进行真实三组对照。具体修改面与验证顺序见[实施计划](../../plans/runtime-plan-001.md)。共享dirty工作区的既有修改持续保留。

## 10. 后续实现的验收设计

以下是已确认的验收方向及Leader收敛的可判定场景；当前未运行。样本规模及性能数值门槛在实现前按测得的基线确定，不能用没有标定的百分比作证明。

| 方法/场景 | 期望行为 | 必须保存的实际证据 |
|---|---|---|
| 正式通道＋真实Settings已知多步路径 | 一次Plan决策可完成有意义的多步段；每步当前语义guard/定位/验证有效 | 正式模型提案、执行序列、逐步结果、全部调用及花费 |
| 真实Settings动态候选 | 新入口在规则适用时本地处理，未知不当不满足；空候选不冒充全树完成 | 新发现、事项来源、展开记录、剩余/未知与任务证明 |
| 局部阻碍及偏差注入 | 保留受阻事实；规则可覆盖的其他路径继续，无法安全判断才咨询 | 原预期、首个偏差、恢复/换路或回Agent原因 |
| Plan中途续额 | 接近阈值即在合法边界复核；批准后同一版本/位置继续，拒绝后无新Effect | 跨复核overview、授额与消耗、位置及receipt连续性 |
| 修订＋同实例续行 | 已确认动作不重发；新版本只替换未执行部分；不清空旧失败/预算 | 版本差异、合法替换边界、唯一尝试/完成锚点 |
| 无Effect的空转/反复未知 | 消耗本地展开工作量，到检查点让出；未知不触发无限自动补证 | 展开计数、资源及回Agent原因，无非法Effect |
| 结构不同的确定性仿真 | 例如记录核验：读取记录→按typed状态选择→必要补证→核验/受阻分支；无页面树与导航。替换场景事实/能力后，同一Plan组合与执行核心通过，不加入场景特判 | 同一核心版本、仿真输入输出及每步结果；明确为仿真证据 |
| 同条件逐步Agent对照 | 相同目标/权限/验证要求下，两类代表段减少完整决策调用；实际时延/成本收益可核实 | 基线与Plan组的范围/初态/模型、决策及其他模型/慢感知调用、token/费用、端到端时延、动作数、达成与失败结果 |

性能对照明确为三组：逐步Agent、固定已知短Plan、动态规则Plan；同等目标、权限、初态及观察/验证要求下比较，结果判定允许不同合法路径。补记正式模型提案有效率、纠正/重规划以及全部失败运行的消耗；关键样例重复并报告样本量和差异，不只挑成功轨迹。数值门槛在读取基线后、比较新方案结果前写入验收记录，避免看到收益后倒定标准。

性能不能只数Planner调用；局部模型、慢感知、重规划、失败及Prompt增长均计入。同一任务状态可变导致不能直接复现时，先记录差异或使用可复位输入，不能把不同范围的结果直接比较。若完整决策下降但总成本/时延未改善，须如实定位主因，不宣称主要收益已验证。仿真证明复用，不证明第二类真实设备/应用适用；真实Settings小范围段也不冒充全遍历完成。

## 12. 业界设计复审：保留方向，收紧首版表达并补执行契约

2026-10-18追加审查，保留当时建议措辞及来源理由。Owner在代码核对/应用说明后回复“好继续”，五项已合入§6-10并记录D10，不推翻D1-D9。新增外部机制对照见[独立研究笔记](../../docs/research/runtime-plan-design-review-20261018.md)；本节不表示源码或正式协议已完成扩展。

### R1：显式区分粗阶段与当前可执行段，按反馈逐段展开

原文允许上层粗阶段，但同一Plan同时承担整个方向与可执行组合，容易让模型一次生成过长规则树。建议同一份计划记录中区分“阶段预期/范围/检查点”和“当前可执行内容”；未来未知只保留事项或待判定分支。已知路径可一次展开较多步，未知部分只展开到当前事实足以支持的位置，长度由适用条件与检查点决定，不另设通用固定步数。

新页面若符合已采纳规则仍然本地继续；只有执行依据不足或到检查点才咨询。因此这不是每到一页重新Plan，也不增加另一套计划Owner。[LangGraph](https://www.langchain.com/blog/planning-agents)支持Planner/Executor/Replanner分工；[Inner Monologue作者项目](https://inner-monologue.github.io/)展示具身任务中反馈促成修订。它们不直接证明UI无模型展开有效，这一迁移仍需本项目验证。

### R2：首版外露少量高价值组合，避免让模型编写通用流程语言

§6.2七类能力是行为需求，不宜一次变成任意嵌套、任意变量/跳转的通用语法。建议先用实际买方证明“具体步骤＋当前候选绑定/有界迭代＋检查点”所需的最小组合；条件只使用已声明谓词，局部补证/结果处理尽量在有清晰输入输出的既有操作中表达。没有买方证明的通用递归、任意表达式、HTN搜索与通用DAG调度延期。

这不把任务写死为Settings流程：操作、条件及集合参数仍由Agent按目标组合，Settings仅提供其事实/语义；普通Act可处理尚不适合复用规则的一步。也不先封装一个“完成所有Settings遍历”的巨型操作来伪造泛化。语义可复用与模型易用性须一起验证：正式模型能否正确选操作、填参数、解释错误，比Schema通过本身更关键。

[Anthropic工具设计实践](https://www.anthropic.com/engineering/writing-tools-for-agents)建议少量清晰、针对实际任务的工具，可在内部合并多项操作，并通过真实调用评估接口。其[Agent设计文章](https://www.anthropic.com/engineering/building-effective-agents)强调从简单组合开始；这是设计原则而非性能保证。

### R3：补齐操作的适用、结果与续行语义，分清条件未知和执行中

原文已规定版本/位置和逐步校验，但每种局部操作怎样结束、失败或续行还不够明确。建议每个可组合操作声明：作用范围及相关事实依赖、适用前提、结果/证据判据、合法暂停位置与错误出口。引用语义事实和任务事项，不永久绑定设备定位信息。

至少分开以下情况：条件满足/不满足/未知是事实求值；动作尚未开始/在途/已对账是执行阶段；本段完成/受阻/需要语义判断是推进结果。它们不能共用一个success布尔值，也不需要为此新增canonical Run状态机。依赖条件变化时重检，已确认动作不重发；动作在途时继续收结果，不能把再次调度当重新dispatch。

尤其要消除§6.2“未知后补证”的歧义：先前声明的Observe或既有Control合法复查可补证；**现有Policy/Decision Package要求Guard Unknown回Agent的出口保持，不得被新Plan包装为本地fallback继续动作**。新Plan条件无法判断时不能选中动作分支。若以后确需改变此语义，必须单独显式决策，不能借减少咨询绕过。

[BehaviorTree.CPP的Sequence文档](https://behaviortree.dev/docs/nodes-library/SequenceNode/)分别提供记住已成功节点与重检条件的组合；其异步节点另有RUNNING及halt生命周期。可借鉴这些区别，不直接安装BT引擎或复制“停止即现实动作已撤销”的假设：UniClaw仍遵守在途Effect串行对账屏障。

### R4：overview明确报告“目标相关变化”，不能用待办净减少作为进度

原文已有预期/结果/剩余，建议把每个检查点后的变化进一步对应到：本段原预期、实际取得的目标相关证明、新发现的范围、已排除且有证据的路径/假设、受阻与未知、下一段事项及依据。数据沿用ADR-0052事项/稳定成果键和Owner投影，不另造进度数据库、通用百分比或Kernel语义评分器。

例如已知10个入口，处理2个又发现5个，待办从10变13，仍可能在正确推进。反之反复返回根页或制造新Plan版本，即使有新日志也不代表新成果。新发现也只有与目标及下一事项相关才有推进价值，不能因为“新事实数量增加”自动授额。范围未知时不显示虚假的总体完成百分比。

[Inner Monologue](https://inner-monologue.github.io/)为使用环境/成功反馈修订提供依据；目标相关性、事项及已用于授额成果的判定纪律以本地[ADR-0052](../../docs/adr/0052-goal-directed-budget-review-and-continuation.md)为权威，不是业界论文能替代的决定。这里主要补Plan与既有overview的连接，而非重做续额机制。

### R5：先验证动态展开的关键假设，再用三组对照定位收益

建议第一个贯穿切片即包含一个小的动态候选集合：发现新项、处理多项、一个局部受阻、检查点/续额后继续。正式wire及已知多步是所需基础，但只跑通线性Plan不能证明本Change最关键的规则展开与泛化；不应在完成庞大语言后才验证此假设。

性能比较保留三组：逐步Agent、已知短Plan、规则Plan。前两组回答批量步骤是否已经足够，第三组回答动态规则是否值得其复杂度。各组保持目标、权限、观察/验证与初态可比，按实际结果判断，不把某一种点击路径写死为唯一正确答案。

除总调用/时延/token/费用外，补上正式模型提案有效率、错误提案纠正/失败重规划及全部失败运行消耗；不能只挑成功轨迹或用截断任务获得低成本。关键样例重复运行并报告差异/样本量；少量结果只支持初步判断，不承诺统计显著性。禁止为了降低Agent调用而隐藏慢感知或把每步判断转移给另一个未计费模型。

[Anthropic评测实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)强调真实环境结果、重复试验、初态隔离和避免过度约束合法路径；本项目具体门槛仍由基线标定。首版不用先建通用评测平台，复用现有场景、journal和证据链即可。

### 复审结论

建议保留“Agent组合有界规则、Kernel单链逐步执行、事件/检查点咨询、同源overview续额”的方向。优先采纳R1-R3以降低表达与执行歧义，R4连接已有ADR-0052，R5调整验证顺序并检验是否确有成本收益。暂不引入完整行为树/HTN/PDDL平台、并行UI Effect或跨进程自动恢复。此结论是文档设计审查，尚无新增运行/性能实测。
