# Grill 第12轮：完成条件、Recovery与handler判断职责

日期：2026-10-19。Owner已逐项回应Q17-Q19；以本轮修正早前推荐中的责任扩大。仅文档，未实现产品。

## 原问题及Owner答复

- Q17原推荐：范围内应处理项完成、发现结束有依据、排除与未知/深度截断均报告；发现不足不声称全覆盖。Owner接受，并提出后续支持结果校验Capability。
- Q18原举例把“动作成功、检查不符合”直接连接到暂停/恢复。Owner明确：不是所有不符合都暂停，例如语音不对只是记录；如何恢复由Recovery考虑。
- Q19原推荐要求统一关联元素/操作/观察版本/字段/规则版本并统一判定重检。Owner明确：如何认定已检查由各能力handler逻辑决定；Kernel负责将对应handlers执行。

## 已接受D17-D19

### 完成与结果校验

Q17接受。Traversal交付限定范围的执行报告；未来有真实买方时，可复用或引入结果校验Capability，按其typed协议返回校验结果。不因为该扩展方向就宣称能力已存在，或让它越过原Goal/Assurance终局链。

### 检查不符合、调用失败、恢复分开

语言/语音不对是领域检查结果，不意味着能力未成功执行；可以“检查调用完成、发现不符合、记录并继续”。只有明确声明的必需继续条件不满足，才按D15暂停。

能力无法调用、执行异常、取消或结果未知属于执行状态，不能假报已执行。现有D12与安全/在途规则继续适用。需要Recovery时由Recovery职责处理，Kernel提供位置、调用状态、结果、已发生动作及消耗等事实；本轮不设计重试/回退/修复算法，不另建Recovery执行器。

### handler定义领域结论，Kernel提供执行机制

handler对应能力协议定义它需要哪些输入、检查覆盖、完成/通过/未知含义及结果有效性。Kernel只校验绑定/协议、时机、顺序和通用边界，调用后保存执行状态及typed结果，按已声明流程信号协调。

这不要求Kernel理解语音正确性、语言规则或“元素是否已检查”的统一算法，也不要求所有能力复制Q19原字段列表。能力所需目标/观察关联仍经显式typed输入提供；Kernel不可替换目标、伪造能力结果或绕过原独立动作验证。

## 推导结论的修订

- K4改为能力协议的输入/输出与领域判据义务；Kernel承担调用和结果关联，不承担领域检查算法。
- K5改为与Recovery的执行事实交接义务；恢复策略由Recovery承担，Traversal不内置统一恢复策略。
- K1/K2的发现/去重仍是遍历算法义务；Q17确定语义标准，不因此宣称已有实现证明。
- K8可由后续结果校验能力辅助，原终局权威保持。

原D1-D16推导与有限模型是历史分析证据，不重标为D17-D19已实现证明。本轮只校验当前文档与职责一致性。
