# Grill 第4轮：Traversal的执行输入

日期：2026-10-19。状态：Owner对修订Q4回复“按推荐”，已记录D4；原四类表仅为信息分类，不作为四个外部入参。

## 已定前提

遍历图不含任务进度；它从World摘取当前任务范围内累计已观察、有依据的结构引用，身份/依据沿用World，当前有效性随World更新。Owner在澄清这个B选项后要求“下一步”，因此转入每轮执行输入。

## 当前前沿 Q4

是否把Traversal每轮执行输入统一划分为以下四类？

| 输入 | 回答的问题 | 来源与约束 |
|---|---|---|
| 计划树 | 要做什么，按什么规则处理，何时结束 | Agent提出/修订，Runtime采纳；可引用安全策略、收紧范围，不能授予权限 |
| 遍历图 | 任务范围内已知哪些结构 | World结构事实的引用/派生视图；不含处理进度，不凭历史定位操作 |
| 任务进度 | 已处理、待处理、受阻，以及执行位置 | 当前Run的执行结果或同源投影；不作为世界事实或权限 |
| 当前运行上下文 | 当前真实位置/控件状态有何依据，现有哪些能力、授权、安全限制和预算 | World/能力及契约/预算等既有Owner的有效只读输入；不是新store或授权来源 |

推荐按四类划分，组合供执行使用。避免把当前状态、进度或权限全部塞进图，也不让模型在计划中预写未来页面事实。这里的“当前”指执行时重新取得的有效输入；观察/定位、安全检查、投递与独立验证仍由原执行链承担，Traversal不从raw artifact自行建立事实。

例如“遍历设置”：计划给进入/记录/跳过规则，图给已知页面关系，进度给本Run剩余工作，当前上下文确认现在在哪、目标是否仍可用及操作是否允许。四者共同支持下一处理项选择。

## 后续

## Owner追问与Q4修订

Owner问“遍历图需要作为输入吗？”。原表混合了执行需要的信息与上层必须提交的参数，两者不等价。遍历图确实是Traversal消费的数据，但按D3可以在执行期间从World按范围派生，不要求调用方准备并随PlanTree提交一份图。

修订推荐：上层提交计划树并关联任务/当前Run；Runtime通过显式Owner只读缝提供世界结构查询、当前状态、Run进度及有效执行约束，按需取得任务遍历视图，Traversal消费这些信息选择下一处理项。不能通过隐藏全局状态、服务定位器或绕过World/Run Owner来省参数，也不由Traversal直接读取raw observation建立事实。

```text
调用方提交计划树并关联任务
→ Runtime关联当前Run及既有Owner读取缝
→ 按计划范围从World取得/派生遍历视图
→ 结合Run进度与当前约束选择下一处理项
→ 既有安全执行、观察与验证链
```

现有只读ProjectWorldGraph(scope)和Owner候选/条件投影说明已有读取缝可供设计复用，不表示新Traverse输入契约已实现；既有投影的裁剪/有效性缺口按第3轮保留。

当前Q4改为：是否采用“调用方提交计划，遍历图由运行时按需从World派生”，而不要求外部独立传图？推荐采用；物理查询/缓存形态仍后定。本次只修订建议，等待Owner答复。

## 答复

Owner对修订Q4回复“按推荐”。记录D4：调用方提交计划树并关联任务；Runtime通过显式World/Run等Owner读取缝按需取得遍历图、Run进度和当前约束，调用方不必独立传图。原四类表仅作为执行所需信息分类，不要求四个外部对象；不引入隐藏全局访问，不改变权限/事实权威，不决定查询或缓存形态。下一轮讨论推进结果，未获得产品实现授权或改动。
