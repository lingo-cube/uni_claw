# 最新机制的三层推导：场景、数学与哲学

日期：2026-10-19。性质：D1-D16机制的分析与反例审查。Owner已授权以该机制再次推导；这不等于正式wire冻结或产品实现授权。原001证据保持。

后续责任修订：Owner在Q17-Q19接受完成标准，并明确检查完成/通过由各handler能力协议判断、检查不符合可仅记录、恢复归Recovery。见[第12轮](grill-round-12.md)。因此下述K4/K5是能力协议与Recovery交接的证明义务，不是Kernel新增统一检查/恢复算法的要求；原D1-D16矩阵/参考模型保留历史基线，不冒充修订后产品证明。

## 1. 结论

这个机制能够作为结构化UI任务的主要规划抽象：**计划表达范围和处理意图，World提供事实，Traversal持续发现和推进，每个操作绑定有序能力处理步骤，原Kernel链负责安全执行和验证。** 比让模型逐步编写菜单循环更符合此类任务。

但“图＋规则＋handlers”本身不足以证明所有任务适配完备。它解决了编排位置，没有自动提供发现完整性、任务相关身份、具体动作语义、可验证目标及恢复账本。地图/连续反馈、跨进程升级、记忆等仍需要具体适配；它们不能靠一个Custom handler算作覆盖。

本次结论分开：

| 问题 | 结论 | 证据性质 |
|---|---|---|
| 这批输入是否逐项纳入 | 是：150条SR、28条场景库、18个交互样例、29个UI字段均有追溯 | 当前文件解析、ID校验、源哈希；各表重叠，不相加计算支持率 |
| 全部输入能否由菜单遍历独立完成 | 否 | 目标态循环、等待重启、连续控制、独立Owner能力反例 |
| 结构化有限任务是否有覆盖论证 | 有条件成立 | [数学推导](mathematical-derivation.md)的假设、证明纲要与有限参考模型 |
| 是否获得无条件全UI完备性 | 否，且该命题过强 | 观察不可区分、无限发现、不可计算目标反例 |
| D1-D16是否已经完整规定可实现协议 | 尚未 | 8项证明义务，尤其发现/去重、操作事件、handler恢复和typed判据 |
| 当前产品是否通过新机制验收 | 未证明 | 新机制产品/模型/设备执行数为0；旧passing不迁移 |

## 2. 推导路径

1. 固定D1-D16及当前场景/UI定义的哈希；重新解析当前源，不把旧矩阵结论搬作当前结果。
2. 对每项需求找出：所需输入→节点选择→具体操作→前后handler→独立安全/验证→结果及未知出口。
3. 区分“当前机制直接描述”“须组合既有阶段/目标态/等待语义”“依赖独立Owner/领域适配”“本轮之外”。拒绝/暂停是合法处置，但不算任务成功适配。
4. 加入专门攻击新机制的反例：规则遮蔽、Unknown、检查后漂移、目标消失、后置失败、暂停续行、共享子页和深度截断。
5. 将结论写成带前提的命题；用小规模独立参考模型寻找反例，保留失败见证，不把参考模型当产品执行。
6. 用概念边界检查数学模型有无偷换：可观察≠真实全部，可计算≠可知，可做≠获准，流程结束≠目标满足。

## 4. 150条推理与18个交互样例

150条按13个压力组逐项建立新映射，而不是把150次safe-stop计作150项成功。旧文档中的“signature变化就是新身份”等描述是压力输入，不能覆盖当前World身份权威。SR-120/122为开发治理，保留但不纳入UI执行支持率；跨域/跨进程/Memory依赖也单列。

18个样例显示5种实际需求：结构探索、顺序阶段、目标态重复、外部事件等待、领域反馈。新机制的操作绑定handlers可以被这些需求复用，但**Traversal是其中的结构探索职责，不必吞并其他职责**。当前不因此新增五种union成员或策略执行器。

- A1、B6最贴合动态结构发现；“找到商品”不包含购买许可，有限未找到不能推断商品不存在。
- A2/A4/B1/C1要求同一元素可在不同阶段重复处理，且已满足时零动作；visited不能禁止必要重复。
- A3/B3/B4/A5要求阶段依赖、参数、多个对象和联合判据；首条规则命中只选该节点的处理方式，不取代任务阶段。
- A6的禁用检查是只读；测试禁用项是否可被绕过属于另行授权的负向测试，不能从“检查”推出点击许可。
- B7等待重启超出同一存活执行的暂停恢复承诺；B5/C3/C4需要具体感知/反馈/接地能力，不能用“回Agent”冒充自动完成。
- C1-C5、文件世界/机器人地图只证明抽象迁移问题值得检验，没有第二域现实适配证据。

## 5. UI定义推导的输入义务

22个节点字段和7个窗口字段均重新解析。新机制需要用它们分清：

| 义务 | 已有线索 | 不可偷换 |
|---|---|---|
| 目标/handler绑定 | capture-local OccurrenceRef、World连续性、操作位置 | 路径/坐标/resource-id不能单独成为永久身份 |
| 节点分类 | Class、Clickable、Checkable、语义文本、相关World事实 | Clickable不等于navigate或safe；Checkable不等于允许切换 |
| 检查输入 | Text、ContentDescription、Hint、状态字段及观察关联 | Accessibility文字不是所有像素文字；Password必须按已有策略脱敏 |
| 继续发现 | Scrollable、层级、前后观察、空间 | 末屏没新项或滚动一次不动不自动证明全域穷尽 |
| 多窗口/焦点 | WindowOccurrenceRef、绘制顺序、Focused/Visible | 一个树不证明只有一窗；窗口字段不证明双屏联动可验 |
| 结果判定 | Observed/Unknown/Unsupported及World冲突 | Unknown/Unsupported不变成false，不用缺字段来宣称已检查 |

字段存在只能满足输入槽位，不能证明来源可靠、目标唯一、操作已实现或覆盖充分。

## 6. 新机制专属反例与尚未满足的证明义务

本次新增16条H场景（不并入既有SR编号），逐项轨迹在矩阵中。以下8项是从反例推得的**待设计/待实现义务**，不是擅自加入D1-D16的新决策。

| 编号 | 缺什么 | 反例及后果 | 最小后续工作 |
|---|---|---|---|
| K1 | 发现范围与穷尽依据 | 虚拟列表/空屏/无进展把未发现当不存在 | 明确本页/本容器发现能力、末端依据与未穷尽报告 |
| K2 | 任务相关去重、深度与结果有效性 | 同页不同任务、共享子页先深后浅、状态改变后不重检 | 去重键关联任务/规则/相关上下文；深度机会不能被较深到达吞掉，事实改变使相应结果失效 |
| K3 | 具体操作的事件边界 | 观察提交不等于该操作已验证；动作失败不能跑成功后置处理 | 定义操作ID、阶段与观察关联、无动作成功、验证失败/取消/未知出口；复用既有Kernel事件缝 |
| K4 | 能力自有typed输入/结果判据 | 当前capture级语言Hook不能由Kernel推断单元素已检查；Finding不等于门禁裁决 | handler能力定义检查范围/完成/通过/有效性；Kernel执行并关联返回结果，不重判领域结论（D19） |
| K5 | 与Recovery的执行事实交接 | 操作已成功；仅记录类不符合继续，确需暂停后恢复不应盲重放 | Kernel保留attempt/handler位置/结果/消耗，Recovery负责具体恢复；不将不符合一律当执行异常（D18） |
| K6 | handler能力边界与工作量 | 借handler调用有Effect能力可绕过gate或无限执行 | 每次有Effect行为仍走原链；无Effect检查也有工作/时间边界；不假定所有能力均可塞入hook |
| K7 | 与阶段/目标态/等待的组合 | 温度仍需再次按同一按钮；重启不能靠在内存保存暂停解决 | 明确复用既有Plan/Policy/等待缝，领域与恢复适配单列，暂不发明通用策略平台 |
| K8 | 覆盖报告与目标证明的关联 | visited清空/返回首页/handler全过，却有禁入或未发现分支 | 区分已知工作处理完、限定域覆盖、原Goal满足；证据链及范围不能省略 |

K1/K2决定“遍历不漏”，K3/K5决定“续行不重做”，K4/K6决定“检查有依据且不越权”，K7/K8决定“组合任务不被误报完成”。只定义handlers数组不能关闭这些义务。

## 7. 推导对设计的影响

无需推翻D1-D16，也无需回到让模型逐步写循环。需要在后续协议设计中优先解决K1-K6，再用菜单Traversal作为第一条真实任务链验证K8；K7按真实买方逐项复用/适配。

当前最值得先压实的是两个细节：**什么条件使一个处理项算完成且还能继续使用，以及暂停恢复到底从哪个操作/handler位置继续。** 它们是新机制能否稳定运行的关键，不能由“有hook位置”替代。

Owner已对这两项给出责任答案：前者由能力handler协议定义，后者交给Recovery。本机制只需提供正确调用、执行事实和结果交接；不继续把领域算法或Recovery内部策略扩入Kernel设计。结果校验Capability是后续方向，不要求本轮提前实现。

完整数学论证见[mathematical-derivation.md](mathematical-derivation.md)，哲学审查见[philosophical-derivation.md](philosophical-derivation.md)。两者对机制的评价是相互制约的分析，不是给同一结论增加三个PASS标签。
