# Design Documentation Sync Skill (V2.0)

**Pre-implementation**: Read PRD → update design docs → sync context to implementation agents.

## When to Use

BEFORE `/opsx:apply`, after a PRD or OpenSpec proposal is approved:
- Update relevant module design docs with planned changes
- Ensure downstream implementation agents have accurate architecture context

Do NOT use after implementation — that's module-test's job to verify.

## What It Does

1. **Read PRD / OpenSpec artifacts** — proposal, design, specs
2. **Map to affected design docs** — `docs/architecture/modules/{module}-design.md`
3. **Update design docs** — new classes, interface changes, architecture shifts, version bumps
4. **Generate context summary** — packaged for `/opsx:apply` agents

## Process

### Step 1: Identify Scope

```
Input: OpenSpec change name OR PRD file path
→ Read proposal.md + design.md + specs/**/*.md
→ List affected modules and their design docs
```

### Step 2: Read Current Design Docs

For each affected module, read `docs/architecture/modules/{module}-design.md`.
If it doesn't exist, note that one needs to be created.

### Step 3: Generate Updates

For each affected design doc, update:
- **Version** — bump to match PRD version
- **Date** — today
- **Module overview** — if the module's responsibilities changed
- **Core classes / interfaces** — add new, mark deprecated, update signatures
- **Architecture** — if relationships between modules changed
- **Dependencies** — new or removed dependencies

### Step 4: Write Context Summary

Generate a summary block for `/opsx:apply` agents:

```markdown
## Design Context (auto-generated by design-doc-sync)

**Change**: <change-name>
**Version**: VX.Y
**Updated Design Docs**:
- docs/architecture/modules/simulation-design.md (V6.0 → V6.4)
- docs/architecture/modules/state-machine-design.md (V6.0 → V6.5)

**Key Interface Changes**:
- MockVisionService: now extends VisionService ABC
- MockActionExecutor: now extends OperationExecutor ABC
- SimulationRunner: dead import fixed, DFS fallback deleted

**New Dependencies**:
- src/trace/recorder.py → src/simulation/runner.py
```

### Step 5: Confirm & Write

Present updates to user. On approval, write all design docs.

## Design Doc Sections to Update

| Section | When to Update |
|---------|---------------|
| Header (version, date) | Every change |
| 1. Module Overview | Responsibility or design philosophy changed |
| 2. Core Classes/Interfaces | New classes, deleted classes, API changes |
| 3. Dependencies | New imports, removed dependencies |
| 4. Architecture | Cross-module relationship changed |
| 5. Data Flow | Processing pipeline changed |
| 6. Examples | API usage changed |

## Rules

- **Overwrite mode** — update existing design doc in-place, don't create versioned copies
- **Design philosophy stays** — only change "what", not "why", unless the PRD explicitly changes philosophy
- **Deprecated → strike through** — `~~OldClass~~` instead of deleting from doc
- **Git commit** — commit updated design docs before `/opsx:apply` starts

User: /opsx:propose simulation-interface-alignment
